# Step 0: docs-fines-ledger

벌금(fine) 기능을 **실제로 동작하게** 하기 위한 설계 결정을 **정본 docs에 명문화**한다. 이 step은 **문서 전용** — 코드는 한 줄도 건드리지 않는다. 이후 step들이 이 문서를 근거로 구현한다.

배경: 현재 벌금은 "보여주기"(읽기·표시 + 금액 수정)만 있고 **데이터를 넣는 경로가 없다**. 구체적으로 (1) 연도별 `FineConfig`를 만드는 런타임 경로가 없어 패널이 항상 "이 해의 벌금 설정이 아직 없어요"만 뜨고, (2) `MemberLedger`(참여·발표자 불참·일반 불참·납부)에 쓰는 코드가 전무해 멤버 현황 표가 영원히 0이다. 이 step은 그 두 경로를 **어떻게** 채울지 결정을 문서로 굳힌다.

확정된 방향(이 task 전체의 전제):
- **장부는 관리자가 수동 편집한다.** 스케줄에서 자동 집계하지 않는다 — 멤버별 출석을 추적하는 데이터 모델이 없고(스케줄 주차는 발표자만 안다), 스케줄 철학이 "절대 자동 채움하지 않음"이다.
- **연도별 벌금 설정(`FineConfig`)은 명시적으로 생성한다**(관리자 버튼). GET이 자동 생성하지 않는다 — row 부재 = 미설정(R15/ADR-006 정신과 동일).
- **생성·편집 권한은 관리자만**(기존 `updateFines`와 동일, SECURITY).

## 작업

### 1. `docs/agent/ADR.md` — ADR 추가

기존 마지막 ADR 뒤에 **다음 번호**(현재 마지막이 ADR-022면 `### ADR-023: 벌금 장부 수동 편집 · 설정 명시 생성`)를 기존 ADR 형식(맥락/결정/근거)에 맞춰 추가한다. 다음 결정을 담는다:

- **벌금 장부(`MemberLedger`: 참여·발표자 불참·일반 불참·납부)는 관리자 수동 편집으로 채운다.** 스케줄 주차에서 자동 집계하지 않는다. 근거: 멤버별 출석 데이터 모델이 없고(스케줄은 발표자만 안다), 스케줄의 "절대 자동 채움하지 않음" 철학과 일관. 출석 추적을 새로 만드는 건 별도 task(YAGNI).
- **연도별 `FineConfig`는 관리자가 명시적으로 생성한다.** GET/조회가 자동 생성하지 않는다 — row 부재 = 미설정(ADR-006/R15와 동일 정신). 기본값은 스키마 default(`finePresenter=30000`·`fineAbsent=10000`)를 따른다.
- **생성·장부 편집·금액 수정 모두 관리자 전용**(기존 `updateFines`와 동일, SECURITY). 일반 멤버에겐 해당 UI를 노출하지 않는다(R19).
- **스키마 변경 없음.** `FineConfig`·`MemberLedger` 모델은 이미 존재한다 — 이 task는 쓰기 경로(Server Action)와 편집 UI만 추가한다. 누적 벌금·미납은 계속 저장하지 않고 파생한다(DB.md).

### 2. `docs/design/SCREENS.md` — schedule 화면 벌금 명세 보강

기존 schedule 섹션의 벌금/멤버 현황 명세에 다음을 추가(기존 형식 유지):
- **벌금 설정이 없을 때(관리자):** "벌금 설정 시작" 버튼을 노출한다 → 그 해 `FineConfig`를 기본값으로 생성하고 멤버 현황 표(전부 0)가 즉시 나타난다. 비관리자에겐 기존 안내문("이 해의 벌금 설정이 아직 없어요")만.
- **연도별 멤버 현황 표(관리자):** "수정/저장" 토글을 둔다(금액 설정 카드의 토글과 동일 패턴). 수정 모드에서 **참여·발표자 불참·일반 불참·납부** 네 칸이 숫자 입력으로 바뀌고, 저장 시 표가 즉시 재계산된다. **누적 벌금·미납 칸은 파생값이라 편집 불가**(읽기 전용 유지). 비관리자에겐 토글 미노출.

### 3. `docs/dev/DB.md` — 장부 채우는 방법 한 줄

`MemberLedger`/`FineConfig` 섹션(또는 파생 계산 표 근처)에 런타임에 어떻게 채워지는지 한 줄을 명시한다: **`FineConfig`는 관리자가 명시 생성(자동 생성 안 함), `MemberLedger`(참여·불참·납부)는 관리자가 수동 편집으로 upsert.** 모델 시그니처·스키마는 변경하지 않는다(이미 존재).
