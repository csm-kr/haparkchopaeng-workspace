# Phase 21 검토 — 논문 기반 대화형 PT

2026-10-18~19. 사용자의 개발 진행, 논문 먼저 읽기, 발표 방향 2~3개, 한 질문씩 Grilling, 실제 논문 Figure·표·설명 도식 중심(1번)을 반영했다. [제품 흐름](../../docs/design/PAPER_PT_WORKSPACE.md), [ADR-029](../../docs/agent/ADR.md), [API](../../docs/dev/API.md)를 정본과 대조했다. 운영 반영과 로컬 검증은 구분한다.

## 발견해 수정한 문제

- 기존 세미나 생성은 텍스트 초안을 한 번 만드는 경로였다. 전용 `/presentations/new`와 `/presentations/create/:taskId`에 논문 읽기·방향·한 질문·브리프·목차·도식 덱·대화 수정·검토 등록을 연결했다. 기존 노트·직접 세미나는 호환한다.
- OTF subset은 `Not a CFF Font`, TTF subset은 MuPDF invalid glyph를 냈다. 고정한 Pretendard TTF 전체를 포함하고 출력 전 문자 지원을 검사한다. 실제 모델이 낸 지원하지 않는 한자와 겹친 연결 설명을 육안 검수에서 찾았다. 문자 검사를 추가하고 도식 설명이 노드·다른 설명과 겹치지 않게 배치한다. 안전한 배치를 못 찾으면 출력 대신 수정 안내를 준다. 출력 오류는 같은 대화에 수정 요청으로 보낼 수 있다.
- 좁은 제작 화면에서 도식 글씨가 작았다. 그림을 넓게 보여주고 모바일 도식은 내부에서 좌우로 움직여 읽게 했다. 권한 상실 시 개인 대화와 논문 선택 목록을 함께 지운다. 빈 팀의 논문 등록 링크는 실제 `/library`다.
- 공유 첨부 다운로드의 기존 인증만 있던 조회를 활성 팀까지 스코프했다. 생성 HTML은 비공개 octet-stream 객체와 인증된 attachment·sandbox CSP·nosniff를 사용한다. 업로드의 PDF 전용 정책은 유지한다.
- 파일 저장 연결이 없을 때 출력 잡을 접수하지 않게 한국어 503을 추가했다. 현재 세션·grant·소유자·원문·검토한 덱을 먼저 확인하고 접수한다.
- 등록 후 출력 완료 사이에 다른 화면에서 소개가 바뀌는 경우 기존 코드는 파일을 붙였다. 실패 테스트로 재현하고 발표 row를 잠근 뒤 제목·소개·시간·장수·핵심 내용·슬라이드를 다시 비교하도록 수정했다. 이후 일치하는 등록본의 후속 파일 첨부도 검증했다. 완료·등록이 같은 task→membership 순서로 잠그며, 작업 상세 갱신은 원문을 포함한 전체 실행 결과 대신 활동 메타데이터만 읽는다.
- task 버전이 같아도 실제 발표가 변경되어 검증 상태가 달라질 수 있다. 실패 테스트로 재현하고 새 검증 상태·권한·파일 상태를 반영하되 편집 중인 덱과 대화 객체는 유지하도록 고쳤다.
- 이전 로그인에서 질문을 기다리던 대화에 재연결 버튼이 없었고, 등록한 덱의 새 출력은 과거 세션을 요구했다. 각각 실패 테스트로 재현했다. 개인 대화는 현재 연결로 명시적으로 resume하고, 새 결정적 출력은 현재 로그인 grant로 접수하도록 수정했다. 과거 세션의 실행 권한은 복원하지 않는다.
- 유휴 덱 재연결에서 revision을 바꿔 읽기 증거가 새 revision에 없는 문제를 재현해 수정했다. 원문이 같고 새 추론이 없으면 증거 revision을 유지한다. 원문이 바뀐 대기 작업은 별도 sourceChanged 관찰과 재시작 CTA로 복구한다.
- 전용 PT는 HTML/PDF 검수 전 등록을 거절한다. 등록 검증에는 실제 두 첨부까지 포함하며 파일 row 삭제를 재현해 성공 표시가 사라지는지 확인했다. 덱 수정 응답에는 선택 이유·변경 설명을 담고, 원문 읽기 실패는 진행 중 화면과 구분한다. 기존 직접 텍스트 세미나 경로는 호환한다.

## 검증과 증거

- 최종 전체 격리 DB 검증은 **955개 통과·16개 건너뜀**, lint·타입 검사·build도 모두 종료 코드 0이다. 2026-10-19 00:26 KST에 step 0~4와 phase 완료를 확인했다. [step4-output.json](./step4-output.json). PostgreSQL 통합 15개와 실모델 opt-in 1개는 일반 실행에서 건너뛴다. 실모델 검증은 아래 별도 실행으로 통과했다.
- 논문 먼저 읽기·방향·한 질문·목차·명시적 제작 전이: [step0-output.json](./step0-output.json). 폰트·16:9·실제 PDF 텍스트·이미지·넘침 거절·도식 설명 겹침·누락 글리프: [step3-output.json](./step3-output.json).
- 실제 Figure 객체 PNG·원문 PDF 페이지·설명 도식을 포함한 출력과 공유 PDF/HTML 첨부를 일회용 DB에서 검증했다. 접수 후 웹 grant가 만료되어도 결정적 렌더는 마치며, 새 검토 등록은 웹에서 권한을 갱신한 뒤 한다. 다른 소유자, 원문 변경, 요청 ID 재사용 변조, 중복 렌더·등록을 검사한다. 저장 연결 누락은 Job 생성 전 503이다. [런타임 결과](./step1-output.json).
- Chromium PC 1280px·모바일 390px에서 논문 선택 → 방향 → 자유 답변 → 목차 → 도식 PT → 대화 수정 → HTML/PDF 링크 → 새로고침 복원 → 명시 등록을 검증했다. 기존 15개 흐름과 새 2개를 함께 실행해 **17개 모두 통과**했다. [브라우저 결과](./step2-output.json). 개발 서버 첫 제작 RSC가 6.4초 걸린 기록을 확인해 해당 이동 기대 시간만 15초로 정했다. 임의 sleep으로 대체하지 않았다.
- 실제 로그인된 Codex CLI `gpt-6.1-sol`을 최종 코드의 도구 없는 어댑터로 6회 호출했다. 합성 연구 원문 6쪽으로 방향 → 질문 → 답변 → 목차 → 3장 덱 → 이유·변경 설명을 담은 수정 → 실제 HTML/PDF 검수 → 등록·파일 재조회가 통과했다. 약 137초. [실모델 로그](./real-model-reviewed.log), [응답·기획·출력 검수](./real-model-result.json). 논문 내용 품질 평가나 설치된 데스크톱 앱 전체의 운영 검증을 대신하지 않는다. 큐 전송과 Storage는 이 테스트에서 각각 수동 드라이버와 메모리 객체로 격리했다.
- 실제 모델의 최종 3장 PDF를 PNG로 확인했다. Aside CLI에서는 생성 HTML의 1→2→3장 이동, 포함한 Regular/SemiBold 폰트 로딩, 첫 장 텍스트의 실제 SVG 경계를 확인했다. 브라우저 스크린샷은 백그라운드 CDP 시간 초과, `file://` 직접 열기는 Aside의 로컬 파일 접근 제한으로 미검증이다. 다른 브라우저로 전환하거나 사용자 기존 탭을 이동하지 않았다. HTML은 외부 폰트·이미지·스크립트 요청 없는 자체 포함 파일이다.

## 배포 전제와 범위

새 DB 컬럼은 없다. phase 20의 [SQL](../../docs/dev/sql/20261018-agent-centric-foundation.sql)이 먼저 필요하다. 운영 DB를 수정하지 않았고 `db push/seed`는 임시 SQLite 경로 검사를 통과한 곳에만 실행했다. 테스트 후 Prisma 클라이언트는 PostgreSQL 정본으로 복원했다.

운영에는 `agent_step_v1`을 보고하는 새 AI 브릿지, 웹·Inngest 함수 배포, 비공개 Storage 연결, phase 20 스키마가 모두 필요하다. 준비 후 `AGENT_TASKS_ENABLED=1`로 켠다. PDF/HTML 폰트와 Linux sharp 바이너리는 `/api/inngest` 추적 포함 목록에 넣었다. 설치 파일 제작·서명·배포와 실제 Supabase Storage 업로드는 이번 로컬 검증에 포함하지 않았다.

공유 등록 전 대화·기획·출력은 작성자 개인 범위다. 정확히 같은 덱의 준비된 파일만 첨부한다. 원문·덱이 바뀌면 오래된 파일을 현재 결과로 제공하지 않는다. 접수한 렌더는 웹 grant를 갱신하거나 새 추론을 하지 않는다. 일정 자동 편성·라이브 자동 시작·범용 셸/파일/MCP·PPTX·영상 제작은 추가하지 않았다. Figure 해석은 본문·캡션 기반이며 연구 주장과 수치의 의미는 사용자가 근거를 보고 검토한다.

첫 build의 기존 webpack 캐시에서 WasmHash 오류가 있었다. 해당 `.next`는 작업공간 내 `node_modules/.cache/hapark-pt-build-20261018234448`에 보존했고 새 캐시 build는 통과했다. 이후 최종 하네스 결과를 기준으로 한다. 기존 사용자 변경의 stage·commit·push·배포는 하지 않았다.
