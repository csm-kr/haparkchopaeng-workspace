# 실제 펫 렌더와 회귀 검증

입력: `step1.md`의 renderer·자산·회귀 테스트, `docs/design/AI_BRIDGE_TRAY_CHARACTER.md`의 표정 주기와 독립 검토 목록.

소유 임시 프로필과 숨김 Electron을 사용해 실제 펫 renderer를 연다. 제품을 바꾸지 않고 QA 표면에 흰색·그라파이트 배경을 합성하고 기본·감긴 눈·자발 미소·호버·동작 줄이기를 비교한다. 한 주기 전체를 관측하고 이미지·계산된 스타일·결과 JSON을 남긴다. 실제 네이티브 드래그 관측과 코드/CSS 보존 검사는 구분해 기록한다. 관측하지 않은 OS·드래그·포커스 상태는 미검증으로 남긴다.

AC는 `node connector/scripts/pet-qa.mjs`와 `node connector/scripts/run-desktop-qa.mjs`를 순차 실행한다. 전자는 펫 renderer 실증, 후자는 기존 연결·저장소·종료 회귀이며 서로를 대신하지 않는다. `connector/test/pet-renderer.test.mjs`의 명시적 opt-in 네이티브 실행이 있다면 기본 Node 실행의 skip과 실제 실행 결과를 분리한다. 부모가 지정한 QA 실행 외에 기존 사용자의 앱·프로필·트레이·브라우저를 조작하지 않는다.

실제 CLI 추론·운영 API 호출을 하지 마라. 이유: 이번 변경은 펫 표시이며 구독을 사용할 필요가 없다. OS 키링이나 sandbox를 완화하지 마라. 이유: 렌더 검증도 출시 보안을 유지해야 한다. 캡처만으로 배포·설치 업그레이드가 끝났다고 기록하지 마라. 이유: 부모의 별도 패키지·정확 소스 CI·게시·설치 확인이 필요하다.

산출물은 실제 실행한 명령·OS·소스·캡처·체크 결과와 정리 영수증이다. 예시 캡처와 아직 실행하지 않은 검증 계획은 실제 성공 기록과 구분한다. 현재 phase는 계획 상태이며 구현·검증·배포 완료를 주장하지 않는다.
