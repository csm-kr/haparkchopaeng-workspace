## 재현과 회귀

- Aside 운영 재현 두 번: 기존 탭의 현재 PC는 온라인이고 모델 19개가 준비됐지만 새 탭의 기기 힌트는 0개, 모델 선택은 비활성화였다. 서버는 ID 없는 상태 조회에서 기기 목록만 반환하며 현재 기기를 임의 지정하지 않는다.
- 공유하는 값은 팀별 기기 ID와 승인 revision뿐이다. 모든 복원과 탭 간 변경은 현재 서버 권한을 검증한다. PIN·실행 링크·인증 토큰은 공유하지 않는다.
- StrictMode 복원과 지연 상태·heartbeat·초기/활성 pending 폴링 경합 회귀 12개가 RED 후 GREEN이다. 다른 탭의 승인 직전·직후에 시작하는 요청을 구분하며 이전 요청이 새 승인을 덮지 않는다.
- 상태 점과 모델명 정렬, 실제 실행 대상으로 고정된 20px 링, 원래 effort 이름, 키보드·터치 첫 활성화를 포함한 관련 UI 검증은 최종 41개 통과다. 터치 `pointerdown → focus → click`과 키보드 `focus → Enter` 회귀를 각각 먼저 실패시켰다.

## 로컬 검증

- 전체 격리 Vitest: 135 suite 통과·1 생략, 1,090개 통과·15 생략. 이후 사용량 상세의 터치·키보드 수정은 위 관련 UI 41개로 추가 검증했다.
- 격리 Chromium: 12개 통과. 새 탭은 별도 sessionStorage로 시작하고, 공유 힌트를 명시 ID로 재검증한다. 실제 native storage event로 연결 해제를 동기화하고 모델·링·툴팁을 확인했다. 실제 앱 실행이나 AI 추론은 요청하지 않았다.
- 실제 HTTP 계약: pairing·응답·취소·로그아웃·쿠키 소실 검증 통과. 일회용 SQLite만 사용하고 Prisma client와 Next cache를 복원했다.
- 최종 lint 및 production build 통과. 운영 DB·API 키 없이 검증했다.
- 독립 리뷰에서 발견한 pending 시작 경합과 터치 상세의 첫 클릭 문제를 수정하고 재검토했다.
- 원본 보존 검사는 기존 729개 파일, Git index 및 CLAUDE.md 부재를 그대로 확인했다.
