# 보안 (Security)

> 권한이 걸린 엔드포인트는 [`../dev/API.md`](../dev/API.md), 비밀 관리는 [`../dev/ENV.md`](../dev/ENV.md), 데이터 모델은 [`../dev/DB.md`](../dev/DB.md)를 본다. 이 문서는 **위협 모델·인증/인가·비밀·데이터 보호 규칙**을 정리한다.

## 위협 모델 (팀으로 스코프한 비공개 워크스페이스)

- **자산:** 논문 PDF·분석·개인 연구 대화, 발표 자료, 라이브 입장 토큰(LiveKit), 멤버 PII(이메일), 벌금 장부, 서버 API 키(LiveKit·Supabase), 로컬 연결 기기 키.
- **주요 위협:** ① 초대 외 무단 접근(공개 가입 없음) ② LiveKit 입장 토큰 유출 → 무단 입장·화면공유 ③ 비밀 키의 클라이언트 노출 ④ 스토리지 객체 무단 다운로드 ⑤ 작성자 위변조(노트/댓글) ⑥ 권한 상승(멤버→관리자).
- 팀 간 데이터 격리와 개인 대화 소유자 검사는 서버가 강제한다. 대규모 공개 서비스의 DDoS 방어는 별도 운영 범위다.

## 인증 (Authentication)

- **초대 전용.** 공개 회원가입 없음(ADR-007). 합류는 서명된 초대 토큰 검증으로만(`INVITE_TOKEN_SECRET`).
- **세션:** 서버 서명 세션(`AUTH_SECRET`). HTTP-only·Secure·SameSite 쿠키. 미인증 → `401`.
- **초대 토큰:** 만료·1회성 권장. 토큰에 부여 역할을 담되 서버가 재검증.

## 인가 (Authorization)

역할: **관리자 / 멤버 / 게스트**. 모든 권한 체크는 **서버(route handler) 진입부**에서 수행한다. 클라이언트 UI 숨김은 보조일 뿐 신뢰 경계가 아니다.

| 동작 | 관리자 | 멤버 | 게스트 |
|---|:--:|:--:|:--:|
| 논문/자료 열람·노트·댓글 | ✅ | ✅ | ✅(읽기 위주) |
| 업로드·분석 생성 | ✅ | ✅ | △ |
| 라이브 시작/입장 | ✅ | ✅ | △ |
| 노트/댓글 삭제 | 본인+관리자 | 본인 | 본인 |
| 스케줄 저장 | ✅ | ✅ | ❌ |
| 벌금 금액 수정 | ✅ | ❌ | ❌ |
| 초대·역할 변경·내보내기 | ✅ | ❌ | ❌ |

- 권한 부족 → `403`. 게스트(△/❌)는 정책에 따라 좁힌다.

## 신뢰 경계 (CRITICAL)

- **작성자/소유자 ID는 항상 세션에서 취한다.** 클라이언트가 보낸 `authorId`/`uploadedBy`/`presenterId`를 신뢰하지 않는다(→ [`../dev/SEQUENCE_DIAGRAM.md`](../dev/SEQUENCE_DIAGRAM.md) S2).
- **입력 검증:** API 경계에서 zod로 검증, 실패 시 `400`. 업로드 Content-Type은 `application/pdf`만(`415`).
- **순번 포인터·확정 상태** 같은 무결성 값은 서버에서 원자적으로 계산·전이(클라이언트가 보내지 않음).

## 비밀 관리

- **CRITICAL: 모든 키는 `.env`(서버)에서만.** 클라이언트 번들·`NEXT_PUBLIC_*`에 비밀 금지. `.env`는 커밋 금지(→ [`../dev/ENV.md`](../dev/ENV.md)).
- LiveKit 토큰 서명·Supabase 등 외부 권한은 서버 route handler에서만 처리한다. PDF 준비·분석 결과 처리는 Inngest의 외부 durable job에서 수행한다. 클라이언트는 자체 API만 호출한다. Gemini 자동 분석은 실행하지 않는다(ADR-026).
- 키 유출 시 즉시 회전. 최소 권한 토큰 사용.

## 라이브(LiveKit · ADR-019)

- **CRITICAL: LiveKit 입장 토큰은 참가자별로 서버가 서명·발급하고 본인에게만** 반환한다(`/live/start`=발표자, `/join`=참가자). **화면공유 grant는 발표자 토큰에만**(R7). 신원(identity)은 세션에서 주입 — 클라가 보낸 식별자 미신뢰(R3). 토큰 서명 키(`LIVEKIT_API_SECRET`)는 서버 전용.
- 동시 active 세션은 **팀당 1개** 강제(`409`) — 팀 전역 `live`와 1:1(ADR-001/ADR-020). `/end`만 전체 종료(LiveKit 룸 삭제 best-effort), `/leave`는 본인만.
- 채팅·반응·손들기는 LiveKit **데이터 채널**로 룸 내부에서만(휘발·미저장). 페이로드의 author를 신뢰하지 않고 LiveKit identity로 판별.

## 파일 스토리지

- 원문 PDF·발표 에셋·figure 이미지는 **비공개 버킷**. 다운로드는 **단기 서명 URL**로만 제공(공개 버킷·영구 URL 금지).
- 논문 URL fetch는 서버가 수행(클라이언트가 임의 URL을 서버에 대신 요청하게 하지 않음 — SSRF 주의). 호스트 화이트리스트로 강제하며(`lib/paper-url.ts` `resolvePaperSource`), 현재 허용: `arxiv.org`, `openaccess.thecvf.com`(CVF), `openreview.net`, `aclanthology.org`, `proceedings.mlr.press`, `proceedings.neurips.cc`. https만 허용하고 호스트는 정확 일치(서브도메인 사칭·사설IP·평문 차단). 새 출처는 이 목록에 추가한다.

## 데이터 보호 / 프라이버시

- 멤버 이메일은 PII — 초대·팀 화면 외 불필요한 노출 금지.
- 라이브 녹화 보존 기간·발표 자료 아카이브 여부는 미결(→ [`../agent/ISSUES.md`](../agent/ISSUES.md)).
- 업로드·본문 준비에는 AI 공급자 호출이 없다. 사용자가 연결한 PC·제공자·모델로 실행할 때 서버가 검증한 논문 본문·질문·허용된 최근 대화를 해당 CLI와 그 AI 공급자에 전달한다. 로컬 연결은 오프라인 추론을 뜻하지 않는다. 민감 비공개 자료의 외부 처리는 팀 합의를 따른다.
- 개인 연구 대화는 활성 `teamId`와 소유 `memberId`로 조회한다. 재로그인 후 이력 읽기와 현재 세션의 실행 허가를 구분한다. 팀 멤버여도 다른 사람의 대화 목록·본문·취소에 접근하지 못한다.

## 체크리스트 (PR/리뷰)

- [ ] 새 엔드포인트에 인증·역할 체크가 진입부에 있는가
- [ ] 작성자/소유자 ID를 세션에서 취하는가(클라 입력 미신뢰)
- [ ] 비밀을 클라이언트에 노출하지 않는가(`NEXT_PUBLIC_` 오용 없음)
- [ ] 업로드 Content-Type·크기 검증(PDF 전용)
- [ ] 다운로드가 서명 URL 경유인가
- [ ] Stream Key가 발표자에게만 가는가

## 로컬 AI 연결과 연구 보조 (ADR-025·026)

웹 세션·활성 팀·승인 기기에 2분 허가를 묶고 웹만 갱신한다. 앱에는 한 번에 최대 45초 앞까지만 알린다(ADR-033). 로그아웃·팀 전환·멤버 제거·만료 뒤 claim/result를 거부한다. 페어링은 웹 전용 6자리 번호·짧은 launch token·오답 5회·일회 소비로 확인한다. 앱은 등록 origin만 허용하고 기기 키를 OS 암호화 저장소에 보관한다. 서버에는 키의 해시만 둔다. CLI OAuth 파일은 복사·전송하지 않는다.

외부 CLI에는 서버가 검증한 팀 논문 텍스트와 질문만 전달한다. 로컬 파일·명령·MCP·프로젝트 지시를 제한하고 취소 시 소유 프로세스를 정리한다. 공개 broadcast에는 번호·키·사용량·질문·답변을 넣지 않는다. [신뢰 경계·검증 범위](../dev/LOCAL_AGENT.md)를 따른다.

분석 결과는 strict JSON 스키마·페이지별 원문 인용·Figure 캡션과 최신 실행을 검증한 뒤 두 관점에 원자적으로 저장한다. 유효 허가 중 이미 접수한 `completed` 결과의 후처리는 로그아웃 뒤에도 마칠 수 있으나, 최종 저장 전에 현재 팀 멤버십을 다시 확인한다. 만료 뒤 새 추론·실행 지속·늦은 결과 접수는 거부한다. 추출 실패는 소유한 오류 코드에 대응하는 고정 한국어 문구만 저장·반환하며 PDF 엔진의 원시 경로·오류를 노출하지 않는다.

## 생성 발표 자료 (ADR-032)

PT 제작 대화와 출력 파일은 등록 전까지 작업 소유자 개인 범위다. 새 추론·출력 접수·공유 저장은 현재 웹 세션의 grant를 검사한다. 접수된 native 렌더는 권한을 연장하지 않는 후처리이며 멤버십·원문 revision·덱 해시를 완료/다운로드에서 다시 검사한다. 최신 내용과 다른 파일은 409다. 내보내기에는 서버가 열거한 실제 Figure/원문 페이지만 쓰고 모델 URL·코드·파일 경로·HTML을 실행하지 않는다.

생성 HTML은 비공개 octet-stream 객체로 저장한다. 작업 다운로드와 공유 발표 첨부 다운로드는 인증·현재 팀 검증 후 attachment·sandbox CSP·nosniff로 반환한다. 다운로드 내용을 앱 origin에서 실행하는 미리보기 iframe은 만들지 않는다. 공유 첨부 PDF의 기존 단기 서명 다운로드를 유지한다. 업로드 정책은 PDF 전용이다.

## 목표 작업 (ADR-031)

작업 조회는 활성 팀·소유자로 제한한다. 새 행동·공유 저장은 현재 세션·멤버십·기기·grant를 트랜잭션에서 재검사한다. 모델/클라이언트는 임의 도구·대상·승인을 주입할 수 없다. 읽기 도구는 task에 고정된 같은 팀 논문만 읽는다. 논문·노트·목표 본문은 신뢰하지 않는 자료로 모델 지침과 구분한다.

검토 입력·원문 버전·task 버전을 결속하고 공유 객체와 원장을 함께 커밋한다. 별도 DB 조회가 실제 값과 일치할 때만 완료다. 쿠키·서명 URL·스토리지 경로·CLI 자격은 공개 DTO/이벤트에 넣지 않는다. PC는 도구가 제한된 텍스트 추론을 사용한다. 이미 접수한 결과의 개인 초안 검증은 새 실행 권한을 부여하지 않는다.
