# Architecture Decision Records

> **정본은 루트의 `PRD.md`(§6 주요 제품 결정, §8 열린 질문)와 `README.md`다.** 이 문서는 그 결정들을 ADR 형식으로 통합한 것이며, 충돌 시 루트 문서를 따른다. 아래 결정들은 의도적이다 — 코드를 보고 "고치지" 말 것.

## 철학
4인 단일 그룹을 위한 도구. 정직한 빈 상태, 단일하고 모호하지 않은 경로, 사람 중심의 분석. 인프라는 빌리고(영상 = LiveKit, ADR-019가 ADR-002 대체) 제품은 분석·일정·아카이브에 집중한다.

---

### ADR-001: 라이브 기본값은 "없음" + `live`를 앱 레벨 상태로
**결정**: 세미나 라이브는 기본적으로 꺼져 있고(빈 상태 + 명확한 시작 CTA), `live: boolean`은 화면이 아니라 앱 레벨에서 보유한다.
**이유**: 라이브는 예외이지 기본이 아니다. 사이드바 LIVE 배지, 홈 배너, 미팅 룸이 절대 어긋나면 안 된다.
**트레이드오프**: 상태를 위로 끌어올려 props 스레딩이 늘어난다. `MeetingScreen` 단독으로는 동작하지 않는다.

### ADR-002: 라이브 비디오는 Cloudflare Stream Live
**결정**: RTMP 서버/인코딩/HLS/CDN/녹화를 직접 구축하지 않고 Cloudflare Stream Live를 사용한다. 앱은 방송 생성·권한 체크·플레이어 노출만 담당한다.
**이유**: 4인 그룹에 영상 인프라 자체 구축은 과투자. 모델은 컨퍼런스(상호 그리드)가 아니라 1인 송출 + 다수 시청 방송에 가깝다.
**트레이드오프**: 외부 서비스 의존(비용·약관). 프로토타입의 상호 비디오 그리드는 1인 방송 모델로 재해석해야 한다(열린 질문: OBS 송출 여부, 녹화 보존, 종료 시 발표 자료로 아카이브할지).

### ADR-003: 업로드는 PDF 전용
**결정**: 업로드는 PDF(드래그앤드롭 또는 arXiv URL)만 받는다. PPTX/MD와 "빈 노트 / 아이디어 메모" 단축은 제거되었다.
**이유**: 수집 경로를 단일하고 모호하지 않게 유지. 제품의 본질은 논문 분석이다.
**트레이드오프**: 자유 형식 메모의 빠른 수집 경로를 포기한다.

### ADR-004: 두 관점(two-lens) 분석 + Figure 분석 공통 하단 고정
**결정**: 논문 분석은 상단 토글로 전환하는 **연구 / 재구현** 두 관점으로 구조화하고, `Figure 분석`은 두 관점 모두의 하단에 고정한다(노트는 `lens: "any"`). AI 요약/팀 노트 탭은 제거.
**이유**: 구조화된 두 관점 분석 자체가 페이지이며 경쟁하는 탭이 없어야 한다. figure는 두 읽기 모드가 공유하는 근거다.
**트레이드오프**: AI 자동 요약이라는 마케팅 포인트를 폐기하고 사람 중심 분석을 택했다.

### ADR-005: 노트는 전역이 아니라 섹션별
**결정**: "분석 추가"는 섹션마다(Figure 포함) 존재하고, 노트는 `{sectionId, lens}`로 스코프되며 작성자가 표기된다.
**이유**: 노트는 정확한 주장/섹션에 고정될 때 가장 유용하다.
**트레이드오프**: 전역 노트 한 개보다 UI와 데이터 모델이 복잡해진다.

### ADR-006: 스케줄은 절대 자동 생성하지 않음 + 명시적 편집/확정 모드
**결정**: 빈 달은 누군가 **일정 짜기**를 누르기 전까지 진짜로 비어 있다. 편집(초안) → 저장(영속화 + 순번 포인터 전진) → 확정(읽기 전용)의 명시적 라이프사이클을 가진다. 편집 중에는 달 이동이 잠긴다.
**이유**: 계획은 의도적 행위다. 가짜/유령 스케줄을 방지하고, 초안과 확정된 계획을 명확히 분리한다.
**트레이드오프**: "다음 달 자동 채움" 같은 편의를 포기한다. 매달 한 번의 명시적 클릭이 필요하다.

### ADR-007: 단일 테넌트, 초대 전용
**결정**: 4인 비공개 그룹 전용. 공개 회원가입 없음, 초대 링크로만 합류. 역할은 관리자/멤버/게스트.
**이유**: 멀티테넌트 SaaS가 아니다. 단순함이 4인 라이브러리에 맞다(같은 이유로 논문 목록 필터도 "전체" 하나만 유지).
**트레이드오프**: 확장성 포기. 다른 그룹이 쓰려면 별도 배포.
**🔁 개정됨 → ADR-018**: 단일 테넌트를 폐기하고 **멀티팀**으로 전환. "공개 가입 없음 · 역할 기반 · 초대 합류" 원칙은 **팀 단위로** 유지한다.

### ADR-008: 프로토타입은 빌드 없는 브라우저 Babel — 프로덕션에서 전면 교체
**결정**: 디자인 프로토타입은 React UMD + `@babel/standalone` + 전역 스코프 + `window.*` 목 데이터로 만들었다. 프로덕션은 실제 스택(예: React + TypeScript + Vite + Radix/shadcn)으로 재구축한다.
**이유**: 빌드 도구 없이 즉시 클릭 가능한 고충실도 레퍼런스를 만드는 것이 목적이었다.
**트레이드오프**: 프로토타입 코드는 출시 불가. UI는 충실히 재현하되 메커니즘은 전부 교체해야 한다(교체표는 [`../dev/ARCHITECTURE.md`](../dev/ARCHITECTURE.md)). `tweaks-panel.jsx`는 포팅 금지.

### ADR-009: 프로덕션 스택은 Next.js 15 (App Router)
**결정**: ADR-008이 Vite/React를 *예시*로 들었으나, 프로덕션 스택을 **Next.js 15 + TypeScript strict + Tailwind**로 확정한다.
**이유**: CLAUDE.md의 CRITICAL 규칙("모든 API 로직은 route handler에서만", "클라이언트에서 외부 API 직접 호출 금지")과 가장 정합적이다. 라이브 권한 체크·PDF 분석·초대 등 서버 로직을 한 스택에서 route handler/Server Action으로 처리한다.
**트레이드오프**: ADR-008의 예시와 달라진다. 프로토타입이 순수 React라 SPA(Vite)도 가능했지만, 서버 로직 일원화를 우선했다.

### ADR-010: 영속화는 Prisma + SQLite로 시작
**결정**: ORM은 Prisma, 개발 DB는 SQLite. Postgres 호환 타입만 사용해 이전 경로를 연다.
**이유**: 4인 단일 그룹에 경량·무설정 시작이 적합. 타입 안전.
**트레이드오프**: SQLite는 enum·배열 스칼라 미지원 → 문자열/JSON로 모델링하고 앱에서 검증([`../dev/DB.md`](../dev/DB.md)).

### ADR-011: 논문 분석 LLM은 "보조 추출"로만 (헤드라인 아님) — 제공자 Google Gemini
**결정**: PDF→두 관점 구조화 분석·figure 해석에 LLM을 쓰되, **사람이 검수·보강하는 보조**로 위치시킨다. AI 자동 요약을 핵심 기능으로 내세우지 않는다. **LLM 제공자는 Google Gemini**(`@google/genai` SDK) — Anthropic Claude에서 변경(`GEMINI_API_KEY`).
**이유**: PRD §3은 "AI 요약을 핵심으로 내세우기"를 폐기했다(ADR-004). 그러나 비교/ablation 표·figure 해석엔 "AI 추출"이 유효하다. 제품의 본질은 사람 중심 분석이고 LLM은 초안 생성기다. Gemini는 PDF document 입력·구조화 출력(responseSchema)·비전(figure)을 지원하고, 이미 Google OAuth를 쓰는 스택과 결이 맞는다.
**트레이드오프**: 외부 API 의존·비용. 키는 `.env`(서버 전용)에 두고 클라이언트 노출 금지([`../dev/ENV.md`](../dev/ENV.md), [`../security/SECURITY.md`](../security/SECURITY.md)). 제공자 교체 시 추출 프롬프트·스키마 재튜닝 필요.

**🔁 개정됨 → ADR-026:** 사람의 검수·보강 원칙은 유지한다. 현재 논문 분석의 기본 실행 제공자는 사용자가 명시적으로 고른 로컬 Codex·Claude Code이며 업로드 시 Gemini를 자동 호출하지 않는다. Gemini를 장애·한도 발생 시 자동 대체 경로로도 쓰지 않는다.

### ADR-012: 배포는 상시 구동 Node 서버 (서버리스 아님)
**결정**: 프로덕션은 서버리스 함수가 아니라 **상시 구동 Node 서버 단일 인스턴스**로 배포한다.
**이유**: ① 분 단위 분석/녹화 후처리를 인-프로세스 워커로 돌려야 하고 ② SQLite 파일은 영속 디스크가 필요하다. 서버리스는 둘 다 깨진다. 4인 단일 그룹엔 단일 인스턴스로 충분.
**트레이드오프**: 수평 확장 포기.
**🔁 개정됨 → ADR-016**: 배포는 **Vercel 서버리스 + Supabase**로 변경. "상시 Node 서버·SQLite 파일" 전제는 폐기. 아래 결정은 ADR-016 기준으로 읽는다.

### ADR-013: 긴 작업은 백그라운드 잡으로 (요청 경로 금지)
**결정**: 논문 분석·arXiv 가져오기·녹화 후처리는 요청 경로에서 인라인 실행하지 않고 **DB `Job` 테이블 + 인-프로세스 폴링 워커**로 처리한다. API는 잡만 적재하고 즉시 응답.
**이유**: LLM(Gemini) 분석은 분 단위라 HTTP 타임아웃을 넘는다. "업로드 성공 ≠ 분석 성공"을 아키텍처로 강제해 부분 실패를 격리한다.
**트레이드오프**: 즉시 결과가 아니라 pending→ready 전이.
**🔁 개정됨 → ADR-016**: 실행 주체는 인-프로세스 폴링 워커가 아니라 **외부 durable 잡 러너**(Inngest/Trigger.dev/QStash 등)로 변경. `Job` 모델(멱등·재시도·실패 보존)과 "업로드 성공 ≠ 분석 성공" 원칙은 유지 — 실행 주체만 외부 큐.

### ADR-014: 실시간 동기화는 SSE 푸시 (폴링 아님)
**결정**: `live` 전이·@멘션은 `/api/live/stream`(SSE)로 푸시한다. 클라이언트는 폴링하지 않는다.
**이유**: `live`는 모두에게 즉시 일관돼야 한다(ADR-001). 폴링은 지연·낭비. 단일 인스턴스라 인-프로세스 이벤트 버스로 충분.
**트레이드오프**: WebSocket이 아니라 단방향 푸시면 충분.
**🔁 개정됨 → ADR-016**: 전송 메커니즘은 인-프로세스 SSE 버스가 아니라 **Supabase Realtime**(broadcast/`postgres_changes`)로 변경. "폴링 금지, 즉시 푸시" 의도(ADR-001)는 유지 — Vercel 서버리스/다중 인스턴스에서도 성립.

### ADR-015: 읽기는 RSC 서버 조회, 쓰기는 Server Action/route handler
**결정**: 조회는 서버 컴포넌트(RSC)에서 `lib/` 서버 함수로 Prisma 직접 호출, 변이는 Server Action 또는 route handler로 처리한다. 클라이언트 컴포넌트는 인터랙티브 섬(live·관점 토글·스케줄 편집·업로드·명령 팔레트)에 한정.
**이유**: CLAUDE.md "서버 로직은 서버에서만"을 RSC 시대에 맞게 구체화. 클라이언트가 DB를 직접 보지 않으면서 초기 페인트가 빠르다.
**트레이드오프**: RSC/클라이언트 경계 설계 필요. 변이 후 `revalidatePath`/`revalidateTag`로 캐시 무효화를 신경 써야 한다.

### ADR-016: 배포는 Vercel + Supabase (ADR-010·012 개정)

> **이 ADR은 ADR-010(Prisma+SQLite)과 ADR-012(상시 구동 Node 서버, 서버리스 금지)를 개정한다.** 두 결정의 전제는 ① 분 단위 분석/녹화 후처리를 인-프로세스 워커로 돌려야 하고 ② SQLite가 영속 디스크를 요구한다는 것이었다. Supabase 채택으로 ②가 사라지고, ①은 외부 durable 잡 러너로 대체 가능하므로 서버리스 배포가 성립한다.

**결정**: 프로덕션을 **Vercel(Next.js 15) + Supabase**로 배포한다. 책임 재배치:

| 관심사 | 이전(ADR-010·012~014) | 변경 후 |
|---|---|---|
| 앱 호스팅 | 상시 구동 Node 서버 단일 인스턴스 | **Vercel** (서버리스/Edge + Fluid Compute) |
| DB/ORM | Prisma + SQLite (영속 디스크) | **Prisma + Supabase Postgres** (`DATABASE_URL` = pooled, `DIRECT_URL` = 마이그레이션용) |
| 파일 스토리지 | 외부 객체 스토리지 | **Supabase Storage** (프리사인 업로드 / 서명 URL) |
| 실시간(`live`·@멘션) | 인-프로세스 이벤트 버스 + SSE | **Supabase Realtime** (broadcast / `postgres_changes`) |
| 백그라운드 잡(분석·arXiv·녹화 후처리) | 인-프로세스 폴링 워커 | **외부 durable 잡 러너**(Inngest/Trigger.dev/QStash 등) — `Job` 테이블 패턴을 큐로 이관 |

**이유**:
- **②(영속 디스크) 소멸**: Supabase Postgres는 관리형이라 SQLite 파일·영속 볼륨이 필요 없다. ADR-010이 열어둔 "Postgres 이전 경로"를 실제로 밟는 것이다.
- **실시간이 더 깔끔해짐**: `live`는 모두에게 즉시 일관돼야 한다(ADR-001). 인-프로세스 버스(단일 인스턴스 한정)를 **Supabase Realtime**으로 대체하면 서버리스/다중 리전에서도 전이 전파가 성립한다. ADR-014의 의도(폴링 금지, 푸시)는 유지된다 — 메커니즘만 교체.
- **①(분 단위 잡)의 유일한 진짜 제약 해소**: Vercel 함수는 실행 시간 제한이 있어 분 단위 LLM(Gemini) 분석을 인라인으로 못 돌린다. 그래서 분석·arXiv 가져오기·녹화 후처리는 **durable 잡 러너**(재시도·멱등·관찰성 내장)에 맡긴다. "업로드 성공 ≠ 분석 성공"(ADR-013)의 원칙과 `Job` 모델(멱등·재시도·실패 보존)은 **그대로 유지**되며, 인-프로세스 폴링 대신 외부 큐가 실행 주체가 될 뿐이다.

**트레이드오프**:
- 인프라 의존이 단일 벤더(자체 서버)에서 **Vercel + Supabase + 잡 러너**로 늘어난다(비용·약관·콜드 스타트).
- ADR-013의 "외부 큐는 과투자" 판단을 뒤집는다 — 서버리스에선 외부 큐가 **필수**다.
- 인증은 자체 서명 세션(ADR-007/SECURITY) 유지 또는 Supabase Auth로 이관 중 택1 — **단일 테넌트·초대 전용 원칙은 불변**. 본 ADR 범위 밖, 별도 결정 필요.
- Cloudflare Stream Live(ADR-002)는 영향 없음. 녹화 완료 웹훅은 Vercel route handler가 그대로 수신(HMAC 검증).
- 다중 인스턴스 환경이 되므로 인-프로세스 상태(이벤트 버스 등)에 의존하던 코드는 전부 외부 서비스(Realtime/잡 러너)로 빠져야 한다.

### ADR-017: 인증은 Google OAuth (Supabase Auth) + 초대 게이트
**결정**: 로그인은 **Supabase Auth의 Google OAuth**로 한다(미결이던 인증 수단 확정). **초대 전용은 유지**(ADR-007) — Google 로그인에 성공해도, 그 이메일이 **수락된 멤버이거나 유효한 초대**가 있을 때만 합류/세션이 발급된다. 비초대 이메일은 거부 + 로그아웃.
**이유**: 비밀번호 컬럼 없이(`Member`에 password 미추가) 안전한 외부 인증. Supabase가 OAuth·토큰·리프레시를 관리.
**트레이드오프**: Supabase 프로젝트 + Google Cloud OAuth 클라이언트 필요(키 없으면 OAuth 왕복 검증 불가 → 해당 step `blocked`). step4의 dev 이메일 로그인은 키 없을 때의 **로컬 테스트 폴백**으로만 남긴다(프로덕션 경로 아님). Supabase `auth.users` ↔ 우리 `Member`를 이메일로 매핑한다.
**🔁 개정됨 → ADR-018**: **이메일 매칭 게이트 → 초대 토큰 합류**로. Google OAuth 인증은 유지하되, 로그인 자체는 누구나 가능(처음엔 팀 없음)하고 **합류만** 토큰으로 게이트한다.

### ADR-018: 멀티팀 워크스페이스 (ADR-007·017 개정)

> **이 ADR은 ADR-007(단일 테넌트, 초대 전용)과 ADR-017(이메일 매칭 초대 게이트)을 개정한다.** RLS 미사용 · 앱레벨 권한(ADR-016)은 **그대로 유지**한다. 다른 앱(`photo-moments`)의 Auth/Teams 패턴을 *참고*하되, RLS·`security definer` RPC·트리거·플랜/과금·세션 무효화·정원 예약은 도입하지 않는다.

**결정**: 단일 고정 워크스페이스를 폐기하고 **멀티팀**으로 전환한다.
- 로그인 사용자는 **처음엔 팀이 없다**. 로그인(Google OAuth)은 누구나 되지만, 진입은 **팀 생성** 또는 **초대 토큰 수락**으로만.
- 역할은 **팀별** `owner`/`admin`/`member`. **UI 표기도 영어 그대로**(owner/admin/member) — 한국어(팀장/관리자/팀원) 쓰지 않는다. `owner`는 초대로 부여 불가, 팀엔 `owner` ≥ 1 보장.
- 합류는 **초대 토큰**(N인 `maxUses` · 만료 `expiresAt` · 회수 `revokedAt`). `owner`·`admin`이 발급, 부여 역할은 `admin`·`member`.
- **전역 팀 생성 상한**: 서버 전체에서 `MAX_TEAMS`(env, 기본 **2**)개까지. 초과 시 "최대 팀 수를 초과했어요". (per-user 한도·플랜 미도입 — `(지금은)` 전역 상한.)
- 권한은 RLS 없이 **앱레벨**(route handler/Server Action)에서 강제(ADR-016). 세션은 기존 자체 서명 쿠키(`lib/auth`)를 유지한다.
- 기존 "하박조팽"은 **팀 1개로 이관**(기존 `관리자` = `owner`, 나머지 = `member`).

**범위**: 이번 단계는 **인증/팀 레이어만**. 기존 엔티티(`Paper`·`Schedule`·`Presentation`·`LiveSession`·`Fine`)는 **아직 팀 스코핑하지 않는다**(단일 워크스페이스 유지) — 별도 단계로 미룬다.

**이유**: 여러 연구 그룹이 한 배포를 공유하도록 확장. "초대 전용"의 정신(공개 가입 없음)은 유지하되, 게이트를 *로그인 시점 이메일 매칭*에서 *팀 합류 시점 토큰 검증*으로 옮긴다.

**트레이드오프**:
- 초대 링크 = 베어러 자격증명 → 유출 시 누구나(부여 역할로) 합류. N인·만료·회수로 완화(세션 무효화·정원 예약은 미도입).
- 과도기: 기존 기능이 비스코핑이라 2번째 팀은 기존 데이터를 공유한다(팀 스코핑 단계 전까지). 의도된 단계적 전환.
- `R17`(논문 목록 필터 "전체" 하나만)은 **영향 없음** — 그대로 유지.

### ADR-019: 라이브는 LiveKit 다자간 화상 컨퍼런스 (ADR-002 대체)

> **이 ADR은 ADR-002(라이브 비디오 = Cloudflare Stream Live, 1인 송출 + 다수 HLS 시청)를 대체한다.** ADR-001(`live` 앱 레벨·단일 세션)·R6(동시 1개)·R33(전이는 Supabase Realtime)·ADR-015(읽기 RSC·쓰기 라우트)·R2(키는 서버·키 없이 build/test 통과)는 그대로 유지한다.

**결정**: 세미나 라이브를 **1인 송출 단방향 방송에서 다자간 실시간 화상 컨퍼런스로 전환**한다. 영상·음성·화면공유 트랙은 **LiveKit(SFU)**가 나른다(Cloudflare Stream Live 폐기). 참가자는 모두 같은 LiveKit 룸에 접속하며(카메라는 선택 — 끄면 아바타 타일), 발표자는 화면공유 권한을 추가로 가진다.

- **영상/음성/화면공유**: LiveKit. 룸 이름은 `LiveSession.id`에서 파생(`live-{id}`). 참가자 신원(identity) = `Member.id`(아바타·이름 매핑용).
- **입장 토큰**: 서버가 참가자별 LiveKit AccessToken을 발급한다(`/start`는 발표자, `/join`은 시청자). **화면공유 grant(`canPublishSources`의 screen_share)는 발표자 토큰에만** 넣는다(R7 개정). 토큰은 본인에게만 응답하고, 신원은 세션에서 주입한다 — 클라가 보낸 식별자 미신뢰(R3).
- **채팅·반응·손들기**: 별도 서버/인프라 없이 **LiveKit 데이터 채널**로 룸 내부에서 주고받는다(휘발·미저장 — 4인 세미나에 충분). 메시지 작성자는 LiveKit 참가자 identity로 판별하고, 페이로드의 author는 신뢰하지 않는다.
- **송출 타이머**: 서버 `LiveSession.startedAt` 기준으로 클라이언트가 경과 시간을 표시한다.
- **앱 전역 `live` 전이**(사이드바 LIVE 배지·홈 배너): 변경 없이 **Supabase Realtime**(`live.started`/`live.ended`)을 유지한다(R33). 룸 내부 presence는 LiveKit, 앱 전역 on/off는 Supabase — 역할이 다르다.

**이유**: PRD가 가정한 "1인 송출 + 다수 시청"(ADR-002)은 실제 기대("서로 얼굴 보이는 화상 세미나")와 어긋났다. 4인 그룹엔 SFU 한 대로 충분하고, 영상 인프라는 여전히 빌린다(R8 정신 유지 — 위탁 대상만 Cloudflare→LiveKit). 채팅 등은 룸에 이미 붙은 데이터 채널로 처리해 이중 presence/시그널링을 피한다.

**트레이드오프**:
- 외부 벤더가 Cloudflare Stream → LiveKit으로 교체된다(비용·약관). 새 키 `LIVEKIT_URL`/`LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET`이 필요 — 키가 없으면 `/start`·`/join`이 `503`으로 친절히 안내(R30)하고, build/test는 키 없이 통과한다(R2).
- 단방향 HLS의 "녹화 자동" 이점을 잃는다 — 녹화는 LiveKit Egress로 가능하나 **이번 범위 밖**(미결 → ISSUES). 기존 `recordingUrl`·Cloudflare 웹훅 경로는 폐기한다.
- `LiveSession.cloudflareLiveInputId` 컬럼은 미사용으로 남긴다(무해한 레거시, 후속 마이그레이션에서 제거) — 이번 phase는 스키마 변경·`prisma db push` 없음.
- 라이브는 **여전히 단일 전역 세션**이며 팀 스코핑하지 않는다(ADR-018 범위 유지 — 팀 분리는 다음 phase).

### ADR-020: 엔티티 팀 스코핑 (ADR-018 보류분 실행 · ADR-019 개정)

> **이 ADR은 ADR-018이 "별도 단계로 미룬다"고 명시한 엔티티 팀 스코핑을 실행하고, ADR-019의 "전역 동시 1개 라이브 세션"을 "팀당 동시 1개"로 개정한다.** RLS 미사용·앱레벨 권한(ADR-016)·초대 토큰 합류(ADR-018)는 그대로 유지한다.

**결정**: 도메인 엔티티를 팀별로 스코핑한다. 각 팀은 자기 데이터(홈·논문·발표자료·스케줄·벌금·라이브)만 본다.
- `Paper`·`Presentation`·`ScheduleMonth`·`FineConfig`·`MemberLedger`·`LiveSession`에 `teamId`. 하위 엔티티(`Analysis`·`Figure`·`SectionNote`·`Comment`·`ScheduleWeek`)는 부모를 통해 스코핑한다(자체 teamId 불필요).
- **활성 팀(active team)**: 사용자는 여러 팀에 속할 수 있고, "활성 팀"을 **쿠키**로 보관한다(검증: 반드시 내 멤버십이어야). 기본값은 가장 최근 합류 팀(`resolveEntryTeam`). `TeamSwitcher`가 활성 팀을 실제로 전환하고 화면을 revalidate한다.
- **쓰기**: `teamId`는 **활성 팀에서 서버가 주입**한다(클라가 보낸 teamId 미신뢰, R3). 다른 팀 엔티티 접근은 `403`(R19).
- **라이브**: 팀당 동시 active 1개(ADR-019 "전역 1개" 개정). `getActiveSession(teamId)`, `LiveSession.teamId`, LiveKit 룸 이름에 팀 포함.
- **고유 제약 변경**: `ScheduleMonth` `@@unique([teamId, year, month])`, `FineConfig` `@@id([teamId, year])`, `MemberLedger` `@@unique([teamId, year, memberId])` — 팀별 독립.

**이유**: ADR-018은 인증/팀 레이어만 했고 엔티티는 단일 워크스페이스로 남겨, 2번째 팀이 1번째 팀 데이터를 공유했다(의도된 과도기). 이 ADR이 그 과도기를 끝낸다.

**트레이드오프**:
- 운영 DB 마이그레이션 필요(teamId 컬럼 + 제약/PK 변경 + 기존 행 백필). **공유 운영 DB라 `prisma db push`(실 반영)는 코드와 분리된 *검토된 수동 단계*로 실행**한다 — harness step은 스키마·백필·테스트 코드까지만 만들고, 실제 push/백필 실행은 사람이 검토 후 한다(ADR-018 step에서 push를 미룬 선례).
- 기존 데이터는 전부 부트스트랩된 "하박조팽" 팀(seed 이관 팀, 가장 먼저 생성된 팀)으로 백필(멱등).
- **교차 팀 격리**가 새 핵심 불변식 — 권한 누락 시 데이터 유출이므로 TDD로 강제한다.
- `R17`(논문 목록 필터 "전체" 하나)은 영향 없음 — 팀 내에서 "전체"는 그대로.

### ADR-021: 진입 팀 허브 (ADR-018 정밀화)

> **이 ADR은 ADR-018(멀티팀)을 *개정하지 않고 정밀화*한다.** 전역 팀 생성 상한(`MAX_TEAMS`)·초대 토큰 합류·RLS 미사용 앱레벨 권한(ADR-016)·자체 서명 세션은 **그대로 유지**한다. 활성 팀 쿠키·`POST /api/teams/active`(ADR-020/R37)도 변경 없이 재사용한다. 이 결정은 "로그인 후 어디에 착지하는가"라는 진입 라우팅만 명문화한다.

**결정**: 로그인 사용자는 진입 시 **항상 팀 허브 `/teams`에 착지**한다(속한 팀이 1개여도 거친다). 허브에서:
- **속한 팀을 선택** → 활성 팀 쿠키 설정(`POST /api/teams/active`, 기존 재사용) → `/dashboard` 진입.
- **새 팀 만들기**(전역 상한 미달일 때만) · **받은 초대 링크로 합류** 안내.
- 팀이 **0개면** 만들기/초대 안내만 보인다(기존 `/teams/new`의 "팀 없음" 역할을 흡수).

- **`/teams/new` 폐지**: 허브 `/teams`로 흡수한다. "팀 없음" 진입 가드의 목적지도 `/teams/new` → **`/teams`**로 바꾼다(`needsTeamOnboarding`의 예외/리다이렉트 목적지 갱신).
- **진입 라우팅 변경**: 로그인 후 기본 착지 `/dashboard` → **`/teams`**(`auth/callback`·`app/page` 모두). 단 **초대 복귀(`next`)는 그대로 우선** — `next`가 정제(same-origin)된 값이면 허브를 건너뛰고 그쪽으로 보낸다(`sanitizeNext` 유지).
- **활성 팀 쿠키는 유지**되므로 `/dashboard` 등 **직접 방문(북마크)은 그대로 동작**한다 — 허브는 "로그인 직후 착지"에만 강제되고, 매 네비게이션마다 세우는 벽이 아니다.
- **생성 상한 정책(유지 + 가시화)**: 상한은 기존대로 **전역**(서버 전체 `team.count()` vs `MAX_TEAMS`, **per-user 아님**)이며 **admin이 env(`MAX_TEAMS`)로만 설정**한다(사용자 UI로 변경 불가). 허브는 상한 도달 시 만들기를 **비활성 + 안내**로 가시화한다(R30 — 따뜻한 인라인 카피). per-user 한도·플랜은 **상업화 시점에 도입**하며 현재는 미도입(ADR-018의 "per-user·플랜 미도입" 정신 계승).
  > **2026-08-01 개정(ADR-024):** "admin이 env(`MAX_TEAMS`)로만 설정(사용자 UI로 변경 불가)" 조항은 폐기됐다. 상한은 이제 DB(`AppSetting.maxTeams`)에 저장되고 관리자 콘솔(`/admin`)에서 조절한다. env `MAX_TEAMS`는 DB row가 없을 때의 폴백으로만 남는다. **전역 상한이라는 성격(per-user 아님)과 허브의 가시화는 그대로다.**
- **위치 근거**: 허브는 `(app)` 셸 **밖**의 독립 로비다(사이드바·`TeamSwitcher` 없음) — `/invite`처럼 "선택 전 화면"과 "선택 후 앱"을 분리한다. 셸은 활성 팀이 정해진 뒤에만 의미가 있다.

**이유**: ADR-018/020으로 한 사용자가 여러 팀에 속할 수 있게 됐지만(`listMemberships`), 로그인 후 곧장 `/dashboard`로 보내면 *어떤 팀의* 대시보드인지가 암묵적(최근 합류 폴백)이라 다팀 사용자에게 혼란스럽다. 진입을 허브로 모으면 "지금 어느 팀으로 들어가는가"가 항상 명시적 선택이 되고, 팀 생성·초대 합류·전역 상한 안내를 한 화면에 모을 수 있다. ADR-018이 "처음엔 팀 없음 → 만들기/초대"라고만 둔 진입을, 팀이 있든 없든 거치는 단일 로비로 일반화한 것이다.

**트레이드오프**:
- **항상 허브**라서 단일 팀만 가진 사용자도 로그인마다 **1클릭이 추가**된다(활성 팀 쿠키 직접 방문으로 우회는 가능). "팀 1개면 자동 진입"은 의도적으로 채택하지 않는다 — 진입 경로를 하나로 단순·일관화하기 위해(ADR-018의 "단일하고 모호하지 않은 경로" 정신).
- 관리 화면 **`/team`**(팀 관리, 단수)과 허브 **`/teams`**(복수)의 이름이 유사해 혼동 여지가 있다 — 역할이 다름(관리 vs 로비)을 화면 카피로 분명히 한다.
- 초대 복귀(`next`)가 우선하므로, 초대 링크로 들어온 신규 사용자는 허브를 거치지 않고 합류 흐름으로 직행한다(의도된 우선순위).

### ADR-022: NEWS 팀 출판 실적 쇼케이스

> **이 ADR은 기존 결정을 개정하지 않고, 새 기능 영역을 추가한다.** 팀 스코핑(ADR-020/R37)·RLS 미사용 앱레벨 권한(ADR-016)·프리사인 직접 업로드/서명 URL(R36)·초대 전용 비공개 워크스페이스(ADR-007)를 그대로 따른다. 기존 "논문"(`Paper`, 분석 대상) 결정(ADR-003/004)과 충돌하지 않는다 — NEWS는 별개 엔티티다.

**결정**: 팀이 발표·출판한 자기 실적(우리 논문)을 모아 보여주는 **내부 쇼케이스 NEWS 탭**을 추가한다. 기존 "논문 분석"(`Paper`)과 의미가 다르다 — Paper는 *남의 논문을 업로드해 두 관점(연구·재구현)으로 분석*하는 협업 도구이고, NEWS는 *우리 팀의 출판 실적*을 카드로 진열하는 쇼케이스다. 랩 홈페이지의 "Publications/News" 섹션을 팀 내부 전용으로 옮긴 것.

- **새 `Publication` 모델을 도입한다(`Paper` 재사용 금지).** `Paper`는 분석 대상이라 `analyses`·`figures`·`notes`가 딸리고, `schema.prisma`에 "kind 같은 타입 필드 두지 말 것"(ADR-003)이 명시돼 의미가 충돌한다. 분석 파이프라인·figure·노트가 전혀 필요 없는 NEWS를 Paper에 끼우면 두 의미가 섞인다 → 별 테이블로 깔끔히 분리한다([`../dev/DB.md`](../dev/DB.md) `Publication`).
- **팀 내부 전용.** 외부 공개 라우트·인증 우회·SEO 없음 — 기존 앱 셸 안에서 **로그인 + 활성 팀 스코프**로만 접근한다. (공개 Publications가 아니라 팀 내부에서 보는 실적 모음.)
- **저자는 자유 텍스트 한 줄**(외부 공저자 포함, 기존 `Paper.authors`와 동형). 렌더 시 `Member.name`과 일치하는 팀원 이름만 강조한다. Member FK 연결·멤버별 실적 집계는 하지 않는다(집계 요구 없음 — YAGNI).
- **티저 이미지**는 클라이언트→스토리지 **프리사인 직접 업로드**, **비공개 버킷 + 단기 서명 URL** 서빙(R36). figure 이미지와 동일 메커니즘을 재사용한다.
- **모든 팀원이 추가·편집·삭제** 가능(논문·발표 자료와 같은 협업 모델 — 역할 게이트 없음, 활성 팀 멤버면 쓰기 허용).
- **팀 스코핑(ADR-020/R37).** `Publication.teamId`로 스코핑하고, 쓰기 시 `teamId`·`createdBy`는 서버가 활성 팀·세션에서 주입한다(클라 미신뢰, R3). 다른 팀 자원 접근은 `404`(존재 숨김, R19).

**이유**: 팀이 "우리가 이런 걸 냈다"를 한곳에 모아 보는 내부 쇼케이스 수요가 있다. 이는 분석 협업(Paper)과 목적이 다르므로 **별 엔티티**가 가장 단순하고 기존 패턴(`presentations` CRUD)과 100% 일치한다. 외부 공개·집계·분석 같은 기능을 의도적으로 빼 4인 그룹에 맞는 최소 형태로 둔다.

**트레이드오프**:
- 모델이 하나 늘어 스키마·라우트·화면이 추가된다(그러나 기존 `presentations` 패턴 복제라 비용이 낮다).
- 저자를 자유 텍스트로 두어 팀원-실적 집계·검증이 불가하다(현 4인 규모에선 불필요 — 문자열 강조로 충분).
- 외부 공개가 없어 랩 홈페이지를 대체하진 못한다(의도된 범위 — 내부 전용).
- **운영 반영은 수동(ADR-020 정신).** `Publication`은 **신규 테이블이라 백필 대상 기존 행이 없지만**, 공유 운영 DB에 실제 `prisma db push`를 적용하는 것은 harness step이 아니라 **사람이 검토 후 수동 실행**한다. harness step은 스키마·코드·테스트까지만 만든다.

### ADR-023: 벌금 장부 수동 편집 · 설정 명시 생성

> **이 ADR은 기존 결정을 개정하지 않고, 벌금(fine) 기능을 "보여주기"에서 "동작"으로 끌어올리는 쓰기 경로를 명문화한다.** 팀 스코핑(ADR-020/R37)·서버 전용 쓰기(ADR-015)·RLS 미사용 앱레벨 권한(ADR-016)·"절대 자동 채움하지 않음"(ADR-006/R15)을 그대로 따른다. 스키마(`FineConfig`·`MemberLedger`)는 이미 존재하며 변경하지 않는다([`../dev/DB.md`](../dev/DB.md)).

**맥락**: 현재 벌금은 읽기·표시 + 금액 수정만 있고 데이터를 넣는 경로가 없다 — (1) 연도별 `FineConfig`를 만드는 런타임 경로가 없어 패널이 항상 "이 해의 벌금 설정이 아직 없어요"만 뜨고, (2) `MemberLedger`(참여·발표자 불참·일반 불참·납부)에 쓰는 코드가 전무해 멤버 현황 표가 영원히 0이다. 이 두 경로를 **어떻게** 채울지 결정한다.

**결정**:
- **벌금 장부(`MemberLedger`: 참여·발표자 불참·일반 불참·납부)는 관리자 수동 편집으로 채운다.** 스케줄 주차에서 자동 집계하지 않는다. 멤버별 출석 데이터 모델이 없고(스케줄 주차는 발표자만 안다), 스케줄의 "절대 자동 채움하지 않음"(ADR-006) 철학과 일관한다. 출석 추적을 새로 만드는 것은 별도 task(YAGNI).
- **연도별 `FineConfig`는 관리자가 명시적으로 생성한다.** GET/조회가 자동 생성하지 않는다 — row 부재 = 미설정(ADR-006/R15와 같은 정신). 생성 시 금액은 스키마 default(`finePresenter=30000`·`fineAbsent=10000`)를 따른다.
- **생성·장부 편집·금액 수정 모두 관리자 전용**(기존 `updateFines`와 동일, [`../security/SECURITY.md`](../security/SECURITY.md) "벌금 금액 수정"). 일반 멤버에겐 해당 UI를 노출하지 않는다(R19) — UI 숨김은 보조이고 권한은 서버(Server Action) 진입부에서 강제한다.
- **스키마 변경 없음.** `FineConfig`·`MemberLedger`는 이미 존재한다 — 이 결정은 쓰기 경로(Server Action)와 편집 UI만 추가한다. 누적 벌금·미납은 계속 저장하지 않고 파생한다(DB.md 파생값 표).

**이유**: 벌금은 "가벼운 사회적 장치"(PRD §핵심 기능, ISSUES I-4 정보용 장부)이지 결제·출석 추적 시스템이 아니다. 4인 그룹에선 관리자가 세미나 후 표를 손으로 채우는 것이 가장 단순하고 정직하다 — 자동 집계는 없는 데이터(멤버별 출석)를 전제하므로 새 모델·UI를 부른다. 명시 생성은 "빈 달은 진짜 빈 달"과 같은 정신으로, 유령 설정을 막는다.

**트레이드오프**:
- 관리자가 매번 수동으로 입력해야 한다(자동화 없음) — 4인 규모에선 부담이 작고, 스케줄 편성과 같은 명시적 행위 모델이다.
- 출석을 별도로 추적하지 않아 장부 숫자의 출처가 사람의 판단이다(감사 추적 없음) — 정보용 장부라 허용 범위.
- per-멤버 출석 자동 반영·결제 연동은 미도입(ISSUES I-4) — 필요해지면 별도 결정.
- 범위 밖(추후/미도입): 초록·본문 텍스트, 출판 상태 배지(under review/accepted), 댓글·반응·버전, PDF 업로드·분석(그건 `Paper` 소관).

### ADR-024: 관리자 콘솔(`/admin`) — 전역 설정 + 라이브 사용량 가시화

> **이 ADR은 ADR-021의 "상한은 admin이 env로만 설정" 조항을 개정한다.** 전역 상한이라는 성격(per-user 아님)·초대 토큰 합류(R18)·RLS 미사용 앱레벨 권한(ADR-016)은 그대로 유지한다.

**결정**: 운영자가 재배포 없이 전역 설정을 바꾸고 LiveKit 사용량을 확인할 수 있는 **관리자 콘솔 `/admin`**을 둔다.

- **전역 설정은 `AppSetting` 단일 row**(`id="singleton"`)에 저장한다. 우선순위는 **DB > env > 코드 기본**이고, **row 부재는 "미설정"**이다(자동 생성하지 않는다 — ADR-006/R15 정신).
- **콘솔 접근은 `Member.email == ADMIN_EMAIL`**(기본 `de8167@gmail.com`)로만 연다. **`Member.role`을 쓰지 않는다** — role은 DB에서 승격될 수 있어 경계로 약하다. 실패는 403이 아니라 **404**로 존재를 숨긴다.
- **라이브 사용량은 `LiveSession`/`Participant`에서 참가자-분을 추정**한다. LiveKit Analytics API는 쓰지 않는다(무료 한도 감시가 목적이라 추정으로 충분).
- **월 경계는 KST 1일 00:00.** 월을 걸친 세션은 `joinedAt`이 속한 달에 전액 귀속한다(분할 없음 — 드문 사례에 로직 비용이 크다).
- **한도 1,000분은 LiveKit 플랜이 정하므로 조절 UI를 두지 않는다.** env `LIVE_MINUTES_QUOTA`로 플랜 변경만 대비한다.
- **조절 대상은 전역 팀 상한 하나뿐**이다. 주간 논문 분석 한도(`PAPER_WEEKLY_LIMIT`)·실패 Job 목록은 의도적으로 뺐다(YAGNI).

**이유**: 팀 상한에 걸려도 운영자가 스스로 풀 방법이 없었고(env 수정 + 재배포 필요), LiveKit 무료 한도 소진 여부를 앱 어디서도 볼 수 없어 사후에야 알게 됐다. 두 문제 모두 "서버 전체" 관심사라 팀 스코프 화면이 아니라 전역 콘솔이 맞다.

**트레이드오프**:
- **사용량은 추정치다.** 재참가가 `Participant` 행을 덮어써(`@@unique([liveSessionId, memberId])`, `leftAt=null`) 과소집계될 수 있고, `/leave` 미호출 시 `endedAt` 보정 때문에 과대집계될 수 있다. UI에 "추정치"로 표기한다. 정확한 값이 필요해지면 LiveKit Analytics API 연동을 별도 검토한다.
- `maxTeams()`가 **동기 → 비동기**가 되고 소유가 `lib/teams.ts` → `lib/settings.ts`로 옮겨간다(호출부에 `await` 추가).
- **`AppSetting` 테이블이 없으면 `maxTeams()`가 던진다** — 팀 생성·`/teams`·`/admin`이 모두 막힌다. 따라서 **코드 배포보다 `prisma db push`가 반드시 먼저**다(ADR-022와 같은 수동 반영 원칙).
- 관리자 판정이 이메일 1개에 묶여 있어 운영자를 늘리려면 env를 바꿔야 한다(현 1인 운영엔 충분 — 복수 관리자는 필요해지면 도입).

## ADR-025 — 설치형 로컬 AI 연결기와 짧은 실행 허가

**결정(2026-10-17):** Codex·Claude Code 로그인으로 논문 질문·연구 보조를 실행하는 선택 기능을 추가한다. 웹 origin은 `https://hapark.vercel.app`, 프로토콜은 `hapark-connect`다. 최초 설치 후 웹 버튼으로 다시 열고 첫 실행은 웹 복귀 URL로 연결 요청을 받는다. 웹의 6자리 번호를 앱의 빈 입력에 확인한다. 같은 로그인·팀·기기만 번호 없이 재연결한다.

실행 허가는 45초이며 웹만 갱신한다. 로그아웃·팀 전환·멤버 제거는 회수하고 쿠키 유실은 만료로 중단한다. 작업은 DB 큐에 적재해 즉시 응답하고 로컬 연결기가 claim한다. 기존 Gemini/Inngest·두 관점 페이지는 유지한다. 모델은 실제 CLI 목록에서 직접 선택하고 한도는 실제 기간·비율·관측 시각만 표시한다. 인증 파일을 서버에 전송하지 않는다.

**트레이드오프:** 앱 한 번 설치와 OS/브라우저 확인이 필요하다. CLI 버전·기능 제한, macOS 서명/공증, Ubuntu GUI/비밀 저장소 제약이 있다. 공유 DB 적용은 기존대로 사람의 SQL 검토·수동 실행 대상이다. [LOCAL_AGENT](../dev/LOCAL_AGENT.md)에 계약·검증을 기록하며 제품 완성 후 공통 repo와 UI/UX 맞춤 스킬로 분리한다.

**🔁 개정됨 → ADR-026:** 설치·페어링·45초 허가·실제 모델 선택은 유지한다. 위의 "기존 Gemini 분석 유지" 범위는 명시적 로컬 모델 논문 분석과 별도 개인 연구 채팅으로 확장·대체한다. 유효 허가 중 서버가 접수한 완료 결과의 후처리와, 만료 후 새 추론은 구분한다.

## ADR-026 — 로컬 모델 논문 분석과 개인 연구 채팅

**결정(2026-10-17):** 사용자의 Codex·Claude Code 구독 로그인을 논문 분석과 연구 보조에 사용한다. ADR-011의 Gemini 기본 제공자와 ADR-025의 기존 분석 유지 범위를 개정한다. 업로드는 PDF 저장·원문 텍스트 준비까지만 수행하여 AI 호출이 없다. 사용자가 연결한 PC·제공자·실제 모델을 선택해 시작한 분석만 실행한다. Gemini·다른 CLI·원격 API로 자동 과금 대체하지 않는다.

**실행과 저장:** `paper/analyze`의 본문 준비 경로는 페이지별 원문과 PDF SHA256을 캐시한다(1~30쪽·본문 12만 자, 스캔·초과는 정직한 준비 실패). 명시적 분석 요청은 `Job(type=prepare_local_analysis)`와 최신 `Paper.analysisRequestId`를 저장한다. Inngest는 서버가 준비한 문맥으로 `LocalAgentJob(purpose=paper_analysis)`를 적재하고 durable sleep·짧은 DB 조회로 완료를 회수한다. 장기 CLI는 PC에서 실행하며 서버리스 요청에서 기다리지 않는다. 결과의 strict JSON, 양 관점의 페이지·원문 인용과 Figure 캡션을 검증하고 최신 실행 CAS로 `Analysis(research/repro)`·`Figure`·상태를 원자적으로 저장한다. 사용자 섹션 노트는 유지한다.

**제품과 한계:** 두 관점 페이지와 공통 Figure 하단은 유지하며 논문 상세에 AI 탭·사이드패널을 추가하지 않는다. 현 CLI 계약은 텍스트 전용으로 파일·브라우저·셸 도구를 차단한다. Figure는 실제 PDF 페이지를 표시하되 해석은 본문·캡션 기반 추론으로 표시한다. 외부 저장소는 방문·검증하지 않으며 `repo.found=false`, `source=paper`로 제한한다.

**개인 대화(2026-10-18 개정):** 별도 작업 공간 메뉴 `/ai-chat`에서 자료 없이 자유롭게 대화한다. 질문마다 `@`로 같은 팀 논문·발표 자료를 합계 10개까지 선택한다. `ResearchConversation.paperIds`의 기존 배열은 계속 읽고 새 선택은 version 2 JSON으로 저장한다. `LocalAgentJob(purpose=chat)`의 서버 context에 해당 턴의 자료 스냅샷과 완료된 이전 대화를 보존한다. 자료 본문 준비는 `preparing` 상태의 잡과 `research-chat/prepare` Inngest 이벤트로 처리하며 준비 뒤 실행 권한을 다시 검사한다. 자료 없는 질문은 곧바로 큐에 넣는다. 모델 설정은 현재 연결의 실제 카탈로그를 사용하고 지원이 확인된 추론 강도만 전달한다. 부분 답변·중지·끊김·세션 오류를 구분한다. 소유자+활성 팀으로 개인 이력을 지속 조회하되 실행은 현재 세션의 grant를 요구한다. 같은 대화의 동시 턴은 하나이며 재전송은 같은 요청으로 처리한다. 목록 100개·상세 최근 50턴, 모델 문맥은 완료된 최근 8턴과 원문 최대 20만 자이고 생략 여부를 알린다. 대화가 공유 분석·노트를 자동 변경하지 않는다.

**완료 경계:** 유효한 45초 grant 중 서버가 이미 `completed`로 접수한 결과는 로그아웃 후에도 검증·렌더·영속을 마칠 수 있다. 이후 새 추론·계속 실행·미접수 결과는 거절하며 Inngest는 grant를 갱신하지 않는다. 멤버 제거·팀 삭제는 별도로 다루어 분석 최종 저장 시 현재 멤버십과 논문/팀 범위를 재검증한다.

**운영:** 기존 로컬 연결 5개 테이블에 더해 `ResearchConversation`, `Paper`의 `sourceText/sourceDigest/analysisRequestId/analysisError`, `LocalAgentJob`의 `purpose/conversationId/conversationTurn`가 필요하다. 기존 연결 SQL 이후 `20261017-local-ai-research-chat.sql`을 검토·수동 적용한다. 운영 DB 적용은 아직 하지 않았다. 소스 `3f16685`의 [CI](https://github.com/csm-kr/haparkchopaeng-workspace/actions/runs/39033348260)에서 웹 946개·실제 PostgreSQL 13개·Chromium 8개·HTTP 계약·3 OS native/패키징을 통과했다. [DB 적용 순서](../dev/DB.md#local-ai-schema), [API](../dev/API.md), [하네스](../../phases/13-local-ai-research-chat/index.json)를 따른다.

## ADR-027 — 자료 선택이 자유로운 개인 AI 대화

**결정(2026-10-18):** 기존 연구 채팅의 자료 선택 의무와 대화별 고정 근거를 해제한다. 자료 없이 질문·후속 질문을 전송하고 `@`로 논문·발표 자료를 턴마다 합계 10개까지 선택한다. 질문별 자료와 완료된 이전 대화는 서버가 문맥에 넣으며 사용자 입력으로 원문·이력을 대신 받지 않는다. 삭제되거나 접근할 수 없는 현재 첨부 자료는 이력 조회를 막지 않는다. 새 실행은 자료 권한을 엄격히 확인한다.

연결 설정은 사이드바 계정 위에 둔다. 연결된 실제 카탈로그의 첫 사용 가능 모델을 현재 선택으로 표시하고 유효한 수동 선택을 유지한다. 카탈로그가 명시한 추론 강도만 UI에 표시하고 생성·claim에서 재검사한다. 구 앱 0.1.2는 강도를 생략해 자유 대화를 계속 실행할 수 있다. 새 CLI adapter는 기존 REST v1의 context 안에 있는 `execution.effort`만 검증해 CLI 인수로 전달한다.

자료 준비는 Inngest `research-chat/prepare`에서 수행한다. `preparing`도 동시 작업 상한·취소·세션 회수에 포함하고, 기기는 `queued`만 claim한다. 준비 후 현재 grant·팀 멤버십·version을 다시 검사한다. DB DDL은 추가하지 않으며 기존 배열 선택을 읽고 새 version 2 선택을 Json 필드에 저장한다. 배포 순서는 호환 웹 → 새 연결기다. 구 웹은 새 모델 메타데이터·version 2 선택을 읽지 못하므로 데이터 기록 후 웹 롤백에는 호환 reader를 유지해야 한다.

범위·화면은 [설계](../design/LOCAL_AI_RESEARCH_CHAT.md), 배포 검증은 [phase 19](../../phases/19-free-ai-chat-release/index.json)로 추적한다. 논문 상세의 두 관점·공통 Figure·명시적 논문 분석과 45초 실행 허가는 ADR-026을 유지한다.

## ADR-028 — 현재 앱 버전과 제공자별 AI 연결 설정

**결정(2026-10-18):** 계정 위 진입점은 `AI 연결`과 8px 상태 점으로 표시한다. 연결됨은 online 토큰, 나머지는 중립 회색이며 텍스트 상태를 접근성 이름에 제공한다. Codex·Claude Code 탭은 해당 도구의 실제 모델과 지원 effort를 보여 준다. 도구 탭 조회로 실행 제공자를 바꾸지 않고 사용자의 명시적 모델 선택만 반영한다. ADR-027의 sticky 선택·자동 대체 금지는 유지한다.

연결 앱 0.1.5는 실제 `app.getVersion()`과 `process.arch`를 선택적 `bridgeVersion`·`bridgeArchitecture`로 heartbeat에 전달한다. 서버는 기기 잠금과 유효 실행 허가 아래 기존 snapshot의 예약 `_bridge` JSON row에 저장하고 CLI 모델·사용량에서는 제외한다. 미보고 구 앱, 20초 이상 오래된 heartbeat, 허가 만료는 버전 미확인으로 표시한다. DDL은 추가하지 않는다. Claude의 `supportsEffort`와 `supportedEffortLevels`가 함께 제공된 모델에만 추론 강도를 광고한다.

웹은 게시된 OS·칩별 최신 파일과 실제 설치 버전을 semantic version으로 비교한다. 최신·더 높은 설치 버전에는 다운그레이드 링크를 제공하지 않는다. 칩 미확인은 선택을 요구하며, 최신 조회는 표시 중 60초와 포커스 복귀·사용자 요청 시 갱신한다. 업데이트는 게시 파일 다운로드 → 사용자가 설치 파일 열기 → 동일 앱 ID·프로필·프로토콜의 새 앱 실행 → 새 heartbeat 확인이다. 웹 배포나 다운로드를 앱 업데이트 완료로 간주하지 않는다. 구 서버는 추가 필드를 거부하므로 호환 웹을 먼저 배포한 뒤 앱을 게시한다.

구현·릴리스 인수는 [phase 20](../../phases/20-ai-connection-controls/index.json)로 추적한다.
