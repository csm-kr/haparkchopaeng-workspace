# Architecture Decision Records

> **정본은 루트의 `PRD.md`(§6 주요 제품 결정, §8 열린 질문)와 `README.md`다.** 이 문서는 그 결정들을 ADR 형식으로 통합한 것이며, 충돌 시 루트 문서를 따른다. 아래 결정들은 의도적이다 — 코드를 보고 "고치지" 말 것.

## 철학
4인 단일 그룹을 위한 도구. 정직한 빈 상태, 단일하고 모호하지 않은 경로, 사람 중심의 분석. 인프라는 빌리고(영상 = Cloudflare) 제품은 분석·일정·아카이브에 집중한다.

### ADR-001: 라이브 기본값은 "없음" + `live`를 앱 레벨 상태로
**결정**: 세미나 라이브는 기본적으로 꺼져 있고(빈 상태 + 명확한 시작 CTA), `live: boolean`은 화면이 아니라 앱 레벨에서 보유한다.
**이유**: 라이브는 예외이지 기본이 아니다. 사이드바 LIVE 배지, 홈 배너, 미팅 룸이 절대 어긋나면 안 된다.
**트레이드오프**: 상태를 위로 끌어올려 props 스레딩이 늘어난다. `MeetingScreen` 단독으로는 동작하지 않는다.

### ADR-002: 라이브 비디오는 Cloudflare Stream Live
**결정**: RTMP 서버/인코딩/HLS/CDN/녹화를 직접 구축하지 않고 Cloudflare Stream Live를 사용한다. 앱은 방송 생성·권한 체크·플레이어 노출만 담당한다.
**이유**: 4인 그룹에 영상 인프라 자체 구축은 과투자. 모델은 컨퍼런스(상호 그리드)가 아니라 1인 송출 + 다수 시청 방송에 가깝다.
**트레이드오프**: 외부 서비스 의존(비용·약관). 프로토타입의 상호 비디오 그리드는 1인 방송 모델로 재해석해야 한다(열린 질문: OBS 송출 여부, 녹화 보존, 종료 시 발표 자료로 아카이브할지).

### ADR-003: 업로드는 PDF 전용
**결정**: 업로드는 PDF(드래그앤드롭 또는 arXiv URL)만 받는다. PPTX/MD와 "빈 노트 / 아이디어 메모" 단축은 제거되었다.
**이유**: 수집 경로를 단일하고 모호하지 않게 유지. 제품의 본질은 논문 분석이다.
**트레이드오프**: 자유 형식 메모의 빠른 수집 경로를 포기한다.

### ADR-004: 두 관점(two-lens) 분석 + Figure 분석 공통 하단 고정
**결정**: 논문 분석은 상단 토글로 전환하는 **연구 / 재구현** 두 관점으로 구조화하고, `Figure 분석`은 두 관점 모두의 하단에 고정한다(노트는 `lens: "any"`). AI 요약/팀 노트 탭은 제거.
**이유**: 구조화된 두 관점 분석 자체가 페이지이며 경쟁하는 탭이 없어야 한다. figure는 두 읽기 모드가 공유하는 근거다.
**트레이드오프**: AI 자동 요약이라는 마케팅 포인트를 폐기하고 사람 중심 분석을 택했다.

### ADR-005: 노트는 전역이 아니라 섹션별
**결정**: "분석 추가"는 섹션마다(Figure 포함) 존재하고, 노트는 `{sectionId, lens}`로 스코프되며 작성자가 표기된다.
**이유**: 노트는 정확한 주장/섹션에 고정될 때 가장 유용하다.
**트레이드오프**: 전역 노트 한 개보다 UI와 데이터 모델이 복잡해진다.

### ADR-006: 스케줄은 절대 자동 생성하지 않음 + 명시적 편집/확정 모드
**결정**: 빈 달은 누군가 **일정 짜기**를 누르기 전까지 진짜로 비어 있다. 편집(초안) → 저장(영속화 + 순번 포인터 전진) → 확정(읽기 전용)의 명시적 라이프사이클을 가진다. 편집 중에는 달 이동이 잠긴다.
**이유**: 계획은 의도적 행위다. 가짜/유령 스케줄을 방지하고, 초안과 확정된 계획을 명확히 분리한다.
**트레이드오프**: "다음 달 자동 채움" 같은 편의를 포기한다. 매달 한 번의 명시적 클릭이 필요하다.

### ADR-007: 단일 테넌트, 초대 전용
**결정**: 4인 비공개 그룹 전용. 공개 회원가입 없음, 초대 링크로만 합류. 역할은 관리자/멤버/게스트.
**이유**: 멀티테넌트 SaaS가 아니다. 단순함이 4인 라이브러리에 맞다(같은 이유로 논문 목록 필터도 "전체" 하나만 유지).
**트레이드오프**: 확장성 포기. 다른 그룹이 쓰려면 별도 배포.

### ADR-008: 프로토타입은 빌드 없는 브라우저 Babel — 프로덕션에서 전면 교체
**결정**: 디자인 프로토타입은 React UMD + `@babel/standalone` + 전역 스코프 + `window.*` 목 데이터로 만들었다. 프로덕션은 실제 스택(예: React + TypeScript + Vite + Radix/shadcn)으로 재구축한다.
**이유**: 빌드 도구 없이 즉시 클릭 가능한 고충실도 레퍼런스를 만드는 것이 목적이었다.
**트레이드오프**: 프로토타입 코드는 출시 불가. UI는 충실히 재현하되 메커니즘은 전부 교체해야 한다(교체표는 [`../dev/ARCHITECTURE.md`](../dev/ARCHITECTURE.md)). `tweaks-panel.jsx`는 포팅 금지.

### ADR-009: 프로덕션 스택은 Next.js 15 (App Router)
**결정**: ADR-008이 Vite/React를 *예시*로 들었으나, 프로덕션 스택을 **Next.js 15 + TypeScript strict + Tailwind**로 확정한다.
**이유**: CLAUDE.md의 CRITICAL 규칙("모든 API 로직은 route handler에서만", "클라이언트에서 외부 API 직접 호출 금지")과 가장 정합적이다. 라이브 권한 체크·PDF 분석·초대 등 서버 로직을 한 스택에서 route handler/Server Action으로 처리한다.
**트레이드오프**: ADR-008의 예시와 달라진다. 프로토타입이 순수 React라 SPA(Vite)도 가능했지만, 서버 로직 일원화를 우선했다.

### ADR-010: 영속화는 Prisma + SQLite로 시작
**결정**: ORM은 Prisma, 개발 DB는 SQLite. Postgres 호환 타입만 사용해 이전 경로를 연다.
**이유**: 4인 단일 그룹에 경량·무설정 시작이 적합. 타입 안전.
**트레이드오프**: SQLite는 enum·배열 스칼라 미지원 → 문자열/JSON로 모델링하고 앱에서 검증([`../dev/DB.md`](../dev/DB.md)).

### ADR-011: 논문 분석 LLM은 "보조 추출"로만 (헤드라인 아님) — 제공자 Google Gemini
**결정**: PDF→두 관점 구조화 분석·figure 해석에 LLM을 쓰되, **사람이 검수·보강하는 보조**로 위치시킨다. AI 자동 요약을 핵심 기능으로 내세우지 않는다. **LLM 제공자는 Google Gemini**(`@google/genai` SDK) — Anthropic Claude에서 변경(`GEMINI_API_KEY`).
**이유**: PRD §3은 "AI 요약을 핵심으로 내세우기"를 폐기했다(ADR-004). 그러나 비교/ablation 표·figure 해석엔 "AI 추출"이 유효하다. 제품의 본질은 사람 중심 분석이고 LLM은 초안 생성기다. Gemini는 PDF document 입력·구조화 출력(responseSchema)·비전(figure)을 지원하고, 이미 Google OAuth를 쓰는 스택과 결이 맞는다.
**트레이드오프**: 외부 API 의존·비용. 키는 `.env`(서버 전용)에 두고 클라이언트 노출 금지([`../dev/ENV.md`](../dev/ENV.md), [`../security/SECURITY.md`](../security/SECURITY.md)). 제공자 교체 시 추출 프롬프트·스키마 재튜닝 필요.

### ADR-012: 배포는 상시 구동 Node 서버 (서버리스 아님)
**결정**: 프로덕션은 서버리스 함수가 아니라 **상시 구동 Node 서버 단일 인스턴스**로 배포한다.
**이유**: ① 분 단위 분석/녹화 후처리를 인-프로세스 워커로 돌려야 하고 ② SQLite 파일은 영속 디스크가 필요하다. 서버리스는 둘 다 깨진다. 4인 단일 그룹엔 단일 인스턴스로 충분.
**트레이드오프**: 수평 확장 포기.
**🔁 개정됨 → ADR-016**: 배포는 **Vercel 서버리스 + Supabase**로 변경. "상시 Node 서버·SQLite 파일" 전제는 폐기. 아래 결정은 ADR-016 기준으로 읽는다.

### ADR-013: 긴 작업은 백그라운드 잡으로 (요청 경로 금지)
**결정**: 논문 분석·arXiv 가져오기·녹화 후처리는 요청 경로에서 인라인 실행하지 않고 **DB `Job` 테이블 + 인-프로세스 폴링 워커**로 처리한다. API는 잡만 적재하고 즉시 응답.
**이유**: LLM(Gemini) 분석은 분 단위라 HTTP 타임아웃을 넘는다. "업로드 성공 ≠ 분석 성공"을 아키텍처로 강제해 부분 실패를 격리한다.
**트레이드오프**: 즉시 결과가 아니라 pending→ready 전이.
**🔁 개정됨 → ADR-016**: 실행 주체는 인-프로세스 폴링 워커가 아니라 **외부 durable 잡 러너**(Inngest/Trigger.dev/QStash 등)로 변경. `Job` 모델(멱등·재시도·실패 보존)과 "업로드 성공 ≠ 분석 성공" 원칙은 유지 — 실행 주체만 외부 큐.

### ADR-014: 실시간 동기화는 SSE 푸시 (폴링 아님)
**결정**: `live` 전이·@멘션은 `/api/live/stream`(SSE)로 푸시한다. 클라이언트는 폴링하지 않는다.
**이유**: `live`는 모두에게 즉시 일관돼야 한다(ADR-001). 폴링은 지연·낭비. 단일 인스턴스라 인-프로세스 이벤트 버스로 충분.
**트레이드오프**: WebSocket이 아니라 단방향 푸시면 충분.
**🔁 개정됨 → ADR-016**: 전송 메커니즘은 인-프로세스 SSE 버스가 아니라 **Supabase Realtime**(broadcast/`postgres_changes`)로 변경. "폴링 금지, 즉시 푸시" 의도(ADR-001)는 유지 — Vercel 서버리스/다중 인스턴스에서도 성립.

### ADR-015: 읽기는 RSC 서버 조회, 쓰기는 Server Action/route handler
**결정**: 조회는 서버 컴포넌트(RSC)에서 `lib/` 서버 함수로 Prisma 직접 호출, 변이는 Server Action 또는 route handler로 처리한다. 클라이언트 컴포넌트는 인터랙티브 섬(live·관점 토글·스케줄 편집·업로드·명령 팔레트)에 한정.
**이유**: CLAUDE.md "서버 로직은 서버에서만"을 RSC 시대에 맞게 구체화. 클라이언트가 DB를 직접 보지 않으면서 초기 페인트가 빠르다.
**트레이드오프**: RSC/클라이언트 경계 설계 필요. 변이 후 `revalidatePath`/`revalidateTag`로 캐시 무효화를 신경 써야 한다.

### ADR-016: 배포는 Vercel + Supabase (ADR-010·012 개정)

> **이 ADR은 ADR-010(Prisma+SQLite)과 ADR-012(상시 구동 Node 서버, 서버리스 금지)를 개정한다.** 두 결정의 전제는 ① 분 단위 분석/녹화 후처리를 인-프로세스 워커로 돌려야 하고 ② SQLite가 영속 디스크를 요구한다는 것이었다. Supabase 채택으로 ②가 사라지고, ①은 외부 durable 잡 러너로 대체 가능하므로 서버리스 배포가 성립한다.

**결정**: 프로덕션을 **Vercel(Next.js 15) + Supabase**로 배포한다. 책임 재배치:

| 관심사 | 이전(ADR-010·012~014) | 변경 후 |
|---|---|---|
| 앱 호스팅 | 상시 구동 Node 서버 단일 인스턴스 | **Vercel** (서버리스/Edge + Fluid Compute) |
| DB/ORM | Prisma + SQLite (영속 디스크) | **Prisma + Supabase Postgres** (`DATABASE_URL` = pooled, `DIRECT_URL` = 마이그레이션용) |
| 파일 스토리지 | 외부 객체 스토리지 | **Supabase Storage** (프리사인 업로드 / 서명 URL) |
| 실시간(`live`·@멘션) | 인-프로세스 이벤트 버스 + SSE | **Supabase Realtime** (broadcast / `postgres_changes`) |
| 백그라운드 잡(분석·arXiv·녹화 후처리) | 인-프로세스 폴링 워커 | **외부 durable 잡 러너**(Inngest/Trigger.dev/QStash 등) — `Job` 테이블 패턴을 큐로 이관 |

**이유**:
- **②(영속 디스크) 소멸**: Supabase Postgres는 관리형이라 SQLite 파일·영속 볼륨이 필요 없다. ADR-010이 열어둔 "Postgres 이전 경로"를 실제로 밟는 것이다.
- **실시간이 더 깔끔해짐**: `live`는 모두에게 즉시 일관돼야 한다(ADR-001). 인-프로세스 버스(단일 인스턴스 한정)를 **Supabase Realtime**으로 대체하면 서버리스/다중 리전에서도 전이 전파가 성립한다. ADR-014의 의도(폴링 금지, 푸시)는 유지된다 — 메커니즘만 교체.
- **①(분 단위 잡)의 유일한 진짜 제약 해소**: Vercel 함수는 실행 시간 제한이 있어 분 단위 LLM(Gemini) 분석을 인라인으로 못 돌린다. 그래서 분석·arXiv 가져오기·녹화 후처리는 **durable 잡 러너**(재시도·멱등·관찰성 내장)에 맡긴다. "업로드 성공 ≠ 분석 성공"(ADR-013)의 원칙과 `Job` 모델(멱등·재시도·실패 보존)은 **그대로 유지**되며, 인-프로세스 폴링 대신 외부 큐가 실행 주체가 될 뿐이다.

**트레이드오프**:
- 인프라 의존이 단일 벤더(자체 서버)에서 **Vercel + Supabase + 잡 러너**로 늘어난다(비용·약관·콜드 스타트).
- ADR-013의 "외부 큐는 과투자" 판단을 뒤집는다 — 서버리스에선 외부 큐가 **필수**다.
- 인증은 자체 서명 세션(ADR-007/SECURITY) 유지 또는 Supabase Auth로 이관 중 택1 — **단일 테넌트·초대 전용 원칙은 불변**. 본 ADR 범위 밖, 별도 결정 필요.
- Cloudflare Stream Live(ADR-002)는 영향 없음. 녹화 완료 웹훅은 Vercel route handler가 그대로 수신(HMAC 검증).
- 다중 인스턴스 환경이 되므로 인-프로세스 상태(이벤트 버스 등)에 의존하던 코드는 전부 외부 서비스(Realtime/잡 러너)로 빠져야 한다.

### ADR-017: 인증은 Google OAuth (Supabase Auth) + 초대 게이트
**결정**: 로그인은 **Supabase Auth의 Google OAuth**로 한다(미결이던 인증 수단 확정). **초대 전용은 유지**(ADR-007) — Google 로그인에 성공해도, 그 이메일이 **수락된 멤버이거나 유효한 초대**가 있을 때만 합류/세션이 발급된다. 비초대 이메일은 거부 + 로그아웃.
**이유**: 비밀번호 컬럼 없이(`Member`에 password 미추가) 안전한 외부 인증. Supabase가 OAuth·토큰·리프레시를 관리.
**트레이드오프**: Supabase 프로젝트 + Google Cloud OAuth 클라이언트 필요(키 없으면 OAuth 왕복 검증 불가 → 해당 step `blocked`). step4의 dev 이메일 로그인은 키 없을 때의 **로컬 테스트 폴백**으로만 남긴다(프로덕션 경로 아님). Supabase `auth.users` ↔ 우리 `Member`를 이메일로 매핑한다.
