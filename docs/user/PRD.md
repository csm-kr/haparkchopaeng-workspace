# PRD: 하박조팽 리서치 워크스페이스

> **정본은 루트의 `PRD.md`다.** 이 문서는 그 내용을 docs 형식에 맞춰 통합·요약한 것이며, 충돌 시 루트 문서를 따른다.

## 목표
매주 토요일 세미나를 진행하는 4인 리서치 그룹의 반복 활동(라이브 발표, 논문 분석, 자료 아카이빙, 일정·책임 관리)을 하나의 따뜻하고 마찰 없는 비공개 워크스페이스로 모은다.

- 누가, 무엇을, 언제 발표하는지 파악하고 라이브 룸에 ≤ 2클릭으로 입장.
- 논문 PDF를 팀이 협업으로 발전시키는 구조화된 두 관점(two-lens) 분석으로 전환.
- 발표 자료와 회고 논의를 검색 가능한 한 곳에 축적.
- 순번 + 출석 + 가벼운 벌금으로 소규모 그룹의 책임을 부담 없이 관리.

## 사용자
4인 멤버(하수현·박진희·조성민·팽진욱). 모두 동등한 동료이며 각자 발표자이자 청중. 한 명이 관리자 역할 가능. 역할: **관리자 / 멤버 / 게스트**. 단일 그룹 전용 — 멀티테넌트 SaaS가 아니다.

## 핵심 기능
1. **세미나 라이브** — 기본값은 라이브 없음(빈 상태 + 라이브 시작하기 CTA). 시작 시 비디오 룸이 열리고 앱 전역이 `live` 상태가 된다(사이드바 LIVE 배지, 홈 배너). 종료는 전체 세션 종료, 나가기는 본인만 퇴장. 프로덕션 영상은 **LiveKit 다자간 화상(SFU)** — 참가자가 서로 얼굴을 보는 컨퍼런스(ADR-019).
2. **논문 분석 관리** — PDF 업로드(드래그앤드롭 / arXiv URL) 후 원문 본문을 준비한다. 사용자가 PC의 AI와 모델을 선택해 분석을 시작하면 **연구**(Problem Setting · Contribution · Input/Output · Comparison · Ablation) / **재구현**(데이터 · 모델 · 학습 · 리소스) 두 관점에 저장한다. **Figure 분석**은 두 관점 공통 하단에 유지하고, 본문·캡션 기반 해석과 원문 페이지를 표시한다. 섹션별 작성자 표기 협업 노트는 그대로 둔다. (ADR-026)
3. **출판 실적(NEWS)** — 우리 팀이 발표·출판한 실적을 카드 그리드로 진열하는 **내부 쇼케이스**. 제목·학회명·저자·연/월·티저 이미지·외부 링크를 담고 전용 티저 상세 페이지로 보여준다. 모든 팀원이 추가·편집·삭제. 분석 대상인 '논문'과 별개의 *우리 실적* 모음(팀 내부 전용 — ADR-022).
4. **자료 관리(발표 자료)** — 발표 자료 아카이브 + @멘션·반응이 있는 스레드형 회고 댓글.
5. **스케쥴 관리** — 매주 토요일, 4인 순번제. 월 단위 계획, **절대 자동 채움하지 않음**. 편집 → 저장(순번 포인터 전진) → 확정 라이프사이클. 편집 가능한 벌금과 연도별 멤버 장부.
6. **팀 관리** — 이메일 초대 + 역할, 초대 링크, 대기 중인 초대(재전송/취소), 역할 변경/내보내기.
7. **설정** — 프로필, 알림, 테마(라이트/다크), 법적 링크.
8. **AI 채팅** — 별도 작업 공간 메뉴 `/ai-chat`에서 자료 없이 자유롭게 대화하고, 필요할 때 `@`로 같은 팀 논문·발표 자료를 질문마다 선택해 비교·질문·실험 설계 보조를 받는다. 대화는 작성자 개인 이력으로 저장하며 두 관점 분석이나 팀 노트에 자동 반영하지 않는다. (ADR-026)

## MVP 제외 사항
- 다중 조직 / 공개 회원가입 — 초대 링크 전용 비공개 그룹.
- 완전한 LMS, 인용 관리자, 참고문헌 그래프.
- 업로드만으로 실행되는 무인 AI 요약·외부 관련 논문 자동 검색. 사용자가 시작하는 로컬 모델 분석과 선택 논문을 근거로 한 연구 채팅은 포함한다(ADR-026).
- PDF 외 업로드 형식 — PPTX/MD와 "빈 노트 / 아이디어 메모" 단축은 제거됨.
- 비디오 인프라 직접 구축 — 영상·음성·화면공유 트랙 라우팅은 **LiveKit(SFU)**에 위임. 앱은 입장 토큰 발급·권한 체크·룸 정리만 담당(ADR-019).

## 내 PC의 AI 연결 (ADR-025)

멤버는 이 웹에 접속한 PC의 Codex·Claude Code로 논문 질문·연구 보조를 사용할 수 있다. 연결앱을 처음 한 번 설치한 뒤 웹의 AI 연결 버튼으로 실행한다. 처음에는 웹의 6자리 번호를 앱에 입력하고, 같은 로그인·팀·PC의 재실행은 다시 입력하지 않는다. 로그아웃·쿠키/세션 유실·팀 변경 시 다시 확인한다.

모델은 실제 CLI 목록을 사용한다. 논문 분석은 사용자가 모델을 선택한 뒤 시작한다. AI 채팅은 연결된 CLI의 실제 첫 모델을 현재 선택으로 표시하고 유효한 수동 선택을 우선 유지한다. 모델 목록이 없으면 전송할 수 없다. 사이드바의 `AI 연결`은 연결됨을 초록색 점, 다른 상태를 회색 점으로 표시하며 상태 설명을 함께 제공한다. 클릭하면 Codex·Claude Code를 구분해 실제 모델과 지원 effort를 선택한다. 도구 탭을 보는 것만으로 실행 모델을 바꾸지 않는다. 작은 사용량 링은 구독 비율과 관측 시각을 상세 표시하며 정확한 잔여 토큰을 주장하지 않는다. 연결앱은 다크 테마, 자동 시작·펫은 선택 사항이다. 설치/연결/오프라인/로그인 만료/사용량 미확인 상태를 구분한다. 연결 UX는 ADR-025를 유지하며, 논문 분석 실행은 아래 ADR-026으로 개정한다. [상세 UX](../design/LOCAL_AGENT_CONNECTION.md), [구현·검증](../dev/LOCAL_AGENT.md).

실행 중인 앱이 보고한 설치 버전과 OS·칩에 맞게 게시된 최신 파일을 비교해 업데이트를 안내한다. 버전을 제공하지 않는 구 앱은 설치 버전 미확인으로 표시한다. 다운로드한 설치 파일을 열어 기존 앱을 교체하고 다시 연결해야 하며, 다운로드만으로 최신 상태를 표시하지 않는다. 앱의 정적 ID·프로토콜·프로필 경로는 업데이트 전후 동일하다. 0.1.5부터 버전·칩 정보와 Claude의 실제 effort 목록을 전달한다. DB DDL 변경은 없다(ADR-028).

## 로컬 모델 논문 분석·개인 연구 채팅 (ADR-026)

업로드는 PDF 저장과 본문 준비까지만 진행하며 AI 호출은 0회다. 본문이 준비되면 `awaiting_ai`로 기다린다. 사용자가 연결한 PC와 실제 모델을 선택하고 분석을 시작해야 구독 한도를 사용하는 로컬 추론을 실행한다. 연결되지 않았거나 모델을 선택하지 않은 상태에서는 분석을 시작하지 않는다. 사용 한도·로그인·네트워크 문제를 다른 모델이나 유료 원격 API로 자동 전환하지 않는다. 원문을 읽지 못한 스캔 PDF도 원본은 보존하고 준비 실패를 안내한다.

두 관점과 공통 Figure 하단은 유지한다. 논문 상세에 별도 AI 탭이나 사이드패널을 만들지 않는다. 현재 연결기는 텍스트만 읽으므로 Figure 해석은 본문·캡션에서 추론한 내용임을 표시하고, 외부 코드 저장소를 실제로 방문·검증했다고 표시하지 않는다. 분석의 JSON 형식과 페이지·원문 인용을 검사한 뒤 최신 분석 요청의 결과만 두 관점에 저장한다. 사람의 섹션 노트는 검수·보강 경로다.

`/ai-chat`은 자료 없이 대화를 시작할 수 있다. 입력창의 `@`로 같은 팀 논문·발표 자료를 합계 10개까지 질문마다 추가·제거하며, 지난 질문의 자료 스냅샷은 보존한다. 본문이 준비되지 않은 자료는 Inngest에서 준비한 뒤 현재 실행 권한을 다시 검사해 큐에 넣는다. 사이드바의 연결 설정에서 현재 실제 모델과 지원 추론 강도를 확인·변경하고 부분 답변·중지·재시도·연결 끊김을 구분한다. 개인 이력은 새 로그인에서도 읽을 수 있지만, 새 질문과 현재 작업 취소는 해당 웹 세션의 권한을 따른다. 목록은 최근 100개, 대화 화면은 최근 50턴을 제공하고 이전 이력 생략 여부를 알린다. 모델에는 완료된 최근 8턴과 원문을 합해 최대 20만 자를 전달하며 생략이 있으면 표시한다.

45초 허가가 유효할 때 서버가 이미 `completed`로 접수한 결과는 로그아웃 후에도 검증·렌더·저장을 마칠 수 있다. 로그아웃 뒤 새 추론·계속 실행·미접수 결과 전송은 허용하지 않는다. 팀 멤버십은 최종 분석 저장 시 다시 확인한다.

새 기능의 전체 품질 검증과 운영 반영 검토는 진행 중이다. 운영 DB에는 새 스키마를 아직 적용하지 않았으며 [DB 수동 적용 순서](../dev/DB.md#local-ai-schema)를 거친다. 결정·구현 계약은 [ADR-026](../agent/ADR.md#adr-026), [API](../dev/API.md)를 따른다.

## 2026-10-18 개정: 논문 기반 대화형 PT (ADR-032)

발표 자료의 **세미나 자료 만들기**는 `/presentations/new`에서 논문을 고르고 `/presentations/create/:taskId`에서 이어간다. 에이전트는 질문에 앞서 원문·분석·Figure 목록을 읽고 근거가 다른 발표 방향 2~3개를 제안한다. 사용자가 방향을 고르면 추천 답이 있는 질문을 한 번에 하나씩 이어가며 청중·시간·메시지·깊이·토론 목적을 브리프에 반영한다. 사용자가 목차 만들기와 PT 만들기를 각각 실행한다. Figure·원문 페이지·표·설명 도식과 페이지 근거·발표자 메모를 담은 슬라이드를 보여주고 자유 대화와 직접 편집으로 수정한다.

등록 전 대화·기획·덱·출력 파일은 작성자 개인 작업이다. **HTML/PDF 준비**는 검토한 현재 내용을 고정해 내구성 잡으로 출력한다. 16:9의 자체 포함 HTML과 한글 폰트가 포함된 PDF를 만들며, 화면 경계·줄바꿈·PDF 장수·실제 래스터화를 검사한다. 넘침은 한국어 오류로 고치도록 안내한다. 파일은 현재 원문·덱과 일치할 때만 내려받는다. 검토한 세미나를 등록하면 구조화 슬라이드와 준비된 HTML/PDF를 원문에 연결한다. 생성 PDF는 기존 라이브 발표 자료 공유 경로에서 선택할 수 있다. 등록 후 같은 덱의 파일을 준비해도 해당 자료에 연결된다.

전용 PT의 팀 등록은 현재 검토본의 HTML/PDF 출력 검수가 끝난 뒤에만 허용한다. 덱 내용과 두 첨부가 실제로 저장되었는지 다시 읽어 확인한다. 이전 로그인으로 되돌아와도 **연결 후 이어가기**로 원문 근거·대화를 보존하며, 원문이 바뀌면 최신 자료로 명시적으로 다시 시작한다. 덱을 다듬는 대화에는 수정 내용과 도식 선택의 이유도 설명한다.

참고한 `csm-kr/pt-maker-skill`의 한 질문씩 기획·목차 합의·원문 시각자료·렌더 검수 흐름을 적용했다. 첫 버전 출력은 고정된 안전한 HTML/SVG와 PDF 공통 좌표 렌더러이며 Reveal.js·PPTX·동영상은 포함하지 않는다. 원문의 주장과 실험 수치의 의미는 사용자가 근거를 보며 검토한다. 자동 검사는 내용의 학술적 타당성 점수가 아니다. 일정 편성·라이브 시작은 별도 사용자 행동을 유지한다.

## 2026-10-18 개정: 논문·세미나 목표 작업 (ADR-031)

사용자가 추가로 요구한 완성 경험은 **논문을 먼저 읽기 → 발표 방향 2~3개 제안 → 한 질문씩 Grilling → 대화하며 목차·시각자료·PT 제작**이다. 발표 자료 안의 전용 제작 공간에서 진행한다. 이 후속 경험은 [설계 논의](../design/PAPER_PT_WORKSPACE.md) 중이며, 아래 현재 작업 기반·텍스트 초안 검증과 구현 상태를 구분한다.

`AGENT_TASKS_ENABLED=1`이면 AI 채팅에서 논문 한 편으로 **노트 초안 만들기**와 **세미나 자료 만들기**를 실행한다. 발표 자료 목록에도 **세미나 자료 만들기** 진입점을 둔다. 자유 채팅·모델 설정·두 관점 논문 상세는 기존 흐름을 따른다.

원문을 읽고 인용을 검증한 초안은 작성자 개인에게만 보인다. 사용자는 노트 제목·본문 또는 세미나 제목·시간·소개·핵심 내용·슬라이드를 수정한 뒤 저장 버튼으로 정확한 내용을 등록한다. 실제 객체를 별도 조회해 검토 내용·팀·작성자가 일치해야 등록 완료다. 중지·조건 변경·재개와 새로고침 후 복원을 지원한다.

세미나는 원문 논문과 연결된 앱 내 3~16장 텍스트 슬라이드다. 발표 시간은 5~120분, 기본 요청은 30분이다. 일정 편성과 라이브 시작은 기존 스케줄·라이브에서 진행한다. PDF/PPTX 파일 생성은 이번 완료 기준에 포함하지 않는다. 연구 해석과 발표 품질은 사람이 검토한다.

일반 채팅은 계속 공유 분석·노트를 자동 변경하지 않는다. 이번 개정은 **명시적으로 검토한 작업 결과 저장**을 추가한다. 이력 조회와 실행 권한을 분리하며 새 추론·읽기 행동·공유 저장에는 현재 웹의 45초 grant가 필요하다.
