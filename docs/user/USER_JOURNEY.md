# 유저 저니 (User Journey)

> 정본 제품 정의는 같은 폴더의 [`PRD.md`](./PRD.md), 화면 단위 흐름은 [`../design/SCREEN_FLOW.md`](../design/SCREEN_FLOW.md), 단계별 조작 흐름은 [`./USER_FLOW.md`](./USER_FLOW.md)다. 이 문서는 **사람의 시점에서 시간 축을 따라가는 서사**를 담는다 — 무엇을 클릭하는지(=USER_FLOW)가 아니라 *언제·왜·어떤 기분으로* 제품을 쓰는지를 정리한다.

## 페르소나

4인 모두 동등한 동료이자 각자 발표자이며 청중이다. 역할(관리자/멤버/게스트)은 권한일 뿐 위계가 아니다.

| 페르소나 | 역할 | 주 관심사 | 제품에서 자주 하는 일 |
|---|---|---|---|
| **하수현 (ha)** | 관리자 / PI | 팀 운영, 일정·책임 관리, 멤버 초대 | 스케줄 편성, 팀 관리, 벌금 장부 확인, 발표 |
| **박진희 (bak)** | 멤버 / Vision | 논문 깊게 읽기, 재구현 | 논문 분석 작성, 섹션 노트, 발표 |
| **조성민 (jo)** | 멤버 / RAG·평가 | 발표 준비, 회고 | 논문 업로드, 발표 자료 업로드, 라이브 발표 |
| **팽진욱 (paeng)** | 멤버 / Robotics | 따라잡기(청중), 가끔 발표 | 라이브 시청, 댓글·반응, 자료 미리보기 |

> 페르소나 기준 데이터는 `src/data.js`의 `window.TEAM` / `window.ACCESS`에 있다.

## 핵심 저니: 주간 세미나 사이클 (월~토)

제품의 심장은 **매주 토요일 10:00 세미나**다. 한 주의 리듬을 따라간다.

```
월   계획 확인 ──→ 화   논문 업로드·분석 ──→ 수~금   협업 노트·자료 준비
                                                      │
토 10:00  라이브 입장 ─→ 발표 ─→ 종료 ─→  토~일  회고 댓글 · 다음 발표자 확인
```

### 1. 월요일 — "이번 주 누구 차례지?"
- **진입점:** 홈(대시보드). 라이브가 없으므로 배너는 없고, 다음 세미나 정보와 퀵 카드가 보인다.
- 스케줄에서 **이번 주** 알약이 붙은 토요일 행을 확인한다. 발표자·주제가 한눈에 보인다.
- *감정 목표:* "내가 발표자인지 아닌지, 무엇을 준비해야 하는지 5초 안에 안다."

### 2. 화요일 — 발표자가 논문을 올린다 (조성민)
- 홈 또는 논문 목록에서 **＋ 업로드** → PDF 드래그앤드롭(또는 arXiv URL).
- 업로드 → 분석 처리 → 논문 상세로 이동. **연구 분석** 관점이 기본으로 열린다.
- 발표자는 Problem/Contribution/IO/Comparison/Ablation을 훑고, 부족한 부분에 **섹션 노트**를 단다.
- *감정 목표:* "PDF 한 장 떨군 게 구조화된 분석 페이지가 됐다. 빈 칸을 채우면 된다."

### 3. 수~금요일 — 팀이 함께 읽는다 (박진희·하수현)
- 논문 상세에서 **재구현 분석** 관점으로 토글 → 데이터·모델·학습·리소스를 검토.
- 특정 섹션/Figure에 **작성자 표기 노트**를 추가한다. Figure 노트는 두 관점 공통으로 남는다.
- 발표 자료(슬라이드)가 올라오면 자료 상세에서 **@멘션 댓글**로 피드백을 주고받는다.
- *감정 목표:* "각자 이해한 걸 정확한 위치(섹션)에 쌓는다. 흩어지지 않는다."

### 4. 토요일 10:00 — 라이브 (전원)
- 발표자가 **세미나 라이브 → 라이브 시작하기**. 그 순간 앱 전역이 `live`가 된다: 사이드바 LIVE 배지, 홈 배너가 모두에게 켜진다.
- 청중은 사이드바 LIVE 배지/홈 배너에서 **클릭 한 번으로 룸 입장**(목표: "토요일이다"→"룸 안" ≤ 2클릭).
- 발표가 끝나면 발표자가 **종료** → 모두의 배지/배너가 사라진다. 개인 사정으로 먼저 빠지면 **나가기**(라이브는 유지).
- *감정 목표:* "들어가고 나오는 게 군더더기 없다. 라이브 상태가 어디서든 일관된다."

### 5. 토~일요일 — 회고와 다음 준비 (전원)
- 발표 자료 상세에서 **회고 댓글**(반응·@멘션)을 남긴다. 세미나의 토론이 자료에 영구히 붙는다.
- 불참자가 있었다면 스케줄의 **연도별 장부**에 출석/벌금이 반영된다.
- 다음 주 발표자는 스케줄에서 자기 차례를 확인하고 사이클이 반복된다.

## 보조 저니

### A. 온보딩 (초대받은 신규 멤버)
초대 링크 클릭 → 로그인/가입 → 온보딩 → 워크스페이스 진입("환영합니다! 🎉"). 공개 가입은 없다 — **초대 전용**(→ [`../agent/ADR.md`](../agent/ADR.md) ADR-007).

### B. 월간 일정 편성 (관리자, 매달 1회)
빈 달은 **진짜로 비어 있다.** 누군가 **일정 짜기**를 눌러야 초안이 생긴다. 편집(확정 체크·시간·발표자·주제) → 저장(순번 포인터 전진) → 확정(읽기 전용). 자동 채움은 없다(→ ADR-006).

### C. 책임 관리 (관리자, 분기/연 단위)
벌금 금액(발표자 불참 / 일반 불참)을 설정하고, 연도별 멤버 장부에서 참여·불참·누적 벌금·납부·미납을 확인한다. 장부는 가벼운 사회적 장치이지 결제 시스템이 아니다.

## 마찰 지점 & 회복 (UX)

좋은 저니는 "잘 될 때"가 아니라 "어긋날 때" 갈린다. 각 단계의 마찰과 회복 설계.

| 단계 | 마찰(감정 저점) | 회복 설계 |
|---|---|---|
| 논문 업로드 | "PDF 떨궜는데 분석이 안 끝났네" | 분석 실패와 업로드 분리 — 논문은 남고 [다시 분석]. 원문 PDF는 항상 열림 |
| arXiv 가져오기 | "주소를 잘못 붙였나" | 인라인 에러로 즉시 교정, 모달 유지(다시 입력) |
| 토요일 라이브 입장 | "두 명이 동시에 시작 눌렀다" | 두 번째는 충돌이 아니라 **입장**으로 안내 — 사고가 아니라 합류 |
| 라이브 중 | "와이파이가 끊겼다" | "다시 연결 중" 배너 + 자동 재연결. 발표 맥락 유지 |
| 라이브 종료 | "실수로 전체를 끝낼라" | 종료=확인 다이얼로그, 나가기=즉시. 둘을 분명히 구분 |
| 스케줄 편집 | "초안 짜다 실수로 취소" | 변경분 있으면 취소 확인. 저장 실패 시 입력 보존 |
| 발표자 휴가 | "이번 주 발표자가 빠졌다" | 휴가 상태 표시 + 순번 건너뛰기/수동 재배정 |
| 알림 | "라이브 시작된 줄 몰랐다" | 라이브 시작·@멘션 알림 채널 결정 필요(→ [`../agent/ISSUES.md`](../agent/ISSUES.md) I-5) |

## 첫인상 (온보딩)

초대 링크 → 로그인/가입 → 온보딩 → "환영합니다! 워크스페이스가 준비됐어요 🎉". 신규 워크스페이스는 **정직한 빈 상태**로 맞이한다 — 가짜 데이터 대신 "첫 논문을 올려볼까요?" 같은 첫 행동을 권한다. 따뜻한 톤이 첫 화면부터 일관되어야 한다("리서치는 혼자 하는 게 아니야").

## 접근성·디바이스 맥락

- **모바일:** "토요일 아침 폰으로 라이브 입장", "이동 중 스케줄 확인", "자료에 댓글" 은 모바일에서도 매끄러워야 한다(→ [`../design/DESIGN_GUIDE.md`](../design/DESIGN_GUIDE.md) §반응형).
- **모션 민감:** LIVE 깜빡임에 의존하지 않고 정적 배지로도 라이브를 인지할 수 있어야 한다(`prefers-reduced-motion`).
