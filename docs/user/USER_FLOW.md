# 유저 플로우 (User Flow)

> 시간 축 서사는 [`./USER_JOURNEY.md`](./USER_JOURNEY.md), 화면 전환·상태 도식은 [`../design/SCREEN_FLOW.md`](../design/SCREEN_FLOW.md), 시스템 시퀀스는 [`../dev/SEQUENCE_DIAGRAM.md`](../dev/SEQUENCE_DIAGRAM.md)다. 이 문서는 **사용자가 하나의 목표를 완료하기까지 밟는 단계와 분기**를 다룬다(클릭 단위). 프로토타입 근거: 루트 `UX_FLOWS.md`, `src/`.

표기: `[버튼]` 사용자 액션 · `→` 결과 전이 · `◇` 분기 · `※` 규칙.

## F1. 라이브 세미나 입장·진행

```
임의 화면
  └─[사이드바: 세미나 라이브] → meeting 화면

◇ live === false (기본)
   빈 상태: "진행 중인 라이브가 없습니다"
   ├─[라이브 시작하기] → onSetLive(true) → 룸 + 전역 live 켜짐(배지·배너)
   └─[스케줄 보기]     → schedule 화면

◇ live === true
   룸: 발표자 스포트라이트 · 참가자 타일 · 컨트롤(마이크/카메라/공유)
   ├─[종료]   ◇ 확인 "모두의 세션이 끝나요. 종료할까요?"
   │           → 세션 전체 종료 · onSetLive(false) · 홈 복귀 (모두의 배지·배너 제거)
   └─[나가기] → 본인만 퇴장 (다른 사람에겐 live 유지)

◇ 동시 시작 충돌
   [라이브 시작하기] → 이미 active(409) → "이미 OOO님이 시작했어요. 입장할까요?" → 합류
```

- **입장 최단 경로(≤2클릭):** 홈 LIVE 배너 클릭 → 룸. 또는 사이드바 LIVE 배지 클릭 → 룸.
- ※ **종료는 파괴적**(전체 종료) → 확인 필수. **나가기는 본인만** → 확인 없음. 둘을 시각적으로 분명히 구분.
- ※ `live`는 앱 레벨 상태다. 배지·배너·룸이 항상 일치한다(→ [`../agent/ADR.md`](../agent/ADR.md) ADR-001).
- ※ 프로덕션: 시작 = Cloudflare Live Input 생성, 발표자에게 RTMPS/SRT 송출 정보 노출; 시청자는 권한 확인 후 HLS 재생(→ ADR-002).

## F2. 논문 업로드 → 분석

```
[＋ 업로드] (홈/논문 목록) → UploadModal

idle 단계
  ├─ PDF 드래그앤드롭            ┐
  └─ arXiv URL 입력 → [가져오기] ┘→ uploading(진행률) → analyzing("읽는 중") → done
                                     → 논문 상세(paper)로 이동, 연구 분석 기본 열림
  ◇ 비-PDF/형식 오류 → "PDF만 올릴 수 있어요" (모달 유지)
  ◇ arXiv URL 오류  → "arXiv 주소를 확인해주세요" (인라인)
  ◇ 분석 실패        → 논문은 생성됨 → paper로 이동, "분석 못 끝냄 + 다시 분석"
```

- ※ 업로드는 **PDF 전용**. PPTX/MD·빈 노트/아이디어 메모 단축은 제거됨(→ ADR-003).
- ※ **업로드 성공 ≠ 분석 성공.** 분석이 실패해도 논문·원문 PDF는 살아 있고 분석만 재시도한다.

## F3. 논문 분석 읽기·노트 작성

```
논문 목록 → [.paper-row 클릭] → paper 상세

상단바 액션 = [⬇ 원문 PDF] 단 하나 (탭/사이드패널 없음)

관점 토글(상단 고정):  ( 🔬 연구 분석 | 🛠️ 재구현 분석 )
  연구:   Problem · Contribution · Input/Output · Comparison · Ablation
  재구현: 데이터 · 모델 · 학습 · 리소스
  공통:   Figure 분석 (항상 하단 고정, "PDF p.N 추출" 배지)

각 섹션에서 노트 추가:
  [+ 이 섹션에 분석 추가] → 인라인 폼(제목 + 본문)
    ├─[취소] → 폼 닫힘
    └─[추가] ◇ 제목·본문 비었으면 토스트 경고
              → 작성자 표기 노트 카드 추가 (CURRENT_USER)
```

- ※ 노트는 `{sectionId, lens}`로 스코프. **Figure 노트만 관점 공통**(`lens:"any"`)(→ ADR-005).

## F4. 스케줄: 빈 달 → 편집 → 확정

```
schedule 화면, 해당 월 보드

◇ weeks == null (계획 없음)
   빈 상태: "이 달은 아직 일정이 없습니다"
   └─[+ 일정 짜기] → draftMonth() 초안 생성 → 편집 모드

◇ editing (초안)
   행마다: [✓확정] [시간] [발표자▾] [주제____]
   고정 바: "확정 N/M …"  [취소] [저장]
   ├─[취소] → 초안 폐기
   └─[저장] → 월 영속화 + 순번 포인터 전진 → 확정 모드
   ※ 편집 중 달 이동 잠김 (토스트 경고)

◇ saved & !editing (확정·읽기전용)
   행마다: 주차·날짜·시간·발표자 · [상태 알약] · [액션]
     done    → 완료    · [자료](presId 있으면)
     current → ●이번 주 · [입장] → meeting
     upcoming→ 발표예정 · [미리보기]
   └─[⚙ 수정] → 초안 복사 → 편집 모드
```

- ※ 월 이동 시 **자동 생성하지 않는다.** 빈 달은 비어 있는 채로 유지(→ ADR-006).

## F5. 발표 자료 회고

```
발표 자료 목록 → [자료 클릭] → presentation 상세
  자료 뷰어 + 댓글 스레드
  댓글 작성: textarea (Cmd/Ctrl+Enter 전송) · @멘션 · 반응
```

## F6. 팀 관리 (관리자)

```
team 화면
  초대:   [이메일] [역할▾ 관리자/멤버/게스트] [초대 보내기] · [🔗 링크 복사]
  멤버 행: 아바타·이름·이메일·[역할 배지]·[⋯]
            └ ⋯: 역할 변경 / 내보내기 ◇ 확인 "OOO님을 내보낼까요?"(위험)
  대기 초대(점선): [재전송] [취소(되돌리기 토스트)]
```

## 전역 인터랙션

- **내비게이션:** 어디서나 `onNavigate(screen, params)`.
- **토스트:** `onToast(msg)`로 가벼운 확인(성공). 실패는 다시 시도/되돌리기 액션 동반 가능.
- **명령 팔레트:** `Cmd/Ctrl+K`로 열기, `Esc`로 닫기.
- **검색:** 논문/발표/아이디어/코멘트 통합 결과. 결과 없음 상태 명시.

## 전역 상태·피드백 규칙 (UX)

모든 플로우에 일관 적용 — 상세 패턴은 [`../design/DESIGN_GUIDE.md`](../design/DESIGN_GUIDE.md) §UX 패턴.

- **상태 3종:** 데이터 화면은 로딩(스켈레톤)·빈·에러(다시 시도)를 모두 제공.
- **낙관적 UI:** 노트·댓글·반응은 즉시 반영 → 실패 시 롤백 + 토스트.
- **파괴적 액션 확인:** 종료·내보내기·삭제·편집 취소는 확인 또는 되돌리기.
- **검증은 인라인:** 빈 노트/댓글, 잘못된 URL은 토스트가 아니라 입력 옆 인라인.
- **권한 안내:** 권한 없는 액션은 "관리자만 할 수 있어요" 식으로 부드럽게(숨기거나 비활성+툴팁).
