# 로컬 AI 연구 보조와 AI 채팅

상태: UI 우선 설계 · 2026-10-17. 이 문서는 새 사용자 요청에 대한 구현 기준이다. 문서 작성 시점에는 채팅·PDF 본문 캐시·로컬 구조화 분석이 구현되었다고 가정하지 않는다.

## 목표와 기존 화면의 경계

기존 Gemini 요약·분석 실행을 연결한 PC의 Codex·Claude Code로 바꾸고, 워크스페이스에 **AI 채팅**을 추가한다. 논문을 한 번 질문하고 끝내는 프로필 폼에서 벗어나, 근거 논문과 이전 질문이 이어지는 개인 연구 대화를 제공한다.

- 주요 메뉴는 `홈 → 논문 → AI 채팅 → NEWS → 발표 자료 → 스케쥴 → 팀 관리 → 모두의 세미나` 순서다. 경로는 `/ai-chat`, 저장한 대화는 `/ai-chat/:id`다.
- 논문 상세의 연구/재구현 관점 토글, Figure, 작성자 노트는 기존 위치를 유지한다. 논문 상세에 채팅 탭이나 사이드패널을 추가하지 않는다.
- 최초 범위는 **활성 팀 논문 1~3편을 선택한 대화**다. 논문 없는 일반 질문은 후속 범위다.
- 대화는 **활성 팀 + 작성자 개인 소유**다. 같은 팀이라는 이유로 다른 사람의 대화가 보이지 않는다. 팀 공유·공개 링크는 최초 범위에 없다.
- 연결·실제 CLI 카탈로그·사용량은 기존 AI 연결을 재사용한다. 앱 설치, 웹의 6자리 번호, 앱의 빈 번호 입력, 구독 로그인·실행 권한 경계를 그대로 지킨다.
- 기존 문서의 Gemini 유지/자동 분석 전제는 이번 요청에서 바뀌는 대상이다. 실제 구현을 확정한 뒤 담당자가 PRD·사용자 흐름·ADR을 함께 개정한다. 이 설계 작업에서 그 문서를 미리 수정하지 않는다.

## 화면 구조

```text
기존 앱 메뉴 │ AI 채팅 / 대화 제목                       [기존 AI 연결]
             ├ 대화 목록 ─────────┬───────────────────────────────────
             │ [+ 새 대화]       │ 새 대화 또는 저장한 메시지
             │ 검색              │ ‘이 팀에서 나만 보는 대화’
             │ 오늘 / 이전       │
             │ 대화 제목         │ [논문 요약] [논문 비교]
             │ 대화 제목         │ [재현 계획] [세미나 질문]
             │                   │
             │                   │ 선택한 근거 [논문 A ×] [논문 B ×]
             │                   │ 질문을 입력하세요…
             │                   │ [모델을 선택하세요 ▾] (작은 링) [보내기]
```

이는 내용 배치 설명이며 실제 데이터가 있는 화면으로 제시하는 시안이 아니다. 메뉴 아이콘은 기존 lucide 계열 `MessagesSquare`를 사용한다. 새 메뉴에 강조 배지·가짜 대화 수를 넣지 않는다.

본문 폭이 충분할 때만 232px의 대화 목록을 본문 왼쪽에 둔다. 목록은 이 화면 안에만 존재한다. 본문 가용폭 960px 미만에서는 제목 옆 **대화 목록** 버튼으로 같은 목록을 대화상자에 연다. 모바일에서도 기존 앱 메뉴의 64px 접힘을 유지하며 목록과 메시지를 나란히 압축하지 않는다.

상단바는 기존 `Topbar`를 사용한다. 대화 제목은 한 줄로 줄이고 전체 제목은 접근 가능한 이름으로 제공한다. 본문은 `min-w-0 min-h-0`의 단일 메시지 스크롤 영역과 하단 입력 영역으로 구성한다. 입력창·화면 키보드가 최근 메시지를 덮지 않도록 `dvh`와 safe-area를 고려한다. 문서 전체와 메시지 영역이 동시에 세로 스크롤되지 않게 한다.

## 처음 방문해서 첫 답변까지

1. **AI 채팅**을 누르면 대화 목록과 빈 새 대화가 보인다. 연결 확인이 끝나기 전에는 ‘연결 확인 중’, 목록 조회 중에는 목록 스켈레톤을 보인다. 아직 대화가 없어도 오류로 표시하지 않는다.
2. **팀 논문 선택**에서 제목을 검색하고 1~3편을 선택한다. 목록에는 제목·연도와 ‘본문 준비 중/사용 가능/본문 없음’ 상태를 함께 보인다. 선택한 논문은 입력창 위 칩이 된다. 선택 팝오버는 제목이 길어도 가로로 넘치지 않으며 키보드로 선택·제거할 수 있다.
3. 네 가지 시작 문장 중 하나를 고르거나 직접 질문한다. 시작 문장은 **입력 초안만 채우고**, 자동 전송하거나 모델을 고르지 않는다. 논문이 부족하면 필요한 선택 수를 바로 설명한다.
4. 연결하지 않았다면 입력창 아래 ‘내 PC의 AI를 연결하면 보낼 수 있어요’와 **AI 연결**을 보인다. 이 버튼은 기존 전역 연결 모달을 연다. 초안·논문 선택을 그대로 둔다. 설치 앱·정상 연결과 CLI 로그인 필요는 서로 다른 상태다.
5. 연결되면 실제 카탈로그의 **모델을 직접 선택**한다. 처음에는 ‘모델을 선택하세요’이며 Codex/Claude·첫 모델·과거 답변 모델을 자동으로 선택하지 않는다. 모델 없는 카탈로그를 샘플 모델로 채우지 않는다.
6. 연결·모델·논문 본문·질문이 준비되면 **보내기**가 활성화된다. 선택한 논문의 자료가 로컬 CLI와 그 공급자에 전달된다는 짧은 안내를 입력창에 둔다. ‘로컬’이 오프라인 추론이나 공급자에 자료를 보내지 않는다는 뜻으로 설명하지 않는다.
7. 첫 전송에서 대화를 생성하고 이어서 첫 턴·실행 작업을 요청한다. URL을 저장한 대화 주소로 교체한다. 대화 생성 뒤 턴 요청이 실패하면 같은 대화와 requestId로 재시도해 빈 대화가 중복 생성되지 않게 한다. 전송 전 빈 대화를 목록에 쌓지 않는다. 제목은 첫 질문의 일부로 만든다. 제목 생성용 별도 AI 호출을 하지 않는다.
8. 답변이 진행되는 동안에도 대화 목록을 열고 다른 대화로 이동할 수 있다. 작업은 서버의 상태로 추적하고 돌아왔을 때 같은 턴에 이어 표시한다. 화면 이동을 완료·취소로 오해하지 않는다.

| 시작 문장 | 요구 논문 | 입력창에 채우는 내용 |
| --- | --- | --- |
| 논문 요약 | 1~3편 | 선택한 논문별 문제·핵심 기여·방법·한계를 원문 근거와 함께 정리해 주세요. |
| 논문 비교 | 2~3편 | 문제 설정·방법·실험 조건·결과·한계를 비교하고, 직접 비교할 수 없는 조건을 구분해 주세요. |
| 재현 계획 | 1~3편 | 원문으로 확인되는 데이터·모델·학습 조건을 정리하고, 재현에 빠진 정보와 확인 순서를 제안해 주세요. |
| 세미나 질문 | 1~3편 | 이해 확인·가정 검토·실험 한계·후속 연구로 나누어 토론 질문을 제안해 주세요. |

논문 비교를 1편에서 누르면 문장을 잃지 않고 ‘비교할 논문을 한 편 더 선택해 주세요’와 선택창을 제공한다. 논문이 없으면 ‘논문을 먼저 올려 주세요’와 `/library` 링크를 보인다. 이때 연결기 설치로 유도하지 않는다.

## 대화가 이어지는 방식

**논문 맥락.** 최초 대화 생성 시 선택한 논문 1~3편을 그 대화의 근거로 고정한다. 각 사용자 메시지에는 당시 제공한 본문 출처/버전을 식별할 수 있어야 한다. 논문을 바꾸려면 **다른 논문으로 새 대화**를 시작하며, 변경으로 지난 답변의 근거를 덮어쓰지 않는다. 턴별 논문 교체는 별도 계약을 갖춘 후속 범위다. 다른 팀 논문은 검색 결과·URL 직접 입력·과거 대화 복구 어느 경로로도 섞이지 않는다.

**앞선 대화.** 실행 시 서버가 이 대화의 허용된 최근 턴과 논문 본문을 제한 내에서 조립한다. 이전 답변의 요약을 자동 사실로 취급하지 않는다. 길이 한도를 넘으면 포함한 범위와 제외한 과거 턴을 UI에 알린다. 전체 대화를 읽은 것처럼 표시하거나 뒤에서 유료 요약 작업을 추가하지 않는다.

**답변.** 본문은 읽기 좋은 Markdown·표·코드 블록으로 표시하되 임의 HTML은 렌더링하지 않는다. 사용자 메시지는 정돈된 작은 표면, 답변은 넓은 본문으로 두어 카드가 계속 중첩되지 않게 한다. 답변 머리에는 실제 공급자·모델·실행 상태를 작게 표시한다. 사용량 수치나 출처를 모델 문장에서 추정하지 않는다.

**근거.** 서버가 실제 제공한 논문·페이지 식별자와 대조 가능한 인용만 클릭 가능한 근거로 만든다. 페이지가 검증되지 않은 인용은 일반 텍스트로 둔다. 본문이 없는 논문을 제목만 전달하고 ‘원문을 읽었어요’라고 표시하지 않는다. 최초 구현이 구조화 인용을 지원하지 않으면 자료로 전달한 논문 칩까지만 제공하고 페이지별 검증 미지원임을 명시한다.

**모델.** 처음 연결할 때는 무선택이다. 이후 기존 `useLocalAgent.selectedModel`의 사용자 선택을 재사용하므로 새 대화를 열 때마다 강제로 초기화하지 않는다. 그 선택이 여전히 실제 카탈로그에 있고 현재 선택 행에 보이는 경우에만 사용한다. 모델을 바꾸면 다음 턴부터 적용되고 과거 답변 모델은 그대로 남는다. 과거 이력의 모델 이름을 실행 권한으로 복구하지 않는다. 새 브라우저 세션·권한 상실·카탈로그 제거 시에는 기존 연결 정책에 따라 무선택으로 돌아간다.

**목록.** 제목·갱신 시각·진행 중 표시를 제공하고 최신 활동순으로 정렬한다. 최초 검색은 불러온 내 대화 제목 범위로 한정한다. 저장한 대화를 클릭하면 서버가 제공한 저장 상태에서 열린다. 제목 수정·삭제·분기·팀 공유·더 긴 이력의 페이지 조회는 후속 계약 범위이며, 실제 API가 없으면 작동하는 것처럼 버튼을 두지 않는다.

## 스트림·취소·재시도

기존 LocalAgentJob의 누적 응답·단조 증가 version/sequence를 활용한다. 최초 UI는 같은 origin의 짧은 polling으로 누적 내용을 보여도 된다. SSE/WebSocket이 있다고 광고하지 않는다. 빈 답변에서 첫 내용이 오기 전에는 ‘PC에서 답변 준비 중’, 받은 뒤에는 ‘답변 중’이다. 응답이 와야만 문장이 나타나며 가짜 타이핑을 만들지 않는다.

- **자동 스크롤:** 사용자가 아래에 있을 때만 최신 내용으로 따라간다. 위로 읽고 있으면 위치를 유지하고 ‘새 답변 보기’를 제공한다. 폴링마다 전체 메시지 DOM·포커스를 교체하지 않는다.
- **중지:** 보내기 자리에 **답변 중지**를 제공한다. 클릭 후 ‘중지 확인 중’으로 두고 서버가 취소를 확인해야 ‘중지됨’으로 바꾼다. 완료와 취소가 경합하면 서버의 최종 상태를 따른다. 실패한 취소를 성공으로 표시하지 않는다.
- **부분 답변:** 정상적인 사용자 취소/실행 오류에서 서버가 보존한 내용만 ‘중단된 답변’으로 남긴다. 세션·팀 권한 상실 시 서버가 응답을 지웠다면 클라이언트 캐시에서 복구해 계속 노출하지 않는다.
- **중복:** 전송 intent의 requestId를 재사용해 접수 응답 유실·더블 클릭·재연결이 같은 질문을 두 번 실행하지 않게 한다. 성공 접수 전 초안을 없애지 않는다.
- **다시 시도:** 저장된 질문·논문을 다시 입력 초안으로 가져오고, 현재 연결·실제 모델·자료 접근을 확인한 뒤 사용자가 전송한다. 새 실행은 새 attempt로 기록한다. 이미 완료한 답변을 조용히 덮어쓰지 않는다.
- **동시 작업:** 같은 대화의 실행은 한 번에 하나다. 해당 실행 중 새 질문은 작성 가능하지만 전송은 기다리게 한다. 다른 대화의 기기 작업 수 제한은 서버의 실제 큐 정책에 맞춰 ‘이 PC가 앞선 질문을 처리하고 있어요’로 안내한다.
- **입력:** Enter는 전송, Shift+Enter는 줄바꿈이며 한국어 IME 조합 중 Enter는 전송하지 않는다. 화면에 단축키 설명과 전송 버튼을 함께 둔다.

| 실행 실패/작업 시간 초과 | 서버의 안전한 한국어 error를 해당 답변에 표시하고 재시도 초안 복원을 제공. 원시 stderr·인증 본문·로컬 경로를 보이지 않는다. |

기존 연결의 웹 heartbeat 15초/허가 45초 경계를 유지한다. 앱만 켜 놓아도 웹 권한이 계속 갱신되는 것으로 설명하지 않는다. 웹·PC를 끄고 다시 켜면 AI 연결 버튼으로 설치된 앱을 열고 허용된 조건에서 재개한다. 세션/팀이 달라졌으면 새 번호 확인이 필요하다. 설치 앱과 대화 저장 이력은 별도 수명이다.

## 작은 사용량 링

기존 `QuotaBadge`와 `quotaWindows()`를 재사용한다. 선택한 공급자 옆에 **20px** 링을 두고 글로 된 자세한 수치는 평소 펼쳐 두지 않는다. 버튼 영역은 최소 40px 높이를 유지한다. 실제 제공된 한도 window만 그리며 5시간·7일 두 개가 항상 있다고 가정하지 않는다.

마우스 hover, 키보드 focus, 터치 tap에서 같은 상세를 볼 수 있고 Escape·외부 클릭·이탈로 닫힌다. 포털로 본문/입력창 경계에 잘리지 않게 한다. label·초기화 시각·실제 관측 시각을 보이고 ‘정확한 잔여 토큰 수를 의미하지 않아요’를 유지한다. `quotaObservedAt ?? observedAt`이 90초보다 오래되면 회색의 ‘이전 확인값’, null은 ‘정보를 제공하지 않아요’, 실제 0%는 ‘한도 도달’이다. unknown을 0%나 100%로 칠하지 않는다. 카탈로그가 새로 갱신됐다는 이유로 과거 한도에 ‘방금 확인’을 붙이지 않는다.

## 기존 Gemini 분석을 로컬 CLI로 대체하는 UX

**저장과 실행을 분리한다.** PDF 업로드/허용 URL 저장은 연결 없이 가능해야 한다. 저장 성공 후 논문 상세에서 ‘논문을 저장했어요. 분석할 AI를 선택해 주세요’를 보이고, 연결·실제 모델을 직접 선택한 뒤 **논문 분석 시작**을 누른다. 모델 미선택 상태에서 자동으로 다른 공급자나 Gemini를 호출하지 않는다. 기존 서버 비용용 주간 업로드 제한은 담당자가 목적을 재검토하되 UI에서 이를 CLI 잔여 한도와 합치지 않는다.

분석 준비·대기·실행·실패는 일반 채팅과 구별되는 분석 실행 상태로 관리한다. 연결/모델 선택이 필요한 상태를 무한 ‘분석 중’이나 시간 기반 92% 막대로 표시하지 않는다. 실제 단계는 ‘본문 준비 → PC 연결 대기 → 분석 대기 → 분석 중 → 결과 확인’으로 안내하고 완료 비율을 추정하지 않는다. 웹을 닫으면 45초 권한이 끝나 작업이 중단될 수 있음을 해당 대기/실행 상태의 도움말에 명시한다.

로컬 텍스트 질문만으로 기존 Gemini 기능이 모두 대체되었다고 표시하지 않는다.

| 기존 기능 | 대체 입력/출력과 정직한 화면 |
| --- | --- |
| 연구·재구현 구조화 분석 | 서버가 권한 있는 PDF에서 페이지별 본문을 추출·캐시한다. 호스트가 JSON 스키마를 검증한 결과만 기존 research/repro payload로 저장한다. JSON·필드 검증 실패는 재시도 가능 실패이며 ‘분석 완료’가 아니다. |
| Figure 이미지/해석 | 기존 PDF 렌더·이미지 자산을 보존한다. 현재 어댑터의 입력은 텍스트다. 캡션/본문에 기반한 설명은 그렇게 표시하고, 이미지 자체를 보지 않은 답을 ‘이미지 분석’으로 부르지 않는다. 이미지 입력·bbox 검출을 별도로 구현/검증하기 전에는 ‘그림의 시각적 분석은 아직 지원하지 않아요’를 보인다. |
| 공개 코드 저장소 검색·구조 | 기존 Gemini GoogleSearch를 CLI 도구 차단 상태에서 재현했다고 주장하지 않는다. 서버가 실제 확인해 제공한 저장소 자료가 없으면 ‘저장소를 확인하지 않았어요’. 논문 기반 재현 계획과 실제 코드 구조 확인을 구분한다. |
| 새 분석 실패/취소 | 기존 원문·연구/재구현 결과·Figure·작성자 노트를 보존한다. 새 실행 상태·안전한 오류를 별도로 보이고 검증한 새 결과만 교체한다. 과거 결과에는 당시 모델/시각을 식별할 수 있는 provenance가 필요하다. |

새 분석 결과를 팀에 저장하는 작업은 개인 채팅 답변과 분리한다. 채팅 답변이 자동으로 팀 분석/노트를 덮어쓰지 않는다. 논문 상세의 주 액션은 기존 원문 PDF이며 분석 실행 제어는 본문의 분석 상태 영역을 사용한다. 프로필의 단발 질문 폼은 별도 채팅이 구현되면 대화 화면으로 가는 안내로 정리하고, AI 연결 설정은 남긴다.

## 데이터·API 접합 기준

아래는 호스트 전용 확장 설계다. 최종 필드/함수명은 backend의 `types/research-chat.ts` 계약에서 확정한다. 배포된 portable connector의 기존 DTO/core를 이번 채팅 때문에 변경하지 않는다.

| 단위 | 필요한 계약 |
| --- | --- |
| Conversation | 서버가 활성 teamId/memberId를 주입한 개인 대화. 제목·갱신 시각·turn 목록. 세션 키는 실행 권한이며 대화의 영속 소유자 키가 아니다. 재로그인 후 자기 이력을 다시 읽을 수 있다. |
| Turn | 사용자 질문·순서·선택 논문 1~3개·본문 출처/버전·실제 provider/model·연결된 LocalAgentJob ID. 실행/최종 상태·안전한 error·누적 response. |
| 생성/다음 질문 | `POST /api/research-chat/conversations`에 requestId·paperIds·선택 제목을 전달한다. `POST /conversations/:id/turns`에 prompt·deviceId/provider/model·별도 requestId를 전달한다. 팀/작성자/context는 클라이언트 입력을 신뢰하지 않는다. 작업을 저장하고 즉시 응답한다. |
| 이력 조회/스트림 | 최초 읽기는 인증한 RSC 서비스 조회. 이후 목록/턴/누적 응답은 자체 API. team+member 검증·캐시 방지·버전 단조 증가·페이지 경계가 필요하다. |
| 취소/재시도 | 기존 LocalAgentJob 취소 경계·claimToken·sequence를 그대로 이용한다. 취소는 해당 대화 소유자만. 이력이 유지돼도 만료한 grant로 새 작업을 실행할 수 없다. |
| 본문 준비 | 서버의 권한 검사 후 durable PDF 텍스트 추출/cache. 클라이언트·연결기는 임의 URL/로컬 경로를 만들지 않는다. 본문 제한/제외 범위를 응답해 UI가 준비·없음·길이 제한을 구분한다. |

본문 선택 DTO의 `sourceReady`와 `sourceError`로 준비 완료와 실패를 구분한다. 실패 사유는 서버의 고정 문구만 표시하며 스캔·1~30쪽·20MB·12만 자 제한을 안내한다. 준비 요청 중이어도 서버가 확인한 실패를 우선 보여주고 ‘본문 준비’로 재시도한다. 재시도 접수 뒤 이전 본문 오류만 지우며, 기존 분석·대화·작성자 노트를 보존한다.

현재 `LocalAgentProvider`의 `job` 한 개는 채팅 이력 저장소로 쓰지 않는다. 연결 상태·명시적 모델 선택·카탈로그·연결 모달은 재사용하고, 채팅의 선택 대화/턴/폴링/requestId/초안은 별도 모듈이 소유한다. 이를 위해 동일한 연결 Provider를 화면마다 다시 만들거나 heartbeat를 중복 실행하지 않는다. 기존 v1이 필요로 하는 단일 paperId와 다중 논문 context 결합은 서버가 관리한다.

| PDF/분석 전환 | 서버 PDF 본문 cache, `lib/analysis.ts`, `worker/analyze-paper.ts`, 업로드·reanalyze 라우트와 analyzer 상태 UI/실행 제어. 채팅 UI 담당이 동시에 편집하지 않는다. |

검증은 실패 테스트부터 만든다. 실제 단발 폼 복사 여부보다 사용자 행동과 서버 권한을 확인한다.

1. UI: 초기 모델 무선택·연결 전 초안 보존·1~3논문·비교 starter 2편 필요·본문 준비와 실패·한국어 IME·더블 전송·누적 응답·취소 경합·안전한 rate-limit/login 오류·이력 재조회·팀 전환 늦은 응답 차단. 새 `components/research-chat/__tests__`에서 검증한다.
2. 접근성/반응형: 키보드 목록/선택·모달 포커스 복원·20px 링 hover/focus/touch·390px의 입력/연결 CTA 노출·긴 논문 제목/표/코드의 가로 넘침. 새 `tests/e2e/research-chat.spec.ts`로 회귀한다.
3. backend: 다른 팀/다른 작성자의 목록·ID·취소 거절, 접근 잃은 논문 재사용 차단, requestId 응답 유실 재시도, 턴 순서·중복/과거 sequence 무시, 세션 grant 회수와 개인 이력 수명 분리, 본문 없는 최초 PDF/추출 cache 실패, 검증 안 된 JSON 저장 금지.
4. 기존 회귀: [연결 단위 흐름](../../components/local-agent/__tests__/local-agent-flow.test.tsx), [분석 화면](../../components/analyzer/__tests__/analyzer.test.tsx), [분석 서버](../../lib/__tests__/analysis.test.ts), [업로드 E2E](../../tests/e2e/upload.spec.ts), [논문 E2E](../../tests/e2e/paper.spec.ts), [기존 연결 E2E](../../tests/e2e/local-agent.spec.ts). 공유 서비스 변경 범위에 맞춰 전체 unit/lint/build를 수행한다.

프론트 시연의 mock 답변·quota·모델은 테스트 fixture로만 표시한다. 실제 CLI 실행·PDF 이해·3OS 설치·운영 연결 검증과 구분해 기록한다. 이 문서는 설계 확정 근거이며 새 기능의 테스트 통과나 배포 완료 보고서가 아니다.
