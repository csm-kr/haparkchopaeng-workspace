# AI 브릿지의 브리 캐릭터와 실행 표시

사용자 요청에 따라 설치 아이콘의 글자 표식을 브리 캐릭터로 교체하고, 앱에 Windows 트레이·macOS 메뉴 막대 진입점을 둔다. 연결 번호의 5분 UX는 웹의 기존 상태 계약을 사용한다.

## 적용 경험

- 설치·작업 표시줄 아이콘은 그라파이트 타일 위의 브리, 앱 헤더는 투명 브리를 사용한다.
- Windows 트레이는 작은 크기에서 알아볼 수 있게 선을 두껍게 하고, macOS는 시스템 테마에 맞는 단색 template 이미지를 사용한다. 계정·번호·키를 아이콘 메뉴에 넣지 않는다.
- 트레이에는 현재 상태와 `AI 브릿지 열기`, `앱 종료`를 제공한다. 상태 갱신만으로 창을 열거나 포커스를 가져오지 않는다.
- 트레이를 사용할 수 있는 Windows·Mac에서 연결 중 창 닫기는 숨김이다. 다시 열기와 종료는 트레이에서 가능하다. Ubuntu 또는 트레이 생성 실패 시 창 닫기는 CLI와 모니터를 정리한 뒤 종료하며 앱의 안내도 이 동작을 설명한다.
- 웹 권한 만료에 따른 종료·자동 시작과 펫의 기본 꺼짐은 기존 수명을 따른다.
- 캐릭터 SVG와 래스터 설치·트레이 아이콘을 같은 소스에서 만든다. 앱 레이아웃과 입력·모델·구독 한도 계약은 기존 컴포넌트를 사용한다.

## 선택한 데스크톱 펫의 대비와 표정

2026-10-18 사용자 요청으로 펫에 눈깜빡임과 짧은 미소를 추가한다. 이 절은 구현·검증할 목표이며, 아래 체크를 통과했다는 기록은 아니다. 처음 설치할 때 펫은 계속 꺼져 있고, 사용자가 앱에서 켰을 때만 표시한다.

- 투명한 펫 창 안에 얼굴 면은 불투명한 그라파이트로 둔다. 눈·입·테두리는 앱의 밝은 글자·라임 토큰을 사용해 흰 바탕에서도 얼굴이 비치거나 눈이 사라지지 않게 한다. 어두운 바탕에서는 밝은 외곽선으로 실루엣을 구분한다. 글로우·그림자만으로 대비를 만들지 않는다.
- 실제 88px 표시 크기에서 흰색과 그라파이트 배경을 각각 확인한다. 열린 눈, 감긴 눈, 기본 입, 미소가 모두 구분되어야 한다. 배경은 QA에서만 합성하며 제품의 투명 창을 전체 불투명 패널로 바꾸지 않는다.
- 기본은 열린 눈과 차분한 입이다. 눈만 잠깐 감았다 뜨고, 별도 주기로 짧게 미소 지은 뒤 기본 입으로 돌아간다. 호버하는 동안은 미소를 유지하고 벗어나면 그 시점의 기본 표정으로 복귀한다. 전체 캐릭터나 창의 크기·위치를 표정 때문에 바꾸지 않는다.
- 표정의 주기와 조건은 다음 구현 목표를 따른다. 미소·깜빡임은 장식이며 연결 성공·답변 완료·AI 실행 권한을 뜻하지 않는다.

| 동작 | 주기·조건 | 복귀 |
| --- | --- | --- |
| 눈깜빡임 | 6초마다 한 번, 감긴 표정 유지 약 180ms·전환 포함 약 360ms | 열린 눈 |
| 자발 미소 | 14초마다 약 1.2초 | 기본 입 |
| 호버 미소 | 포인터가 눈·입 중앙의 28×26px 표정 영역에 들어오면 즉시 | 이탈하면 현재 주기의 표정 |
| 동작 줄이기 | 호흡·깜빡임·자발 미소 반복 없음 | 열린 눈·기본 입, 호버만 정적 미소 |

- `prefers-reduced-motion: reduce`에서는 호흡·눈깜빡임·자발 미소의 반복 동작을 끈다. 호버는 애니메이션 없이 정적인 미소만 보여 준다. 표정마다 스크린리더 알림을 보내지 않고 캐릭터의 접근 가능한 이름을 유지한다.
- 눈·입 중앙의 28×26px 투명 표정 영역만 `no-drag`로 둔다. 104×112px 펫 창의 약 6.25%이며, 테두리·몸체·플러그는 계속 잡아 옮긴다. 캐릭터 전체를 `no-drag`로 바꾸거나 마우스를 가로채지 않는다. 얼굴 표정 영역의 실제 네이티브 호버를 확인하고, 코드 미리보기의 호버와 구분한다.
- 표정은 `pet.html`의 인라인 SVG와 `pet.css`만 사용한다. 설치·트레이·메인 앱의 공용 자산은 교체하지 않는다. 펫에 스크립트·preload·Node 접근·새 IPC·원격 리소스를 추가하지 않는다. 앱의 기존 sandbox, CSP, 탐색 차단과 권한 만료 동작을 유지한다. 펫을 켰다는 이유로 AI 실행 권한이나 자동 시작 권한을 만들지 않는다.

## 독립 검토 체크

- [ ] 최초 펫 꺼짐과 명시적 켜기·끄기, 중앙 표정 영역을 제외한 드래그·종료 정책이 유지된다.
- [ ] 흰색·어두운 배경의 실제 렌더에서 얼굴 면과 두 눈·입·외곽선이 구분된다.
- [ ] 한 주기 전체의 열린 눈→감긴 눈→열린 눈과 기본 입→짧은 미소→기본 입을 관측한다. 정지 화면이나 CSS 존재만으로 실제 동작을 통과시키지 않는다.
- [ ] 호버 중 미소·호버 이탈 복귀, reduced-motion에서 반복 동작 없음과 정적 호버를 확인한다.
- [ ] 중앙 28×26px의 실제 얼굴 호버와 테두리·몸체·플러그의 드래그 영역을 구분한다. 네이티브 드래그·포커스 비탈취, 추가 권한·원격 요청 없음과 소유 QA 프로세스 정리를 확인한다.
- [ ] 합성 배경·QA 캡처·모의 연결은 실제 계정 인증·구독 추론·OS 전체 지원이나 운영 배포의 증거로 사용하지 않는다.

## 검증 범위

트레이의 메뉴 콜백·상태·폐기·실패 복구·종료 순서를 Node에서 먼저 검증하고, Electron 부트스트랩 회귀와 OS별 기존 네이티브 QA·설치 파일 빌드를 이어서 수행한다. 그림 시안과 fixture 화면은 실제 계정 페어링·CLI 추론 성공의 근거로 쓰지 않는다.

## 2026-10-24: ImageGen 상태별 브리

사용자가 기존 브리를 더 귀엽게 만들고, 대기·연결 끊김·작업 상태에 맞는 행동을 요청했다. 이어 ImageGen 사용을 명시했다. 이번 구현에는 이 절이 앞의 SVG 전용·스크립트 없음·표정은 상태와 무관하다는 설계보다 우선한다. 설치 아이콘·트레이·앱 ID는 이번 변경 대상에 포함하지 않는다.

ImageGen 원본은 [상태별 스프라이트](assets/bri-imagegen-v1.png), 생성 조건은 [프롬프트](../../connector/desktop/assets/bri/generation.md)에 보관한다. 제품에는 같은 원본의 704×352px WebP atlas(176px 정사각 셀 8개)를 사용한다. 각 상태의 글자는 이미지에 넣지 않고 시스템 글꼴로 렌더한다. 88px 표시에서 대기·눈 감음·인사·연결·타이핑 두 장·복구·연결 끊김을 표현한다.

| 표시 상태 | 시각적 행동 | 문구 |
| --- | --- | --- |
| idle / ready | 6초 주기의 3px 수직 부유, 6초 깜빡임, 14초마다 짧은 인사 | 쉬는 중 / 준비됐어요 — 호버 중에 표시 |
| connecting | 위를 보는 눈과 귀 기울이는 기울기 | 연결 중 |
| working | 집중 표정, 작은 키보드, 0.9초 두 프레임 타이핑 | 일하는 중 — 항상 표시 |
| recovering | 옆을 살피는 눈과 6초 주기 작은 기울기 | 연결 확인 중 |
| disconnected | 처진 안테나와 걱정스러운 입, 정지 | 다시 연결 |
| error | 같은 걱정스러운 표정, 정지 | 연결 확인 |

`selectBriMode()`가 앱 stage와 런타임 status/currentJobId로 표시 상태 하나를 파생한다. 새 연결·오류·권한 종료와 복구는 작업 표시보다 우선한다. 작업이 끝나도 성공·실패·취소를 따로 알 수 없으므로 축하를 추정하지 않는다. 메인 창에도 같은 mode를 보내 작업·복구 배지를 표시한다.

펫 전용 `pet-preload.cjs`는 `onState` 하나만 공개한다. 펫은 mode 문자열만 단방향으로 받으며 질문·답변·작업 ID·계정·기기 키는 받지 않는다. 초기 구독 이전 값은 preload가 보관하고, `did-finish-load` 때 메인이 최신 상태를 다시 발행한다. `script-src 'self'`와 `connect-src 'none'`, sandbox·contextIsolation·Node 차단을 사용한다. 읽기 IPC 요청이나 설정·페어링·종료 API를 펫에 노출하지 않는다.

104×112px 투명 창, 기본 꺼짐과 중앙 28×26px no-drag 영역을 유지한다. 창은 자동으로 돌아다니지 않으며, 처음 보일 때 `showInactive`와 `focusable: false`를 사용한다. 작업 중 호버는 키보드를 가리지 않는다. 동작 줄이기에서는 프레임 재생과 반복 동작을 모두 멈추지만 작업 소품과 상태 문구가 유지된다.

실제 격리 macOS Electron에서 11개 검사를 통과했다. 2× Retina 캡처를 CSS 좌표와 맞춰 흰색·어두운 배경의 얼굴·플러그 대비, 타이핑 두 프레임 차이, 7개 mode의 한글 문구, 호버 복귀, 동작 줄이기와 6초·14초 실제 경과를 확인했다. 포커스 획득·원격 요청·CLI 추론은 0회다. 물리 드래그와 Mac 네이티브 포인터 호버, Windows·Linux와 설치본 배포는 이 검사로 확인하지 않았다.

### 움직임 문법과 품질 검토

사용자가 idle의 수직 움직임과 어색한 동작의 독립 검토를 추가로 요청했다. [MDN의 easing/steps](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timing-function), [Godot의 sprite sheet 재생](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html), [Rive의 state machine](https://rive.app/docs/editor/state-machine/state-machine)을 참고해 기존 Electron/CSS에서 다음을 적용했다. 숫자와 브리에 대한 선택은 이번 구현의 디자인 판단이다.

- **Idle bobbing:** `translateY(0) → translateY(-3px) → translateY(0)`을 6초 `ease-in-out`으로 반복한다. 좌우 이동·회전·크기 변화는 없다. 위아래 끝에서 속도를 줄이고 시작·끝 자세를 같게 한다.
- **분리된 동작 트랙:** 바깥 캐릭터가 부유를 소유하고, 안쪽 이미지가 표정·타이핑·고개 기울기를 소유한다. idle에서 작업 상태로 전환해도 바깥 트랙의 현재 phase를 유지한다. 끊김·오류는 현재 부유 위치에서 정지하고 복귀하면 이어 간다.
- **표정 중복 제거:** 인사 이미지를 보일 때 기본 이미지는 같은 타이밍에 숨긴다. 호버와 자발 인사 모두 몸체가 겹쳐 남는 현상을 실제 렌더에서 재현한 뒤 고쳤다.
- **상태의 즉시성:** 일하는 중·복구 중·연결 끊김 문구를 전환 즉시 표시한다. 움직임의 phase를 유지하는 것과 상태 변경을 지연하는 것을 구분한다.

검사에는 수평 이동 0·회전 0, 6초 실제 float 반복, 상태 전환 전후 phase 유지와 루프 양 끝의 같은 렌더를 추가했다. 타이핑은 손이 바뀌는 두 프레임을 실제 크기로 비교했다. 인사 이미지가 기본 몸체와 동시에 보이지 않는지 별도로 검사했다.

검토용 움직임은 `connector/artifacts/bri-motion-preview-20261024/`에 실제 격리 Electron renderer를 24fps의 정확한 CSS 시각으로 샘플링해 저장한다. 이 미리보기는 같은 스프라이트·스타일·preload를 사용하며, 작업 상태는 모의 입력이다. 영상의 화면 배율과 타임라인은 manifest에 기록한다.

## 2026-10-26: 몸이 있는 브리와 클릭 반응

사용자가 브리에게 몸을 만들어 달라고 했고, 호버 때 움직이던 반응을 클릭으로 옮기며 어디를 잡아야 옮겨지는지 보이게 해 달라고 했다. 클릭하면 무작위 반응을 요청했다. 몸 제작은 Codex ImageGen 재생성, 모양은 짧은 다리 장난감 로봇을 사용자가 선택했다. 이 절은 앞의 "중앙 28×26px no-drag", "호버 미소", "104×112px 창"보다 우선한다. 설치 아이콘·트레이·메인 창 그림(`idle-v1.png`)은 바꾸지 않는다.

[원본](assets/bri-imagegen-v2-body.png)과 [프롬프트·파생 방법](../../connector/desktop/assets/bri/generation.md)을 보관한다. 제품은 800×720px WebP atlas(200×240px 셀 12개, 100×120 CSS px 표시)를 쓴다.

- **창:** 104×144px 투명 창. 기본 위치는 작업 영역 오른쪽 아래에서 26·28px 안쪽이다. `acceptFirstMouse`를 켠다. 펫은 `focusable: false`라 활성화되지 않으므로, 이 옵션이 없으면 macOS의 첫 클릭이 페이지에 전달되지 않는다.
- **옮기기:** 창 드래그 영역은 오른쪽 위 22×22px ✥ 손잡이 하나(창의 약 3.2%)다. 호버하면 0.15초 동안 나타나고, 동작 줄이기에서는 전환 없이 바로 보인다. Electron의 드래그 영역은 클릭 이벤트를 받지 못하므로 몸 전체를 드래그 영역으로 두면 클릭 반응을 만들 수 없다. 창 이동을 위한 IPC는 추가하지 않는다.
- **클릭 반응:** 대기·준비에서는 손 흔들기·점프·킥킥·춤·윙크 중 직전과 다른 하나를 1.2초 동안 보여 준다. 연결 중·작업 중·복구·끊김·오류에서는 상태 자세를 가리지 않도록 0.45초 눌림만 한다. 실제 상태가 바뀌면 반응을 즉시 끝낸다. 반응은 장식이며 연결·작업 결과를 뜻하지 않는다.
- **움직임 트랙:** `.bri`가 부유, 새 `.pose`가 클릭 반응의 움직임, `.sprite`가 표정·타이핑을 맡는다. 반응이 부유 phase를 초기화하지 않는다. 14초마다 하는 인사는 손 흔들기 셀로 유지한다. 호버는 손잡이와 대기·준비 문구만 보여 주고 표정을 바꾸지 않는다.
- **동작 줄이기:** 반복 동작과 반응 움직임을 모두 멈추고, 클릭하면 반응 자세만 정적으로 1.2초 보여 준다.

실제 격리 macOS Electron에서 12개 검사를 통과했다. 흰색·어두운 배경의 얼굴·플러그 대비, 깜빡임·타이핑 프레임, 7개 mode의 한글 문구, 호버 손잡이 표시, Chromium 입력 이벤트로 보낸 클릭의 무작위 반응과 복귀, 작업 중 눌림, 동작 줄이기, 드래그 영역이 손잡이 하나뿐인지 확인했다. 포커스 획득·원격 요청은 0회다. 실제 OS 포인터 클릭·물리 드래그와 Windows·Linux, 설치본은 이 검사로 확인하지 않았다.

## 2026-10-27: 브리 어디든 끌기와 우클릭 앱 열기

0.1.14의 ✥ 손잡이는 너무 작았고, 커서를 올리면 사라졌다. 손잡이가 OS 드래그 영역이라 Chromium이 그 위에서 마우스가 창을 떠난 것으로 보고 호버를 끄기 때문이다. 사용자 요청에 따라 손잡이를 없애고, 앞 절의 손잡이·"창 이동 IPC 없음"보다 이 절을 우선한다.

- **입력:** 브리 위에서 커서는 `move`(✥)다. 왼쪽 버튼을 누른 채 4px 이상 움직이면 끌기, 그보다 적으면 클릭이다. 좌클릭은 반응만 하고, 끌기는 반응 없이 창만 옮긴다. 우클릭하면 트레이의 `AI 브릿지 열기`와 같은 함수로 메인 창을 연다.
- **OS 드래그 영역 없음:** 드래그 영역은 클릭을 받지 못하므로 쓰지 않는다. 끌기 판정은 창 기준 좌표로 한다. 끌기가 보고되기 전에는 창이 움직이지 않기 때문이다.
- **신호:** 펫 preload는 `onState`에 더해 인자 없는 `startDrag`·`endDrag`·`openApp` 세 신호만 보낸다. 페이지가 좌표나 대상을 정하지 못한다. 메인은 펫 창의 main frame에서 온 신호만 받는다. 끌기 동안 메인은 실제 커서를 16ms마다 따라 창을 옮기고, 놓으면 멈춘다. 놓기 신호를 잃어도 1분 뒤 멈추고, 펫 창이 닫히면 바로 멈춘다.
- 펫은 계속 `focusable: false`이고 끌기·우클릭으로 펫이 포커스를 갖지 않는다. 우클릭으로 메인 창이 앞으로 오는 것은 사용자가 요청한 동작이다.

실제 격리 macOS Electron에서 13개 검사를 통과했다. Chromium 입력 이벤트로 보낸 좌클릭은 반응만 하고 신호를 보내지 않는다. 끌기는 시작·끝 신호를 한 번씩 보내고 반응이 없으며, 우클릭은 앱 열기 신호를 한 번 보낸다. 메인이 커서를 따라 창을 옮기고 우클릭으로 메인 창을 여는 동작은 Node fixture에서 확인했다. 실제 OS 포인터로 끄는 동작과 Windows·Linux의 창 이동(특히 Wayland)은 확인하지 않았다.
