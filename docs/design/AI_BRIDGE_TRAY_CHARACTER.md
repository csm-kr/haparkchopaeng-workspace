# AI 브릿지의 브리 캐릭터와 실행 표시

사용자 요청에 따라 설치 아이콘의 글자 표식을 브리 캐릭터로 교체하고, 앱에 Windows 트레이·macOS 메뉴 막대 진입점을 둔다. 연결 번호의 5분 UX는 웹의 기존 상태 계약을 사용한다.

## 먼저 확인한 시각 근거

2026-10-18 Aside의 로그인된 GitHub에서 사용자가 지정한 저장소의 다음 두 파일을 읽었다. 참고 범위는 캐릭터와 앱의 색감이다.

- [Bri.tsx](https://github.com/csm-kr/agents-bridge/blob/main/apps/web/src/components/Bri.tsx): 둥근 사각 머리, 점눈, 한 줄 입, 안테나, 양옆 플러그가 있는 선형 로봇. 작은 크기에서는 글로우를 생략한다.
- [globals.css](https://github.com/csm-kr/agents-bridge/blob/main/apps/web/src/app/globals.css): 그라파이트 바탕·라임·앰버·코랄 팔레트.

## 적용 경험

- 설치·작업 표시줄 아이콘은 그라파이트 타일 위의 브리, 앱 헤더는 투명 브리를 사용한다.
- Windows 트레이는 작은 크기에서 알아볼 수 있게 선을 두껍게 하고, macOS는 시스템 테마에 맞는 단색 template 이미지를 사용한다. 계정·번호·키를 아이콘 메뉴에 넣지 않는다.
- 트레이에는 현재 상태와 `AI 브릿지 열기`, `앱 종료`를 제공한다. 상태 갱신만으로 창을 열거나 포커스를 가져오지 않는다.
- 트레이를 사용할 수 있는 Windows·Mac에서 연결 중 창 닫기는 숨김이다. 다시 열기와 종료는 트레이에서 가능하다. Ubuntu 또는 트레이 생성 실패 시 창 닫기는 CLI와 모니터를 정리한 뒤 종료하며 앱의 안내도 이 동작을 설명한다.
- 웹 권한 만료에 따른 종료·자동 시작과 펫의 기본 꺼짐은 기존 수명을 따른다.
- 캐릭터 SVG와 래스터 설치·트레이 아이콘을 같은 소스에서 만든다. 앱 레이아웃과 입력·모델·구독 한도 계약은 기존 컴포넌트를 사용한다.

## 선택한 데스크톱 펫의 대비와 표정

2026-10-18 사용자 요청으로 펫에 눈깜빡임과 짧은 미소를 추가한다. 이 절은 구현·검증할 목표이며, 아래 체크를 통과했다는 기록은 아니다. 처음 설치할 때 펫은 계속 꺼져 있고, 사용자가 앱에서 켰을 때만 표시한다.

- 투명한 펫 창 안에 얼굴 면은 불투명한 그라파이트로 둔다. 눈·입·테두리는 앱의 밝은 글자·라임 토큰을 사용해 흰 바탕에서도 얼굴이 비치거나 눈이 사라지지 않게 한다. 어두운 바탕에서는 밝은 외곽선으로 실루엣을 구분한다. 글로우·그림자만으로 대비를 만들지 않는다.
- 실제 88px 표시 크기에서 흰색과 그라파이트 배경을 각각 확인한다. 열린 눈, 감긴 눈, 기본 입, 미소가 모두 구분되어야 한다. 배경은 QA에서만 합성하며 제품의 투명 창을 전체 불투명 패널로 바꾸지 않는다.
- 기본은 열린 눈과 차분한 입이다. 눈만 잠깐 감았다 뜨고, 별도 주기로 짧게 미소 지은 뒤 기본 입으로 돌아간다. 호버하는 동안은 미소를 유지하고 벗어나면 그 시점의 기본 표정으로 복귀한다. 전체 캐릭터나 창의 크기·위치를 표정 때문에 바꾸지 않는다.
- 표정의 주기와 조건은 다음 구현 목표를 따른다. 미소·깜빡임은 장식이며 연결 성공·답변 완료·AI 실행 권한을 뜻하지 않는다.

| 동작 | 주기·조건 | 복귀 |
| --- | --- | --- |
| 눈깜빡임 | 6초마다 한 번, 감긴 표정 유지 약 180ms·전환 포함 약 360ms | 열린 눈 |
| 자발 미소 | 14초마다 약 1.2초 | 기본 입 |
| 호버 미소 | 포인터가 눈·입 중앙의 28×26px 표정 영역에 들어오면 즉시 | 이탈하면 현재 주기의 표정 |
| 동작 줄이기 | 호흡·깜빡임·자발 미소 반복 없음 | 열린 눈·기본 입, 호버만 정적 미소 |

- `prefers-reduced-motion: reduce`에서는 호흡·눈깜빡임·자발 미소의 반복 동작을 끈다. 호버는 애니메이션 없이 정적인 미소만 보여 준다. 표정마다 스크린리더 알림을 보내지 않고 캐릭터의 접근 가능한 이름을 유지한다.
- 눈·입 중앙의 28×26px 투명 표정 영역만 `no-drag`로 둔다. 104×112px 펫 창의 약 6.25%이며, 테두리·몸체·플러그는 계속 잡아 옮긴다. 캐릭터 전체를 `no-drag`로 바꾸거나 마우스를 가로채지 않는다. 얼굴 표정 영역의 실제 네이티브 호버를 확인하고, 코드 미리보기의 호버와 구분한다.
- 표정은 `pet.html`의 인라인 SVG와 `pet.css`만 사용한다. 설치·트레이·메인 앱의 공용 자산은 교체하지 않는다. 펫에 스크립트·preload·Node 접근·새 IPC·원격 리소스를 추가하지 않는다. 앱의 기존 sandbox, CSP, 탐색 차단과 권한 만료 동작을 유지한다. 펫을 켰다는 이유로 AI 실행 권한이나 자동 시작 권한을 만들지 않는다.

## 독립 검토 체크

- [ ] 최초 펫 꺼짐과 명시적 켜기·끄기, 중앙 표정 영역을 제외한 드래그·종료 정책이 유지된다.
- [ ] 흰색·어두운 배경의 실제 렌더에서 얼굴 면과 두 눈·입·외곽선이 구분된다.
- [ ] 한 주기 전체의 열린 눈→감긴 눈→열린 눈과 기본 입→짧은 미소→기본 입을 관측한다. 정지 화면이나 CSS 존재만으로 실제 동작을 통과시키지 않는다.
- [ ] 호버 중 미소·호버 이탈 복귀, reduced-motion에서 반복 동작 없음과 정적 호버를 확인한다.
- [ ] 중앙 28×26px의 실제 얼굴 호버와 테두리·몸체·플러그의 드래그 영역을 구분한다. 네이티브 드래그·포커스 비탈취, 추가 권한·원격 요청 없음과 소유 QA 프로세스 정리를 확인한다.
- [ ] 합성 배경·QA 캡처·모의 연결은 실제 계정 인증·구독 추론·OS 전체 지원이나 운영 배포의 증거로 사용하지 않는다.

## 검증 범위

트레이의 메뉴 콜백·상태·폐기·실패 복구·종료 순서를 Node에서 먼저 검증하고, Electron 부트스트랩 회귀와 OS별 기존 네이티브 QA·설치 파일 빌드를 이어서 수행한다. 그림 시안과 fixture 화면은 실제 계정 페어링·CLI 추론 성공의 근거로 쓰지 않는다.
