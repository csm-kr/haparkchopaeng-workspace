# 논문 기반 대화형 PT 제작 공간

2026-10-18 제품 설계·구현 기록. 사용자에게서 제작 방식 1번과 개발 진행을 확인했다. 실제 구현·검증 상태는 [phase 21](../../phases/21-paper-pt-workspace/index.json), 공통 목표 작업 기반은 [phase 20](../../phases/20-agent-centric-foundation/index.json)에 기록한다. 로컬 검증과 운영 배포는 구분한다.

## 사용자가 정한 방향

1. 논문 자료를 사용해 실제 발표용 PT를 만든다.
2. 발표 자료 메뉴 안에 PT를 만드는 전용 공간을 둔다. 같은 공간에서 제작 에이전트와 대화하고 결과를 고친다.
3. 가능한 한 Grilling과 티키타카로 의도를 좁힌다. 긴 설문을 한꺼번에 제시하지 않고 한 질문과 답변을 이어간다.
4. **논문을 먼저 읽고 발표 방향 2~3개를 제안**한다. 발표 목적부터 질문한 뒤 논문을 읽는 순서는 사용하지 않는다.
5. [csm-kr/pt-maker-skill](https://github.com/csm-kr/pt-maker-skill)의 기획·제작·검수 흐름을 참고한다. 확인한 commit은 `a08309374bdf77ea1d4ab797bb39e101c0b9baf1`이다.

## 참고 스킬에서 가져올 계약

- [인테이크](https://github.com/csm-kr/pt-maker-skill/blob/a08309374bdf77ea1d4ab797bb39e101c0b9baf1/pt-maker/reference/intake.md): 질문은 하나씩, 이미 답한 항목은 재질문하지 않는다. 모호한 답에는 꼬리 질문을 하고 근거와 주장 불일치는 짚는다. 메시지·청중·근거·발표 후 기대 행동을 기획에 남긴다.
- [제작 계약](https://github.com/csm-kr/pt-maker-skill/blob/a08309374bdf77ea1d4ab797bb39e101c0b9baf1/pt-maker/SKILL.md): 기획을 합의한 뒤 슬라이드를 만든다. 각 장의 주장·역할·시각자료 계획을 연결하고 한 장에 한 주장을 둔다.
- [기본 산출물](https://github.com/csm-kr/pt-maker-skill/blob/a08309374bdf77ea1d4ab797bb39e101c0b9baf1/pt-maker/reference/production-direction.md): 정적 발표는 Reveal HTML/PDF, 애니메이션 발표는 탐색 가능한 HTML이다. MP4는 명시 요청한 경우에만 추가한다. 현재 PPTX export는 이미지 기반 옵션이며 편집 가능한 PowerPoint가 아니다.
- 렌더된 페이지로 넘침·한글 줄바꿈·크롭·정렬·장수·원문 근거를 검사한다. 수정 뒤 해당 결과를 다시 렌더하고 사용자와 반복 검토한다. 검사 전 품질 점수나 완성 판정을 주장하지 않는다.

외부 스킬의 ‘포맷을 가장 먼저 묻기’는 이 앱의 사용자 결정인 **논문 먼저 읽기**에 맞게 조정한다. 이 앱 설계를 위한 참고이며 지금 특정 논문의 덱 제작을 실행하는 요청은 아니다.

## 제안하는 사용자 흐름

논문 선택 → 논문 읽기 → 근거가 붙은 발표 방향 2~3개 → 방향 선택·수정 → 한 질문씩 Grilling → 합의한 발표 브리프 → 목차·장별 주장·Figure 계획 → 슬라이드 제작 → 대화로 수정 → 렌더 검수 → 발표 자료 등록·내보내기.

각 발표 방향은 제목만 다른 후보가 아니라 중심 주장·청중에게 남길 메시지·주요 근거·뺄 범위·장단점이 달라야 한다. 예를 들어 방법 이해, 실험 비판, 재현 검토 같은 방향을 원문에 맞게 제시하며 고정된 세 가지를 모든 논문에 강제하지 않는다.

논문 Figure·표·수치는 원문 페이지와 출처를 보존한다. 생성 일러스트나 다시 그린 개념도는 원문 실험 증거와 구분한다. 대화로 방향을 바꾸면 기획 revision을 올리고 영향을 받는 목차·슬라이드·검수를 다시 수행한다. 팀 공개 전까지 대화와 초안은 작성자의 개인 작업이다.

## 확정한 제작 방식

사용자는 **1번: 논문의 실제 Figure·표·설명 도식 중심**을 선택했고 개발을 이어가도록 했다. 첫 버전은 현재 팀 연구 발표, 기본 30분, 앱 안의 미리보기와 HTML/PDF 내보내기를 기준으로 개발한다. 발표마다 에이전트와 대화하며 청중·시간·깊이·메시지·도식 사용을 바꿀 수 있다.

Grilling은 앱 사용자가 PT를 만드는 상호작용이다. 개발 도중 모든 UI 선택을 다시 사용자에게 질문하며 구현을 멈추는 절차로 사용하지 않는다. 기존 기획·목차를 먼저 보여주고 슬라이드를 만든 뒤 대화로 고친다. 공개 등록은 검토한 결과만 저장한다.

## 구현과 기존 경로 연결

`/presentations`의 세미나 만들기는 `/presentations/new`로 연결한다. `/presentations/create/:taskId`에서 논문을 먼저 읽고 방향 제안·한 질문씩 대화·브리프·목차·Figure/표/설명 도식 슬라이드·대화 수정을 이어간다. 페이지를 다시 열면 개인 작업을 복원한다. 기존 노트·직접 세미나 생성은 호환한다.

다시 로그인한 사용자는 이전 개인 대화를 읽고 **연결 후 이어가기**로 현재 연결에 명시적으로 붙인다. 이미 등록한 덱의 HTML/PDF 준비는 현재 로그인 grant로 접수한다. 과거 세션의 실행 권한을 자동 복원하지 않는다.

공통 작업 엔진과 현재 웹의 45초 grant를 재사용한다. 기획·대화·덱은 AgentTask.draft JSON에 보존하며 새 컬럼은 없다. 논문 읽기·그림 목록·출력 자산은 서버에서 팀·소유자를 검증한다. 모델은 JSON만 제안하고 기존 CLI 도구 제한을 유지한다. 검토한 덱의 HTML/PDF는 기존 Job과 Inngest에서 제작하며 요청 경로에서 렌더하지 않는다.

1280×720 공통 장면을 안전한 HTML/SVG와 native PDF로 출력한다. 원문 그림은 실제 자산을 포함하고 도식은 구조화 노드·연결로 그린다. 한글 폰트를 파일에 포함하며 줄바꿈·장면 경계·장수·실제 PDF 래스터화를 검사한다. 참고 스킬의 Reveal.js를 그대로 임베드하지 않고 앱의 제한된 렌더러를 사용했다. HTML은 비공개 다운로드 첨부로 제공한다. 원문·덱이 바뀌면 이전 파일을 최신 결과로 제공하지 않는다.

검토 등록 시 정확히 같은 덱의 생성 PDF/HTML을 PresentationAsset에 연결한다. 등록 후 같은 덱의 출력을 준비해도 연결한다. 기존 `getShareablePresentations`가 PDF를 찾으므로 라이브의 수동 자료 선택과 접합한다. 일정 자동 생성·라이브 자동 시작은 추가하지 않는다. 학술적 주장·표 수치의 의미·발표 적합성은 사용자가 원문 근거와 함께 검토한다. 자동 기하 검사만으로 내용 품질 점수를 매기지 않는다.
