# UI 디자인 가이드

> **정본은 `src/styles.css`(전체 토큰·컴포넌트 스타일)와 루트 `README.md`의 디자인 토큰 절이다.** 이 문서는 대표 값만 발췌한 통합 요약이다 — 구현 시 값은 항상 `styles.css`의 CSS 커스텀 프로퍼티에서 가져오고 하드코딩하지 않는다.
>
> 형제 문서: [`SCREENS.md`](./SCREENS.md)(화면 카탈로그) · [`SCREEN_FLOW.md`](./SCREEN_FLOW.md)(화면 전환·상태).

## 디자인 원칙
1. 도구처럼 보여야 한다 — 마케팅 페이지가 아니라 매주 쓰는 워크스페이스. 따뜻하고 격식 없는 한국어 톤.
2. 정직한 빈 상태 — 라이브 없음, 빈 달은 비어 있는 그대로 + 명확한 CTA 하나.
3. 모든 색·반경·그림자·간격은 토큰으로 — 컴포넌트에 hex를 직접 쓰지 않는다. 라이트/다크는 `[data-theme]` 토큰 오버라이드만으로 동작해야 한다.

## 하지 마라
| 금지 사항 | 이유 |
|-----------|------|
| 토큰 대신 hex 하드코딩 | 다크 테마·액센트 스위칭(`--accent*` 오버라이드)이 깨진다 |
| 논문 상세에 탭/사이드 패널 추가 | 두 관점 토글 자체가 페이지다 (ADR-004) |
| 화면 안에 `live` 상태 보관 | 배지·배너·룸이 어긋난다 (ADR-001) |
| 허용 목록 밖의 애니메이션 | 아래 "애니메이션" 절의 keyframes만 사용 |
| `tweaks-panel.jsx` 포팅 | 디자인 탐색 도구이지 제품 기능이 아니다 |
| 균일한 큰 rounded 모서리 남발 | 반경은 용도별 토큰(`--r-xs`~`--r-xl`)을 따른다 |

## 색상
모든 값은 `src/styles.css`의 `:root`(라이트) / `[data-theme="dark"]`에 정의. 대표 값:

### 배경 (라이트 / 다크)
| 용도 | 라이트 | 다크 |
|------|--------|------|
| 페이지 `--bg` | `#fbfaf7` (웜 화이트) | `#16151a` |
| 카드 `--bg-elevated` | `#ffffff` | `#1e1d23` |
| 서브틀 `--bg-subtle` | `#f3f1ec` | `#25242c` |
| 호버 `--bg-hover` | `#efece5` | `#2c2b34` |

### 텍스트
| 용도 | 라이트 | 다크 |
|------|--------|------|
| 주 텍스트 `--fg` | `#1a1814` | `#f0eee9` |
| 본문 `--fg-muted` | `#57534b` | `#a8a39a` |
| 보조 `--fg-subtle` | `#8a857a` | `#767168` |
| 비활성 `--fg-faint` | `#b8b3a5` | `#4a473f` |

### 액센트 / 시맨틱
| 용도 | 값 |
|------|------|
| 브랜드 액센트 `--accent` | `oklch(0.58 0.20 280)` 보라-파랑 blurple (다크: `oklch(0.68 0.18 280)`) |
| 액센트 틴트 | `--accent-soft`, `--accent-faint` (배지·포커스 링) |
| 온라인 `--online` | `oklch(0.72 0.17 145)` |
| 자리비움 `--away` | `oklch(0.75 0.15 75)` |
| 바쁨/위험 `--busy` | `oklch(0.65 0.20 25)` |
| 멤버 색 | `--m-ha`(코랄) · `--m-bak`(그린) · `--m-jo`(퍼플) · `--m-paeng`(앰버) — 아바타/태그 |

역할 배지: 관리자 = 액센트 틴트, 멤버 = 중립, 게스트 = 앰버 틴트. 브랜드 그라데이션(`--grad-brand`, `--grad-vivid`)은 히어로/브랜드 표면 전용 — 일반 UI 카드에 쓰지 않는다.

## 컴포넌트
### 카드 (`.card`)
```
background: var(--bg-elevated); border: 1px solid var(--border);
border-radius: var(--r-lg);  /* hoverable: hover 시 border-strong + shadow-sm */
```

### 버튼 (`.btn`)
```
공통:      padding 7px 14px; radius var(--r-sm); 13px/500
Primary:   background var(--accent); color var(--accent-fg); hover → --accent-hover
Secondary: background var(--bg-elevated); border var(--border-strong)
Ghost:     color var(--fg-muted); hover → bg-hover + fg
크기:      .btn-lg (10px 18px / 14px) · .btn-sm (4px 10px / 12px)
```

### 입력 필드 (`.input`)
```
padding 9px 12px; background var(--bg-elevated); border 1px solid var(--border-strong);
radius var(--r-sm); focus → border --accent + 0 0 0 3px var(--accent-soft)
```

## 레이아웃
- 앱 셸: 사이드바 260px + 콘텐츠의 2컬럼 grid, `height: 100vh`.
- 간격: 4px 기반, flex/grid `gap` 사용. 밀도 토큰 `--density-row/pad/gap` (compact 변형 있음).
- 반경: `--r-xs` 4 / `--r-sm` 6 / `--r-md` 8 / `--r-lg` 12 / `--r-xl` 16px.
- 그림자: `--shadow-xs`~`--shadow-lg` (lg는 메뉴/팝오버).

## 타이포그래피
| 용도 | 스타일 |
|------|--------|
| 페이지 제목 `.h1` | 28px / 700 / letter-spacing -0.025em |
| 섹션 제목 `.h2` | 20px / 600 |
| 소제목 `.h3` | 16px / 600 |
| 본문 | 13–14px, line-height 1.5 |
| 작은/메타 | 11–12px |
| 폰트 | UI = Pretendard(`--font-sans`); 날짜·시간·숫자·코드 = JetBrains Mono(`--font-mono`) |

## 애니메이션
허용 목록 (전부 `styles.css`에 정의된 것만):
- `slidein` 0.2s — 토스트 진입
- `shimmer` 1.4s — 분석 처리 중 스켈레톤
- `livepulse` 1.6s — LIVE 알약/도트 깜빡임 (라이브 상태 전용)
- `fade-up`, `floatup`(미팅 이모지 반응), 히어로 전용 `aurora-drift`/`ring-spin`
- 그 외 모든 애니메이션 금지. 트랜지션은 0.1s 수준의 border/shadow/transform만.

## 아이콘
- `<Icon name="…" />` 인라인 SVG 세트 (`video`, `play`, `calendar`, `users`, `sparkles`, `download`, `plus`, `x`, `chevron-*` 등). 프로덕션은 Lucide로 매핑하면 거의 전부 커버.
- 아바타는 `<Avatar user={…} />` — 이니셜 + 멤버 색 타일.
- 외부 브랜드 에셋 없음. 유일한 브랜드 마크는 텍스트 워드마크 "하박조팽".

# UX 패턴 (Interaction Patterns)

> 화면별 상태 적용은 [`SCREENS.md`](./SCREENS.md), 전환·조건부 UI는 [`SCREEN_FLOW.md`](./SCREEN_FLOW.md)를 본다. 이 절은 **모든 화면에 일관되게 적용할 인터랙션 규칙**이다.

## 상태 3종 (모든 데이터 표면)

데이터를 부르는 모든 화면은 **빈 / 로딩 / 에러** 세 상태를 반드시 정의한다. 하나라도 빠지면 미완성으로 본다.

| 상태 | 표현 | 카피 톤 |
|---|---|---|
| **로딩** | `shimmer` 스켈레톤(레이아웃 유지, 스피너 지양). 즉시 응답 액션은 낙관적 UI | 카피 없음 — 형태로 전달 |
| **빈(Empty)** | 정직한 빈 상태 + 명확한 CTA 하나. 가짜 데이터 금지 | 따뜻하게: "아직 없어요. {행동}부터 시작해볼까요?" |
| **에러** | 인라인 에러 카드 + **다시 시도** 액션. 화면을 통째로 날리지 않는다 | 비난 없이: "불러오지 못했어요. 잠깐 후 다시 시도해주세요." |

- **부분 로딩:** 셸(사이드바·상단바)은 즉시 그리고 콘텐츠 영역만 스켈레톤. 전체 화면 블로킹 스피너 금지.
- **낙관적 UI:** 섹션 노트 추가, 댓글, 반응은 즉시 반영하고 실패 시 롤백 + 토스트. (서버 작성자 주입은 유지 → [`../security/SECURITY.md`](../security/SECURITY.md))

## 피드백 (Toast)

- **성공:** 가벼운 토스트(`slidein`, ~2.8s 자동 소멸). 예: "올렸어요 ✅", "저장했어요". 과용 금지 — 화면이 이미 결과를 보여주면 토스트 생략.
- **실패:** 토스트 + 가능하면 **되돌리기/다시 시도** 액션. 영구 에러는 인라인으로.
- **진행:** 업로드→분석처럼 긴 작업은 단계(진행률 → "분석 중…")를 명시. 침묵 금지.

## 확인 (Confirmation) — 파괴적/비가역 액션

되돌리기 어려운 액션은 **실행 전 확인**하거나, 실행 후 **되돌리기 창**을 제공한다.

| 액션 | 패턴 |
|---|---|
| 멤버 내보내기 | 확인 다이얼로그(이름 명시) — 위험 색(`--busy`) 버튼 |
| 노트/댓글 삭제 | 인라인 확인 또는 짧은 되돌리기 토스트 |
| 라이브 **종료**(전체) | 확인 다이얼로그 "모두의 세션이 끝나요. 종료할까요?" |
| 스케줄 편집 **취소** | 변경분 있으면 확인 "작성 중인 초안이 사라져요" |
| 초대 취소 | 즉시 + 되돌리기 토스트 |

- **나가기 vs 종료** 구분을 시각적으로 분명히(나가기=Secondary, 종료=위험). 혼동이 사고로 이어진다.

## 접근성 (a11y)

- **모션 존중:** `prefers-reduced-motion`이면 `livepulse`(LIVE 깜빡임)·`shimmer`·`floatup`을 **정적 표현으로 대체**(깜빡임 대신 정적 LIVE 배지 + 도트). 깜빡임만으로 정보를 전달하지 않는다.
- **색에만 의존 금지:** 상태(온라인/벌금/역할)는 색 + 텍스트/아이콘 병행. presence 도트엔 `aria-label`.
- **키보드:** 모든 인터랙션은 키보드로 도달·실행 가능. 포커스 링은 `--accent-soft`(이미 input에 정의)로 명확히. 모달은 포커스 트랩 + `Esc` 닫기(업로드/명령 팔레트는 이미 `Esc`).
- **스크린리더:** 아바타·아이콘 버튼에 `aria-label`(예: "조성민 아바타", "원문 PDF 다운로드"). LIVE 상태 변화는 `aria-live`로 안내.
- **대비:** 토큰은 라이트/다크 모두 본문 대비 AA를 목표. `--fg-faint`는 비활성 전용(본문 텍스트로 쓰지 않음).
- **타깃 크기:** 아이콘 버튼 최소 ~32px 히트 영역.

## 반응형

- **데스크톱 우선**(주 사용처는 책상). 단, **스케줄 확인·라이브 입장·댓글**은 모바일에서도 되어야 한다("토요일 아침 폰으로 입장").
- 좁은 화면: 사이드바는 `collapsed`(레일) → 오버레이 드로어로. 2컬럼은 1컬럼으로 스택. 논문 분석 `toc` 점프는 상단 셀렉트로.
- 라이브 룸은 모바일에서 발표자 스포트라이트 우선(참가자 타일 접기).

## 마이크로카피 톤

따뜻하고 격식 없는 한국어("리서치는 혼자 하는 게 아니야"). 에러도 비난하지 않는다. 시스템 용어("Error 500") 노출 금지 — 사람 말로 번역.

| 맥락 | 권장 카피 |
|---|---|
| 빈 논문 목록 | "아직 올라온 논문이 없어요. 첫 PDF를 올려볼까요?" |
| 분석 처리 중 | "논문을 읽고 있어요…" |
| 업로드 실패 | "업로드가 안 됐어요. 파일을 확인하고 다시 시도해주세요." |
| 빈 달 | "이 달은 아직 일정이 없어요." + [일정 짜기] |
| 라이브 없음 | "진행 중인 라이브가 없습니다." |
| 권한 없음 | "이 작업은 관리자만 할 수 있어요." |

## 지연·낙관성 가이드

| 작업 | 패턴 |
|---|---|
| 노트/댓글/반응 추가 | 낙관적 즉시 반영 → 실패 시 롤백+토스트 |
| 업로드 → 분석 | 명시적 단계 진행(진행률 → 분석 중 → 완료 이동) |
| 스케줄 저장 | 버튼 로딩 상태, 완료 후 확정 모드 전환 |
| 라이브 입장 | 즉시 룸 진입, 플레이어 버퍼링은 룸 안에서 표시 |
