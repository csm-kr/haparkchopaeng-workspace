## 목표와 결정

사용자는 **AI 연결** 한 곳에서 시작한다. 설치 여부를 물어보는 선택창이나 긴 설정 마법사를 먼저 보여주지 않는다. 시스템이 현재 웹 권한, 연결기 응답, 공급자 상태를 확인하고 필요한 화면만 이어 준다.

- 처음에는 연결기를 한 번 설치하고, 웹에 나온 6자리 번호를 연결창에 입력한다.
- 설치·첫 실행 후 웹은 완료 이벤트를 받아 이어 간다. Windows 설치기는 완료 후 첫 실행을 연결하고, macOS·Ubuntu는 패키지별로 필요한 최초 열기 동작을 안내한다. 웹에서 ‘설치했어요’를 누르는 단계를 기본 흐름에 두지 않는다.
- 다음 사용에는 웹의 **AI 연결**이 OS에 등록한 전용 링크로 설치된 연결기를 연다. 유효한 웹 세션·기기 권한이면 번호를 다시 요구하지 않는다.
- 이미 실행 중이며 현재 웹에 승인된 연결기라면 상태를 자동 복구한다. 다른 PC가 온라인이라는 이유로 현재 PC에 연결됐다고 표시하지 않는다.
- 앱 자동 시작, 펫, 첫 모델 선택은 켜거나 지정하지 않는다. 사용자가 명시적으로 선택한다.
- 연결기 창은 다크모드다. 웹은 기존 테마 설정을 따른다.

## 기존 UI에 놓는 위치

`DESIGN_GUIDE.md`, `src/styles.css`, `components/settings/settings-view.tsx`, `components/shell/topbar.tsx`를 기준으로 한다.

1. **상단 액션:** 기존 `Topbar.actions`에 작은 모니터 아이콘과 ‘AI 연결’을 둔다. 연결 후에는 ‘내 PC 연결됨’으로 바뀐다. 별도 내비게이션 메뉴를 만들지 않는다.
2. **설정 카드:** 기존 `/profile`의 카드 목록에 ‘AI 연결’을 추가한다. PC, 공급자 상태, 모델 선택, 연결 관리를 여기서 확인한다. 사용자의 연결은 계정과 활성 팀에 귀속된다.
3. **연결창 하나:** 기존 모달의 테두리·여백·버튼·오버레이를 사용한다. 평소에는 닫혀 있다. 사용자가 할 일이 생겼을 때만 내용을 바꿔 보여준다.
4. **로컬 창:** 설치·6자리 입력은 OS/연결기 창이다. 시연에서는 웹 옆에 표시하지만, 실제 웹이 로컬 앱 UI를 iframe으로 제어하는 설계가 아니다.

논문 상세에는 새 탭·사이드패널을 추가하지 않는다. 논문 질문을 보내는 화면 자체와 도구 권한 범위는 이후 설계 대상으로 둔다.

## 형태와 문구

| 요소 | 설계 |
|---|---|
| 색 | 기존 warm light / dark 토큰과 blurple 액센트. 일반 카드에 브랜드 그라데이션을 쓰지 않음 |
| 크기 | 제목 28px, 카드 제목 20px, 본문 13–14px, 메타 12px |
| 카드·버튼 | 기존 `Card`, `Button`, `Input` 패턴. 카드 `--r-lg`, 버튼·필드 `--r-sm` |
| 연결 표시 | 6px 도트 + 텍스트. 색만으로 상태를 전달하지 않음 |
| 사용량 | 20px 링 2개, `5h` / `7d`. 버튼 히트 영역은 최소 40px |
| 사용량 상세 | 호버·키보드 포커스 때 표시. 포인터 이탈·Escape로 닫힘. 터치는 탭으로 열고 닫음 |
| 모델 선택 | ‘모델을 선택하세요’로 시작. 한 팝오버 안에서 검색하고 공급자별 목록을 바로 고름 |
| 상태 문구 | ‘연결기를 열고 있어요’, ‘설치 파일을 열어 주세요’, ‘웹의 번호를 입력해 주세요’, ‘다시 로그인해 주세요’ |
| 동작 중 | 내용 영역의 기존 shimmer 패턴. 전체 화면 스피너·확인할 수 없는 진행률·연결 도트 점멸을 쓰지 않음 |

연결과 로그인 확인 전에는 모델 선택·질문 실행을 허용하지 않는다. 카탈로그와 사용량은 선택한 공급자별로 묶는다. 실제 CLI가 제공한 모델만 활성화하며, 시연의 모델명·62%·44%는 예시다.

## 사용자가 보는 흐름

### 처음 연결

`AI 연결 → 연결기 열기 시도 → 응답이 없으면 설치 안내 → 설치 파일 다운로드 → 사용자가 파일 열기·설치 승인·필요한 최초 열기 → 연결기 응답 → 웹의 6자리 입력 → 연결 완료 → 모델 직접 선택`

설치가 이미 필요하다고 사용자가 명시한 재시도·다운로드 경로에서는 다운로드부터 시작할 수 있다. 설치 파일은 OS 감지값을 표시해 제공하고, 감지가 불확실하면 OS를 선택하게 한다. 임의의 OS를 기본값으로 고정하지 않는다.

### 설치되어 있고 종료된 경우

`AI 연결 → 전용 링크로 OS가 연결기 실행 → 현재 세션·기기·팀 권한 확인 → 연결 완료`

앱을 찾아 실행하거나 설치 파일을 다시 받는 단계가 없다. 브라우저·OS가 ‘앱 열기’ 확인을 추가할 수 있다.

### 이미 실행 중인 경우

현재 웹 세션에 승인된 연결기의 온라인 상태를 확인하면 조용히 연결을 복구한다. 웹 새로고침·정상적인 세션 갱신·일시적인 네트워크 복구는 최초 페어링과 구분한다.

### 로그아웃·쿠키·세션 소실

`기존 실행 권한 회수 → 웹 로그인 → 새 연결 요청 → 새 6자리 입력 → 연결 완료`

이미 설치한 연결기를 다시 설치하지 않는다. 이전 사용량·모델·실행 허가는 새 계정이나 팀으로 넘기지 않는다. 명시적 팀 변경도 별도의 권한 확인이 필요하다.

## 자동으로 처리할 일과 사용자 확인

| 상황 | 자동 처리 | 사용자에게 필요한 동작 |
|---|---|---|
| 앱 실행 중 + 현재 권한 유효 | 상태·모델 카탈로그·사용량 동기화 | 없음 |
| 설치된 연결기 종료 | 한 번의 전용 링크 요청, ACK 대기 | AI 연결 클릭. 환경에 따라 앱 열기 허용 |
| 설치 여부 불확실 / 앱 응답 없음 | 같은 창을 설치·다시 열기 안내로 전환 | 설치가 필요하면 다운로드 선택 |
| 다운로드 시작 | 웹에 파일 열기 안내 유지. 요청당 중복 다운로드 방지 | 브라우저 다운로드에서 파일 열기 |
| 설치 완료·첫 실행 | 서버 요청 복구, 웹 상태 전환 | OS 설치 승인과 패키지에 따라 필요한 최초 열기 |
| 페어링 필요 | 새 번호 발급, 대상·만료·입력 오류 안내 | 웹 번호를 앱에 입력하고 연결 |
| CLI 로그아웃 | 해당 공급자 사용 중지·이전 사용량 숨김 | PC에서 공식 로그인 |
| CLI 미설치 | 해당 공급자만 설치 안내, 다른 공급자 유지 | 사용할 CLI 공식 설치 |
| 통신 일시 끊김 | 제한된 재연결, 초안 유지, 복구 상태 표시 | 자동 복구 실패 때만 다시 시도 |
| 한도·모델 정보 없음 | 알 수 없음으로 표시. 질문 가능 여부는 별도 권한·상태로 판단 | 지원되는 다른 공급자·모델 선택 가능 |
| 이전 사용량 | 회색 링, ‘이전 확인값’·관측 시각 표시 | 필요하면 상태 다시 확인 |
| 모바일 / GUI 없는 Ubuntu | 현재 기기에 데스크톱 설치·실행 동선을 제공하지 않음 | 지원하는 PC 브라우저에서 연결 |

웹은 ‘프로토콜 응답 없음’을 ‘앱 미설치’로 확정할 수 없다. 확인창 대기·실행 지연·설치 손상도 같은 결과를 만들 수 있다. 이 경우 자동 화면 전환까지만 하고, 설치 파일을 무조건 내려받거나 반복 실행하지 않는다.

웹이 다운로드한 설치 파일을 임의로 실행하는 경로는 없다. 설치기의 자동 첫 실행은 지원하는 패키지에서 사용자가 설치 파일을 열어 승인한 뒤의 동작이다. macOS의 일반적인 디스크 이미지에서 앱을 옮기는 일 자체가 첫 실행을 보장하지는 않는다. 시연의 OS 버튼은 이 사람의 동작을 재현하는 검토 도구이며 제품의 웹 버튼이 아니다.

## 연결 상태와 전이

사용자에게 설치·실행 여부를 추측하게 하지 않고 아래 상태를 조합한다.

| 축 | 값 |
|---|---|
| 웹 권한 | 확인 중 / 승인됨 / 로그인 필요 / 팀 변경 / 회수됨 |
| 연결 | 미확인 / 여는 중 / 온라인 / 복구 중 / 오프라인 |
| 공급자 | 감지 중 / 사용 가능 / 로그인 필요 / 설치 필요 / 한도 도달 |
| 데이터 | 최신 / 이전 관측값 / 미제공 |

표시 우선순위는 웹 권한 → 연결 상태 → 선택 공급자 상태 → 모델·사용량이다. ‘연결됨’이라는 단어 하나로 네 축을 합치지 않는다.

초기 ACK 대기는 8초, 이후 자동 통신 재시도는 상한을 둔 backoff를 제안한다. 이 값은 UX 검증 전 가설이다. OS 확인창과 설치 중에는 시간만으로 실패를 확정하지 않고 대기·복구 액션을 유지한다.

- 요청·응답에는 `attemptId`, 서버 상태 버전, 기기 증명, 현재 세션·팀 스코프를 묶는다.
- 취소·로그아웃·새 시도 뒤의 늦은 응답은 상태를 되살리지 못한다. 같은 시도의 중복 ACK·설치 완료도 한 번만 반영한다.
- 페이지 복귀·새로고침 시 서버에서 시도를 조회해 계속한다. localStorage의 ‘설치됨’ 표시는 힌트이며 승인 근거가 아니다.
- 복수 탭은 같은 기기 연결을 공유해도 실행 허가는 검증한다. 첫 확인 전 질문을 자동 재전송하지 않는다.

## 6자리 번호

번호는 웹에 표시하고 연결기 입력은 비워 둔다. 6자리 형식이 완성되기 전 연결 버튼은 비활성화한다. 틀린 번호는 입력 옆에서 설명하고, 만료되면 웹에서 새 번호를 받게 한다.

서버가 짧은 TTL, 시도 제한, 일회성 소비, 현재 세션·팀·기기키 증명을 검증한다. 설치가 길어져 기존 요청이 만료되면 앱에서 서버의 새 요청을 받아 웹에도 새 번호를 표시한다. 설치 파일·URI·앱 입력에 웹 쿠키나 CLI 인증 토큰을 포함하지 않는다.

## 실행 수명

자동 시작을 선택하지 않아도 설치된 전용 링크로 필요할 때 실행할 수 있다. 연결기 창 닫기, 연결 일시 중지, 앱 완전 종료, 기기 연결 해제를 구분한다. PC 종료 중에는 로컬 CLI를 사용할 수 없다.

제안: 자동 시작이 꺼져 있고 마지막 웹 연결도 끝났다면, 진행 작업이 없는 유휴 상태에서 연결기를 종료할 수 있다. 새로고침·다중 탭·작업 중단을 구분하는 유예 시간은 구현 전에 검증한다. 펫을 계속 표시하는 선택과 유휴 종료 정책은 함께 안내해야 한다. 상시 실행이나 자원 사용량을 측정 없이 보장하지 않는다.

## 구현 경계와 선행 검증

이번 산출물은 화면·카피·전이 설계다. 실제 설치기, OS 프로토콜 등록, CLI 연결, 인증·모니터링을 구현하거나 등록하지 않는다.

- 웹: `Topbar.actions`의 클라이언트 섬, `/profile` 카드, 연결 모달을 재사용한다. 읽기·초기 권한은 서버 조회, 변경은 route handler/Server Action에서 처리한다.
- 서버: 계정·활성 팀·기기·웹 세션별 연결 시도와 짧은 실행 허가. 상태 전파는 기존 Supabase Realtime 경로를 사용한다. Vercel 요청 안에서 상시 브리지 서버를 띄우지 않는다.
- 연결기: OS별 설치·프로토콜 등록·단일 인스턴스·CLI 어댑터·기기 증명·앱 첫 실행을 담당한다. 설치기에서 CLI를 몰래 설치하지 않는다.
- 구현 전 확인: Codex 어댑터 완성, CLI 버전별 모델·한도 정보, 연결 해제·로그아웃 이후 서버 write 차단, 설치 파일 서명·업데이트·제거, Windows/macOS/Ubuntu 실제 프로토콜 흐름.
- Ubuntu는 GUI 세션·패키지 연결·기본 브라우저 조합을 검증한다. Wayland의 펫 위치·항상 위 제약과 CLI 연결을 분리한다.

## OS별 설계 계약

| OS | 첫 설치 | 이후 AI 연결 | 완료로 볼 검증 |
|---|---|---|---|
| Windows | 사용자용 설치 패키지 열기·OS 확인·첫 실행. 자동 시작은 선택 | 등록한 전용 링크 → 동일 사용자 연결기 실행 | Chrome/Edge 앱 열기, 종료 후 재실행, 단일 인스턴스, 비영문·공백 경로, 업데이트 후 링크, 콘솔 포커스 보존 |
| macOS | 서명·공증할 앱 패키지의 설치·최초 열기. 앱 이동과 실행을 구분 | 등록한 전용 링크 → 앱 실행·기존 인스턴스 전달 | Safari/Chrome, Apple Silicon/Intel 배포 범위, 앱 설치·첫 실행, Keychain, 재부팅·업데이트·앱 이동 후 동작 |
| Ubuntu · GUI | 지원 버전을 정한 패키지 설치·필요한 최초 열기 | 데스크톱에 등록한 전용 링크 → 연결기 실행 | 지원 Ubuntu 버전, GNOME 기본 브라우저, X11/Wayland, 실행 권한·패키지 의존성, 설치·업데이트 후 링크 |

세 OS 모두 하박조팽 웹과 CLI 연결을 목표로 한다. 이 문서와 시연만으로 실제 OS 호환성이 검증된 것은 아니다. 헤드리스 Ubuntu에는 이 데스크톱 설치·확인창 흐름을 적용하지 않는다. 펫의 표시 기능이 제한돼도 CLI 연결 상태를 실패로 처리하지 않는다.

## 다른 웹앱 재사용과 후속 분리

사용자 지시 순서: **하박조팽 UX 설계 → 하박조팽에 연결 기능 구현·검증 → 전체 완성 후 별도 repo와 스킬 분리**. 현재 단계에서는 별도 repo 생성·원격 게시·스킬 설치를 진행하지 않는다.

공통 실행부와 하박조팽 어댑터를 구분해 설계한다. 실행부는 설치·앱 수명·CLI 어댑터·기기 증명을 맡고, 웹앱 어댑터는 브랜드 토큰·표시명·계정/팀 표시·서버 인증·허용 도메인·배포 파일·상태 이벤트를 연결한다.

여러 앱이 하나의 연결기를 공유하면 각 앱의 세션·기기 승인·사용량·로그아웃 범위를 격리한다. 전용 링크에서 받은 임의의 도메인을 신뢰하지 않고 등록된 클라이언트·서명된 요청을 검증한다. 별도 제품별 패키지라면 전용 링크 스킴 충돌을 피해야 하며, 공용 연결기라면 프로토콜 소유자는 하나로 유지한다.

완성 후 만들 스킬의 시작 절차:

1. 대상 앱의 `AGENTS.md`, 디자인 토큰, 상단바·설정·모달·인증 흐름을 먼저 읽는다.
2. 대상 앱에 맞춘 연결 UX·카피·위치·상태 전이를 먼저 설계한다. 하박조팽의 이름·색을 다른 앱에 강제하지 않는다.
3. 서버 인증·팀 스코프·CLI 어댑터·설치 패키지를 연결한다.
4. Windows·macOS·Ubuntu의 설치·첫 실행·재실행·로그아웃·복구를 실제 환경에서 검증한다.
5. 미검증 환경과 제한을 분명히 표시한 뒤 해당 앱에 통합한다.

## 검토 기준

1. 사용자는 ‘설치됨 / 실행 중 / 포트 / 브리지 종류’를 선택하지 않는다.
2. 설치 후에는 웹의 ‘설치했어요’ 확인 없이 앱 이벤트로 이어진다.
3. 다음 실행은 웹 버튼에서 시작하며 정상 권한에서는 새 번호를 요구하지 않는다.
4. 잘못된 번호·권한 회수·취소 뒤의 늦은 응답은 연결을 완료하지 못한다.
5. 모델은 최초 무선택이고, 사용량은 작은 링 + 접근 가능한 상세만 제공한다.
6. 설치 파일 실행·OS 확인·번호 입력처럼 사람이 해야 하는 단계는 숨기지 않는다.
7. 기존 테마·카드·버튼·모달을 따르고 논문 상세의 탭·패널 구조를 바꾸지 않는다.
