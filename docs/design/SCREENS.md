# 화면 카탈로그 (Screens)

> 토큰·컴포넌트 규칙은 [`./DESIGN_GUIDE.md`](./DESIGN_GUIDE.md), 화면 전환·상태는 [`./SCREEN_FLOW.md`](./SCREEN_FLOW.md), 사용자 흐름은 [`../user/USER_FLOW.md`](../user/USER_FLOW.md)다. 정확한 마크업은 `src/`의 프로토타입, 정본 핸드오프는 루트 `README.md`. 이 문서는 **화면별 구성 요소와 카피**를 한곳에 정리한다.

## 영속 셸 (`shell.jsx`)

모든 앱 화면을 감싼다.

- **사이드바:** 로고("하박조팽") · 내비 목록 · 접기 토글 · 하단 멤버 목록(클릭 → 팀 관리).
  - 내비 순서: 홈 · 논문 · **NEWS** · 발표 자료 · 스케쥴 · 팀 관리 · 세미나 라이브 (NEWS는 "논문" 다음에 위치 — ADR-022, 실제 `nav.ts` 반영은 별도 step).
  - 항목은 선택적 `count`/`unread` 배지. **`meeting` 항목은 `live === true`일 때만** 깜빡이는 **LIVE** 알약(이때 count 배지 억제).
- **상단바:** 좌측 브레드크럼 + 우측 맥락 액션. 모든 화면이 `<Topbar crumbs actions />` 사용.

### auth — 로그인 / 히어로
스플릿 레이아웃. 좌측 브랜드 패널: 워드마크 "하박조팽", 태그라인 **"리서치는 혼자 하는 게 아니야."**, 4개 기능 목록(세미나 라이브 / 논문 분석 관리 / 자료 관리 / 스케쥴 관리, 각 아이콘+제목+한 줄). 우측 로그인/가입 폼. 빠른 멤버 로그인 버튼(데모). → 합류는 **초대 전용**(ADR-007).

### teams — 진입 팀 허브 (로비)
로그인 후 **항상 거치는 착지 화면**(ADR-021). `(app)` 셸 **밖**의 독립 로비 — 사이드바·`TeamSwitcher` 없음. 단 초대 복귀(`next`)가 있으면 허브를 건너뛴다.
- **내 팀 목록:** 속한 팀을 이름·역할(owner/admin/member)과 함께 카드/행으로. 선택 시 활성 팀 쿠키 설정(`POST /api/teams/active`, 검증된 멤버십만 — R37) → `/dashboard` 진입.
- **새 팀 만들기:** 이름(+선택 주소). 전역 상한(`MAX_TEAMS`) **도달 시 비활성 + 안내**("최대 팀 수를 초과했어요", 인라인 — R30). 상한은 **전역·admin이 env로만 설정**(per-user 아님) — 사용자가 바꿀 UI는 없다.
- **초대 안내:** "초대 링크를 받았다면 그 주소로 들어가면 합류할 수 있어요."
- **팀 0개:** 목록 없이 만들기/초대 안내만(기존 `/teams/new`의 "팀 없음" 역할 흡수).
> 관리 화면 **`team`(팀 관리, 단수)**과 역할이 다르다 — `teams`는 **선택 전 로비**, `team`은 **선택 후 셸 안의 관리**다.

### dashboard — 홈
- **LIVE 배너**(`live === true`일 때만, 최상단) → 클릭 시 미팅 입장.
- **퀵 카드** 행: `{icon, label, count, desc}` (논문/발표 자료 등).
- 최근 활동: 최근 발표 자료, 최근 논문.
- 헤더 액션: `＋ 업로드`.

### library — 논문 목록
- 단일 필터 칩 **"전체"**만(타입 필터 의도적 제거 — 4인 라이브러리에 잡음).
- `.paper-row`: 종류 태그 · 제목 · 저자 · 업로더 아바타 · 날짜 → 클릭 시 `paper`.

### paper — 논문 상세 (가장 중요)
- 헤더: 브레드크럼 · 제목 · 저자/메타. **상단바 액션 = `⬇ 원문 PDF` 단 하나**(arXiv/공유 제거). **탭/사이드패널 없음**(ADR-004).
- 전체 폭 **AnalysisView**:
  - 상단 고정 **관점 토글** `🔬 연구 분석` ⇄ `🛠️ 재구현 분석` + 한 줄 힌트.
  - 섹션 카드(연구: Problem Setting·Contribution·Input/Output·Comparison·Ablation / 재구현: 데이터·모델·학습·리소스).
  - **`Figure 분석`** 두 관점 하단 고정: "원문 PDF p.N에서 추출" 배지 + figure 이미지 + 캡션 + **설명(해석)**.
  - 각 섹션 `+ 이 섹션에 분석 추가` → 인라인 폼 → 작성자 표기 노트 카드(삭제 가능). Figure 노트는 관점 공통.
- 레이아웃 변형 `layout`: `stack`(기본)/`grid`/`toc`(좌측 섹션 점프).

### news — NEWS 목록 (팀 출판 실적 쇼케이스)
우리 팀이 발표·출판한 실적을 카드 그리드로 진열한다. 기존 "논문"(분석 대상)과 별개 — 여긴 *우리 실적*이다(ADR-022). 팀 내부 전용(로그인 + 활성 팀 스코프).
- **카드:** 티저 썸네일(서명 URL·없으면 플레이스홀더) + 제목 + 학회명·연/월 + 저자(팀원 이름 강조). 정렬은 연/월 **내림차순**(`month` 없으면 연도만 표시, null 월은 뒤로).
- **상단바 액션 = `＋ 실적 추가`**(모든 팀원). 클릭 → 추가 폼(제목·학회·저자·연·월·외부 링크 + 티저 이미지 선택, 프리사인 직접 업로드).
- **빈 상태:** "아직 등록된 실적이 없어요" + **첫 실적 추가하기** CTA(정직한 빈 상태, R21).
- 카드 클릭 → `news-detail`.

### news-detail — 티저 상세
- 큰 티저 이미지(서명 URL) + 제목 + 학회명·연/월 + 저자(팀원 강조) + **외부 링크 버튼들**(arXiv/PDF/코드/프로젝트).
- 액션: **편집 / 삭제**(모든 팀원). 삭제는 확인(R27) → 티저 객체 best-effort 정리.
- 다른 팀/없는 id → "찾을 수 없음"(404 등가, R19/R37).

### presentations — 발표 자료 목록
개수 표시("14개"). 항목 클릭 → `presentation`.

### presentation — 자료 + 댓글
자료 뷰어 + **스레드 댓글**: 아바타·이름·시간·텍스트(@멘션 링크화)·반응. 작성: textarea(Cmd/Ctrl+Enter 전송)·첨부/이모지/멘션·보내기. 회고가 여기 쌓인다.

### schedule — 스케쥴 (두 번째로 중요)
단일 컬럼 보드. 월별 3상태(빈/편집/확정) — 상세는 [`./SCREEN_FLOW.md`](./SCREEN_FLOW.md) §스케줄.
- 월 보드 + **벌금 설정**(발표자 불참/일반 불참, 편집 가능) + **로테이션**(하수현→박진희→조성민→팽진욱) + **연도별 멤버 현황 표**(참여/불참/누적 벌금/납부/미납).

### team — 팀 관리
- 초대 블록: `[이메일][역할▾ 관리자/멤버/게스트][초대 보내기]` + 🔗 초대 링크 복사.
- 멤버 목록: 아바타·이름(+자신 "나")·이메일·역할 배지·`⋯`(역할 변경/내보내기).
- 대기 초대(점선 행): 재전송/취소.
- 역할 배지: 관리자=액센트 틴트, 멤버=중립, 게스트=앰버 틴트.

### meeting — 세미나 라이브
- `!live` 빈 상태: "진행 중인 라이브가 없습니다" + **라이브 시작하기**(주요) + 스케줄 보기 + "다음 세미나" 칩.
- `live` 룸: 발표자 스포트라이트 · 참가자 타일 · 컨트롤(마이크/카메라/공유) · 헤더 `[종료][나가기]`.
- 프로덕션: LiveKit 다자간 화상(SFU) — 참가자 비디오 타일·화면공유, 채팅·반응은 데이터 채널(ADR-019).

### profile — 설정
프로필 필드 · 알림 토글 · 테마(라이트/다크) · 법적 링크.

### legal — 약관/개인정보
모달. 약관 ⇄ 개인정보 전환.

## 화면별 상태 (빈 / 로딩 / 에러)

모든 데이터 화면은 세 상태를 갖는다(패턴: [`./DESIGN_GUIDE.md`](./DESIGN_GUIDE.md) §UX 패턴). 화면별 구체.

| 화면 | 로딩 | 빈(Empty) | 에러 |
|---|---|---|---|
| teams(허브) | 팀 목록 스켈레톤 | **팀 0개**: 만들기/초대 안내만 | 목록 에러 카드 + 다시 시도; 팀 전환 실패 토스트 |
| dashboard | 카드/활동 스켈레톤 | 신규 워크스페이스: "첫 논문을 올려볼까요?" | 활동 영역만 에러 카드 + 다시 시도 |
| library | 행 스켈레톤 | "아직 올라온 논문이 없어요" + 업로드 | 목록 에러 카드 |
| paper | 섹션 스켈레톤(`shimmer`) | **분석 대기/실패**: "논문을 읽고 있어요…" 또는 "분석을 못 끝냈어요" + 다시 분석 | 분석 실패 시 원문 PDF는 항상 다운로드 가능 |
| news | 카드 그리드 스켈레톤 | **실적 0개**: "아직 등록된 실적이 없어요" + 첫 실적 추가하기 | 목록 에러 카드 + 다시 시도 |
| presentations | 행 스켈레톤 | "발표 자료가 아직 없어요" | 목록 에러 카드 |
| presentation | 뷰어 스켈레톤 | 댓글 없음: "첫 회고를 남겨보세요" | 댓글 영역만 에러 |
| schedule | 보드 스켈레톤 | **빈 달**: "이 달은 아직 일정이 없어요" + 일정 짜기 | 저장 실패 토스트 + 편집 유지 |
| team | 멤버 스켈레톤 | (4인이라 사실상 항상 차 있음) | 초대 전송 실패 토스트 |
| meeting | — | **라이브 없음**(기본): "진행 중인 라이브가 없습니다" | 시작 실패(409/외부): "이미 진행 중인 라이브가 있어요"/"잠시 후 다시" |

> **paper의 분석 대기/실패는 핵심 UX다.** 업로드는 성공해도 LLM 분석은 비동기·실패 가능하다. 이때 논문 자체는 열리고, 분석 섹션만 "읽는 중/재시도" 상태가 된다. 원문 PDF 다운로드는 분석 상태와 무관하게 항상 동작.

## 주요 엣지 케이스 (화면 카피 포함)

| 상황 | 화면 처리 |
|---|---|
| 두 멤버가 동시에 **라이브 시작** | 두 번째는 시작 대신 **입장**으로 안내: "이미 OOO님이 라이브를 시작했어요. 입장할까요?" (409 → 합류) |
| 업로드 중 **arXiv URL 오류** | 드롭존 인라인 에러: "arXiv 주소를 확인해주세요." 모달 유지 |
| **분석 실패** | paper 상단 배너 "분석을 못 끝냈어요" + [다시 분석]. 노트/원문은 사용 가능 |
| 발표자가 **휴가(vacation)** | 스케줄 편집 시 발표자 선택에 상태 표시, 순번 건너뛰기 안내(→ [`./SCREEN_FLOW.md`](./SCREEN_FLOW.md)) |
| 라이브 중 **네트워크 끊김** | 룸 상단 "연결이 끊겼어요. 다시 연결 중…" 배너, 자동 재연결 시도 |
| **세션 만료** | 작업 시도 시 부드러운 재로그인 유도(작성 중 내용 보존 시도) |
| 노트/댓글 **빈 값 제출** | 인라인 검증: "내용을 입력해주세요." (토스트 아님) |

## 전역 오버레이
- **UploadModal**: PDF 전용 드롭존 + arXiv URL(ADR-003). 단계: idle → uploading(진행률) → analyzing("논문을 읽고 있어요…") → done(이동). 실패 시 단계별 인라인 에러.
- **CommandPalette**: `Cmd/Ctrl+K`. 빈 검색: 최근/추천. 결과 없음: "검색 결과가 없어요."
- **Toaster**: `onToast(msg)` 일시 확인(성공). 실패 토스트는 되돌리기/다시 시도 액션 동반 가능.
- **ConfirmDialog**: 파괴적 액션(내보내기·종료·삭제·편집 취소) 확인. 위험 버튼은 `--busy`.
