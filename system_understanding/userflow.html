유저 워크플로우 & 저니

워크플로우는 사용자가 하나의 목표를 완료하기까지 밟는 단계와 분기(클릭 단위)를, 저니는 사람의 시점에서 시간 축을 따라가는 서사(언제·왜·어떤 기분)를 다룹니다.

앱 진입 게이팅 — 전체 상태 머신

app.jsx의 stage가 전체를 게이팅하고, 내부 switch(screen)이 현재 화면을 선택합니다.

auth → onboarding → app, 그리고 app 내 화면 전환 (live는 전역 오버레이)
stateDiagram-v2
  [*] --> auth
  auth --> onboarding: 초대 토큰 합류 / 첫 로그인
  auth --> app: 기존 세션 로그인
  onboarding --> app: "환영합니다 🎉"
  state app {
    [*] --> 대시보드
    대시보드 --> 논문목록
    대시보드 --> 스케줄
    대시보드 --> 라이브
    논문목록 --> 논문상세
    논문상세 --> 라이브: 입장
    스케줄 --> 라이브: 이번주 입장
    발표자료목록 --> 발표자료상세
    팀 --> 팀
  }
  app --> auth: 로그아웃

주간 세미나 사이클 — 사용자 저니 (월~일)

제품의 심장: 매주 토요일 10:00 세미나를 중심으로 한 주의 리듬
journey
  title 주간 세미나 사이클 (감정 곡선)
  section 월요일 — 누구 차례?
    홈에서 이번 주 발표자 확인: 4: 전원
  section 화요일 — 논문 업로드
    PDF 드래그앤드롭/arXiv: 4: 발표자(조)
    두 관점 분석 페이지 생성: 5: 발표자(조)
  section 수~금 — 함께 읽기
    재구현 관점 토글·섹션 노트: 4: 박·하
    자료에 @멘션 댓글: 4: 전원
  section 토 10:00 — 라이브
    배지/배너 클릭→룸 입장(≤2클릭): 5: 전원
    발표·종료: 5: 발표자
  section 토~일 — 회고
    회고 댓글·반응: 4: 전원
    벌금 장부 반영·다음 발표자 확인: 3: 관리자(하)

F1 · 라이브 세미나 입장·진행

기본 빈 상태 → 시작/입장 → 종료(파괴적) vs 나가기(본인만)

  Empty --> Sched["[스케줄 보기]"]
  Begin --> Conflict{"이미 active?"}
  Conflict -->|예 409| Join2["'이미 OOO님이 시작했어요.
입장할까요?' → 합류"]
  Conflict -->|아니오| Room["룸 + 전역 live ON
(배지·배너 모두에게)"]
  Q -->|true| Room
  Room --> End["[종료]"]
  Room --> Leave["[나가기]"]
  End --> Confirm{"확인: '모두의 세션이
끝나요'"}
  Confirm -->|확인| Off["전체 종료 · live OFF · 홈 복귀"]

입장 최단 경로 ≤2클릭: 홈 LIVE 배너/사이드바 배지 클릭 → 룸. 종료는 파괴적(확인 필수), 나가기는 본인만(확인 없음) — 시각적으로 분명히 구분.

온보딩 · 팀 관리 · 책임

A · 온보딩 (신규 멤버)

초대 링크 클릭 → 로그인/가입 → 온보딩 → "환영합니다! 🎉". 공개 가입 없음 — 초대 전용(ADR-007). 신규는 정직한 빈 상태로 맞이("첫 논문을 올려볼까요?").

F6 · 팀 관리 (관리자)

[이메일][역할▾][초대 보내기] · [🔗 링크 복사]. 멤버 행 ⋯: 역할 변경 / 내보내기(확인). 대기 초대: [재전송][취소(되돌리기 토스트)].

C · 책임 관리 (관리자)

벌금 금액(발표자/일반 불참) 설정 → 연도별 멤버 장부에서 참여·불참·누적 벌금·납부·미납 확인. 결제 시스템이 아닌 가벼운 사회적 장치.

마찰 지점 & 회복 설계

좋은 저니는 "어긋날 때" 갈립니다. 각 단계의 감정 저점과 회복 설계.

단계마찰 (감정 저점)회복 설계
논문 업로드"분석이 안 끝났네"분석 실패와 업로드 분리 — 논문은 남고 [다시 분석], 원문 PDF는 항상 열림
arXiv 가져오기"주소를 잘못 붙였나"인라인 에러로 즉시 교정, 모달 유지
토요일 입장"두 명이 동시에 시작"두 번째는 충돌이 아니라 입장으로 안내 — 사고가 아니라 합류
라이브 중"와이파이 끊김""다시 연결 중" 배너 + 자동 재연결, 발표 맥락 유지
라이브 종료"실수로 전체 종료"종료=확인 다이얼로그, 나가기=즉시 — 둘을 분명히 구분
스케줄 편집"초안 짜다 실수로 취소"변경분 있으면 취소 확인, 저장 실패 시 입력 보존
발표자 휴가"이번 주 발표자가 빠짐"휴가 상태 표시 + 순번 건너뛰기/수동 재배정

전역 인터랙션 & UX 규칙

전역 인터랙션

  • 내비게이션: 어디서나 onNavigate(screen, params)
  • 토스트: onToast(msg) — 성공은 가벼운 확인, 실패는 다시 시도/되돌리기
  • 명령 팔레트: ⌘/Ctrl+K 열기, Esc 닫기
  • 검색: 논문/발표/아이디어/코멘트 통합 결과

전역 상태·피드백 규칙

  • 상태 3종: 로딩(스켈레톤)·빈·에러(다시 시도) 모두 제공
  • 낙관적 UI: 노트·댓글·반응 즉시 반영 → 실패 시 롤백 + 토스트
  • 파괴적 액션: 종료·내보내기·삭제·편집취소는 확인/되돌리기
  • 검증은 인라인, 권한 안내는 부드럽게("관리자만 할 수 있어요")
