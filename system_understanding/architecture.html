아키텍처 & 토폴로지

프로토타입은 단일 클라이언트 SPA지만, 프로덕션은 상시 구동 Node 서버 + 인-프로세스 백그라운드 워커 + 외부 서비스가 얽힌 단일 인스턴스 시스템입니다. 아래는 그 토폴로지, 경계, 데이터 흐름입니다.

🔥
CRITICAL — 서버리스가 아니라 상시 구동 Node 서버. 이유: ① 분 단위 분석/녹화 후처리를 인-프로세스 워커로 돌려야 하고 ② SQLite 파일은 영속 디스크가 필요합니다. 서버리스는 둘 다 깨집니다 (ADR-012). 4인 단일 인스턴스 가정 — 수평 확장은 비범위.

읽기 vs 쓰기 — 데이터 흐름 (ADR-015)

CLAUDE.md의 "서버 로직은 서버에서만" 규칙을 RSC 시대에 맞게 구체화합니다.

경로방법비고
읽기 (조회)서버 컴포넌트(RSC)에서 lib/ 서버 함수로 Prisma 직접 조회클라이언트가 DB를 직접 보지 않음 → 규칙 충족. 초기 페인트 빠름
쓰기 (변이)Server Action 또는 route handler (app/api/**)zod 검증·권한·작성자 주입 여기서. 변이 후 revalidatePath/Tag

백그라운드 작업 (ADR-013) — CRITICAL

🔥
분석·arXiv 가져오기·녹화 후처리는 요청 경로에서 인라인으로 돌리지 않습니다. Claude 분석은 분 단위라 HTTP 타임아웃을 넘기기 때문입니다. 업로드 성공과 분석 성공을 아키텍처로 분리합니다.

외부 서비스 경계

☁️ Cloudflare Stream Live

앱은 Live Input 생성·권한 체크·플레이어 노출만(ADR-002). 인코딩/HLS/CDN/녹화는 위임. 녹화 완료는 웹훅(HMAC)으로 수신. 송출 자격증명은 발표자에게만.

📦 객체 스토리지

PDF·에셋은 프리사인 업로드(클라이언트→스토리지 직접, 서버는 서명만)로 큰 파일이 서버를 거치지 않게. 다운로드는 단기 서명 URL.

🤖 Anthropic API

논문 분석. 워커에서만 호출(분 단위). 사람이 검수·보강하는 보조 추출(ADR-011). 키는 서버 .env 전용.

🔗 arXiv

워커가 arxiv.org/pdf/{id} PDF를 가져와 스토리지에 저장(요청 경로 아님). SSRF 화이트리스트.
